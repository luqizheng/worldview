# 4. Command 依赖与路线

## 4.1 D01-11：Command 依赖关系

阶段性选择：B。

依赖关系来源包括：

1. 用户显式指定的依赖。
2. 系统执行时发现的隐式依赖。

隐式依赖例如：

- 行军路线经过桥梁。
- 移动受到地形影响。
- 行动受到道路状态影响。
- 操作受到其他对象状态影响。

依赖关系可以动态发现。

系统需要能够解释依赖链。

依赖关系属于可重建派生信息，不是第二套权威历史。

## 4.2 D01-12：移动路线确定方式

阶段性选择：C。

用户可以：

- 自己指定路线。
- 让系统计算建议路线。

系统不能擅自改变用户指定路线。

系统建议路线与用户接受后的路线必须区分：

- 建议路线：候选结果，不改变 Command。
- 用户接受：路线纳入 Command。
- 用户直接指定：路线直接成为 Command 的执行依据。

## 4.3 D01-13：修改已指定路线

阶段性选择：A。

用户修改 Command 的路线后：

- 从该 Command 开始时间起重新计算派生结果。
- 旧派生结果失效。
- 重建受影响的 World State。
- 重新评估依赖命令。
- 重新检查警告。
- 重建受影响 Branch。

不保留旧路线作为另一份世界历史。

## 4.4 D01-14：修改 Command 历史时间

阶段性选择：A。

修改 Command 的历史时间后，从新旧时间中较早的时间开始重建受影响历史及 Branch。

这个时间点是重建起点，不意味着必须从地图初始时间全部重新计算。

## 4.5 D01-15：删除 Command

阶段性选择：A。

删除 Command 只删除该 Command 本身。

不自动删除依赖它的其他 Command。

依赖它的命令保留并重新评估，必要时产生警告。

受影响的派生 State Change 失效，并重建受影响的 World State 和 Branch。

旧警告可能重新变成有效，需要重新诊断。

## 4.6 D01-16：任意历史时间插入 Command

阶段性选择：A。

允许在任意历史时间插入新 Command。

插入后：

- 从最早受影响的时间重建。
- 后续 Command 保留。
- 按依赖关系重新评估。
- 重建受影响 Branch。

历史时间是创作内容的组织维度，不是用户操作顺序。
