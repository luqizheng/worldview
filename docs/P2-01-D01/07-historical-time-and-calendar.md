# 7. Historical Time 与 Calendar

## 7.1 D01-37：内部时间模型

阶段性选择：B。

用户提出：地图系统内部日期应当从第 0 天开始，以累计天数持续记录；显示出来是什么属于显示问题。

因此：

- 内部历史时间与日历显示分离。
- 内部时间不依赖公元纪年、月份、闰年和年号。
- 不同日历是同一内部时间的不同显示表达。
- 不同来源时间体系在组合地图时需要明确时间映射转换。
- 时间精度最高支持秒。
- 内部存储避免浮点精度误差。

具体数值存储方案仍需技术设计。

## 7.2 D01-38：地图第 0 天

阶段性选择：C。

每张地图独立定义自己的第 0 天。

组合地图时，允许用户建立来源地图到新地图的时间轴映射。

不默认共享时间原点。

## 7.3 D01-39：Branch 时间轴

阶段性选择：A。

Branch 完全继承父地图时间轴，包括第 0 天定义。

Branch 不允许独立改变时间轴或第 0 天。

组合地图可以有独立时间轴及来源时间映射。

## 7.4 D01-40：日历显示规则

阶段性选择：C。

每张地图有一种默认日历。

同时允许显示其他辅助日历。

所有日历都是同一内部累计时间的不同表达。

切换日历不改变 Command 执行顺序或历史内容。

## 7.5 D01-41：用户自定义日历

阶段性选择：C。

第一版支持基本自定义：

- 一年天数。
- 月份结构。
- 纪年起点。
- 简单闰年规则。

复杂天文周期、多个太阳/月亮周期联动等以后扩展。

## 7.6 D01-42：默认日历按历史时间分段生效

阶段性选择：B。

默认日历可以按历史时间区间生效。

允许在历史时间线上发生历法改革。

日历改革只改变日期解释，不改变内部累计天数或 Command 执行时间。

## 7.7 D01-43：日历改革与 Command

阶段性选择：C。

日历改革既可以作为一条 Command 记录，也有独立的 Calendar Configuration。

- Command 表达历史行为。
- Calendar Configuration 表达具体历法规则。
- Command 执行可以触发日历配置在指定历史时间生效。

## 7.8 D01-44：删除日历改革 Command

阶段性选择：A。

删除日历改革 Command 时，自动删除其对应的新历法配置，恢复旧历法。

日历改革 Command 与对应 Calendar Configuration 建立明确关联。

修改改革 Command 生效时间时，重新计算配置生效区间，后续日历显示重新计算。

用户手动创建、但未通过该 Command 启用的独立日历配置，不受影响。

## 7.9 D01-45：日历改革追溯生效

阶段性选择：A。

允许追溯修改日历改革的生效时间。

由于事件和 Command 的内部时间都使用累计天数：

- 修改日历改革生效时间不影响其他历史数据。
- 不改变 Command 内部时间。
- 不改变 State Change 执行时间。
- 不改变事件先后关系。
- 不需要重建 World State。
- 只需重新计算受影响时间区间的日历显示。

内部 Historical Time 是权威数据，Calendar Date 是显示表达。

## 7.10 D01-46：内部时间数值表达

阶段性选择：C。

使用整数天数 + 当天内的时间偏移表达内部时间。

例如：

`day=1, offset=43200 seconds`

表示第 1 天中午。

建议当天内偏移使用整数秒，避免浮点精度误差。

未来更高精度可扩展，尚未独立裁决。

## 7.11 D01-47：Command 的时间表达

阶段性选择：C。

瞬时 Command 只有一个历史时间点。

持续 Command 有开始时间和结束时间。

持续时间可以由开始时间 + 持续时间计算，也可以由开始时间 + 结束时间确定。

持续 Command 可以产生多个阶段性 State Change，它们是可重建派生结果。

## 7.12 D01-48：持续 Command 暂停时的结束时间

阶段性选择：B。

最初讨论中，暂停时保留原开始时间和结束时间。

用户可以手动修改结束时间，系统不自动修改。

修改结束时间后，重新计算剩余阶段及受影响历史。

**D01-49 对暂停时间的后续纠正必须同时考虑。**

## 7.13 D01-49：持续 Command 暂停期间的历史时间

用户纠正了此前“暂停期间仍然消耗行动时间”的解释。

最新阶段性规则：

- 世界历史时间继续推进。
- 当前持续 Command 自身的执行时钟和行动进度暂停。
- 暂停期间不消耗剩余行动时间。
- 恢复时从暂停时的进度继续。
- 预计完成时间应考虑暂停造成的顺延。
- 用户可以手动修改结束时间。
- 系统不得擅自修改用户的结束时间。

示例：

- 第 100 天开始。
- 原计划需要 3 天。
- 第 101 天暂停。
- 第 105 天恢复。
- 剩余 2 天。
- 预计第 107 天完成。

这里暂停的是持续 Command 自身的执行时间，不是整个世界的全局历史时间。
