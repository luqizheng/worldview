# 11. 创作工程与发布作品

在 D01-69 讨论中，用户提出：

如果作者发布地图给其他用户查看，发布作品是否不包含 Command？

讨论后形成以下阶段性产品方向。

## 11.1 创作工程

创作工程是作者继续创作和编辑的完整工程数据。

可能包含：

- 初始地图数据。
- Command 及其顺序约束。
- Branch 和历史关系。
- 日历配置。
- 地图资源。
- 可选的 Checkpoint 缓存。
- 其他创作所需数据。

Command 是创作工程中的权威历史数据。

## 11.2 发布作品

发布作品是从创作工程生成的只读交付物。

可以不包含 Command。

发布作品可以包含：

- 已经重建的地图状态。
- 地图资源和展示所需数据。
- 日历及历史时间显示信息。
- 历史播放所需的状态数据。

**不包含 Command，不代表不包含历史。**

例如作者发布一张从公元 1000 年到 1500 年的地图，其他用户仍然可以拖动时间轴观看历史变化。

为实现这一点，发布作品需要携带足够的派生结果，例如历史时间点的状态数据或可播放的历史状态序列。

作者可以不公开内部 Command、创作过程和设计逻辑。

## 11.3 当前确定的边界

阶段性产品方向：

**发布作品是从创作工程生成的只读交付物，不是创作工程本身。**

但以下内容尚未讨论：

- 发布作品的具体文件格式。
- 历史状态序列的存储结构。
- 历史播放数据的压缩策略。
- 发布版本与源工程的关联方式。
- 发布作品是否支持离线下载、复制或二次分发。
- 发布作品的更新和撤回机制。

这些内容不属于本轮 D01 已裁决范围。
