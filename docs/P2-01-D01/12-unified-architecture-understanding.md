# 12. 当前统一架构认识

根据 D01-01 至 D01-69，形成以下阶段性模型。

## 12.1 权威数据与派生数据

| 对象 | 阶段性定位 |
|---|---|
| Command | 用户创作历史的权威记录 |
| Initial State | 地图初始状态 |
| State Change | Command 执行产生的状态变化语义及派生结果 |
| World State | 某个历史时间点的世界状态 |
| Dependency | Command 执行依赖，可重建派生信息 |
| Checkpoint | 按 Branch 归属的完整合成 World State 派生缓存（D01-72），用于加速重建，非权威历史；唯一性、完整性校验、完成标记与 MD5、保存内容等专题规则见[第 18 章](18-checkpoint-topic-d01-101-143.md)（D01-101~143） |
| Calendar Configuration | 日历规则配置 |
| Calendar Reform Command | 历史上的日历改革行为 |
| Order Constraint | Command 之间的显式顺序约束 |
| Shared Object | 表达共享对象身份及共享基础数据；共享身份不等于跨 Branch 共享运行时修改结果（D01-70） |
| Branch | 动态继承父地图截至分叉点的有效历史结果、只保存自有 Command 的创作分支，不是创建时冻结的历史副本（D01-71） |
| Combination Map | 通过历史路径固化（History Path Materialization，D01-74）形成的独立地图：父地图截至分叉点最新有效历史 + 分支分叉点后自有历史 |

## 12.2 历史重建工作流程

阶段性工作流程：

1. 用户创建或修改 Command。
2. 用户可以连续修改多个 Command。
3. 用户主动点击重新播放 / 重建。
4. 系统确定重建起点。
5. 复用仍然有效的缓存或 Checkpoint。
6. 按历史时间和顺序约束执行 Command。
7. 遇到第一个无法执行的 Command，立即停止。
8. 展示错误、原因及必要的依赖信息。
9. 用户修改设计。
10. 用户再次主动重建。
11. 全部 Command 成功后，生成完整 World State。
12. 保存可重建的缓存和 Checkpoint。

## 12.3 播放规则

- 只能播放当前创作内容已经成功重建的历史结果。
- 有未重建修改时，暂停播放。
- 有历史错误时，不能越过错误播放后续历史。
- 用户可以拖动播放条选择历史时间点。
- 播放起点和重建起点是两个不同概念。
- 播放结果必须与当前创作内容一致。

## 12.4 错误处理规则

采用简单的 Fail-Fast 方式。

- 遇到第一个错误立即停止后续重建。
- 不继续收集后续错误。
- 不建立复杂的并行错误报告体系。
- 不自动修改 Command。
- 不自动回滚用户修改。
- 提供针对失败 Command 的单项修复建议。
- 由用户决定是否采用修复建议。

## 12.5 后续审查补充（2026-11-19，D01-70~75）

以下四点为[第 16 章](16-follow-up-review-d01-70-75.md)裁决在本章的对应更新，细节以[第 16 章](16-follow-up-review-d01-70-75.md)为准：

1. **Shared Object**：共享对象身份，不等于跨 Branch 共享运行时修改结果；对 Shared Object 的局部修改属于当前 Branch 自己的 Command，不改变 Shared History（D01-70）。
2. **Branch**：动态继承模型——继承父地图截至分叉点（≤分叉时刻）的有效历史结果，只保存自有 Command；祖先分叉点及之前（≤）的 Command 后续新增或修改自动传播，分叉点之后（>）的新增或修改不影响（D01-71，V0.3 闭式边界）。
3. **Checkpoint**：按 Branch 归属，保存完整合成 World State（祖先继承状态 + Shared Object 在该 Branch 的有效状态 + 局部对象 + 自有 Command 执行结果）；祖先修改使受影响 Checkpoint 失效并重新生成（D01-72）。
4. **Combination Map**：整合语义修正为历史路径固化 `C = A_latest(<=1200) + B_own(>1200)`，不再是"继承父地图完整历史，再吸收子地图全部新增历史"（D01-74/75）。

## 12.6 后续讨论补充（2026-11-19，D01-76~100）

以下要点为[第 17 章](17-follow-up-discussion-d01-76-100.md)讨论结论在本章的对应更新，细节以[第 17 章](17-follow-up-discussion-d01-76-100.md)为准：

1. **重建单位**：用户一次只激活一条 Branch 时间线；按选定 Branch 的继承路径连续执行 Command；Shared Object 在该路径重建中持续接收 Command 影响，不是独立于 Branch Local Command 的权威历史（D01-76）。
2. **活动 Branch 与切换**：同一时刻只有一条活动 World State；切换 Branch 按目标 Branch 的有效 Checkpoint 恢复并继续执行；不存在有效 Checkpoint 时立即按祖先到后代顺序重建（D01-78/95）。
3. **Checkpoint 管理**：逐层复用祖先 Checkpoint；Checkpoint 保存生成时的完整继承路径版本组合，读取或使用前校验；重建任务建立使用引用，引用期间不物理淘汰；逻辑失效与物理淘汰分离；系统自动管理位置与数量，分叉点优先（D01-77/88/89~92）。
4. **失效与重建调度**：祖先历史修改触发受影响 Checkpoint 与路径版本的全局逻辑失效，只立即重建当前活动路径，非活动路径切换时按需重建；同一继承路径祖先到后代顺序执行，独立 Branch 可并行，调度不得改变历史语义（D01-84/94）。其中 D01-94 决定重建任务的触发范围，D01-84 决定已具备重建资格任务的调度方式；并行调度不得绕过 D01-94 主动启动已失效的非活动 Branch（V0.4.1）。
5. **失败处理**：Fail-Fast 约束单条继承路径的重建；严格区分重建失败（可进入受限修复模式）与继承阻断（只读）；一个 Branch 失败只阻断自己的后代；祖先修复后沿继承链恢复活动路径重建（D01-81/82/83/94/97~100）。

## 12.7 后续讨论补充（2026-11-19，D01-101~143）

以下要点为[第 18 章](18-checkpoint-topic-d01-101-143.md) Checkpoint 专题讨论结论在本章的对应更新，细节以[第 18 章](18-checkpoint-topic-d01-101-143.md)为准：

1. **基本定位与继承**：Checkpoint 是恢复缓存非权威历史；每个 Branch 每个历史时间点最多一个；按 Branch 归属；后代复用祖先分叉点有效 Checkpoint 后继续执行自有 Command；使用前校验完整继承路径版本（不能只查自身版本）；祖先历史变化沿路径传播失效；活动路径优先重建、非活动按需重建（D01-101~108）。
2. **创建与失败处理**：创建受唯一性约束；同一 Checkpoint 同时只能有一个有效生成任务；生成失败不发布；生成中继承路径版本变化旧任务立即失效；发布前再次完整校验；发布原子完成；不完整数据不可用（D01-109~114）。
3. **数据完整性与损坏**：恢复前必须完整性检查；单个损坏只影响自身、祖先损坏不连带后代失效；活动 Branch 自动恢复、非活动 Branch 只逻辑失效切换时按需重建；不建复杂损坏历史；仅在恢复失败或影响操作时通知（D01-115~122）。
4. **用户触发的全部重建与批量调度**：不能手动删除单个 Checkpoint；可要求全部重新创建（覆盖当前 Branch 及完整祖先继承路径、按祖先到后代顺序执行）；批量重建期间地图级锁定、不得切换 Branch 绕过；支持继续/修复与强制全部两种模式；目标范围启动时固定；进度与错误可查看；失败/取消/再次启动/祖先历史再次变化严格沿用既有裁决（D01-123~137）。
5. **单机应用与重启恢复**：单机应用软件；正常关闭或关机时安全停止重建任务、不要求关机期间继续计算；轻量级任务持久化 + 完成标记；启动时检查标记——有标记仍须通过版本与完整性校验，无标记视为未完成需重新创建（D01-138~140）。
6. **完成标记与 MD5**：完成标记只表示写入流程完成、不代替校验；`md5.txt` 记录组成文件与校验值，读取/恢复时重算比较，不一致或缺失即不可用需重建；防意外损坏、非防恶意篡改；与原子发布职责区分（D01-141/142）。
7. **保存内容**：指定 Branch 指定历史时间点的完整合成 World State，足以独立恢复并继续执行后续 Command；不含 Command、State Change、顺序约束、可重算警告/错误、隐式依赖、UI 状态（D01-143）。
