- Branch Checkpoint 的内部数据结构（格式留待技术设计，另见[第 13.4 节](13-known-pending-review-items.md)）。
- 祖先历史修改导致 Branch 自有 Command 无法执行时的报告与诊断流程。（V0.4 注：处理原则已定——Fail-Fast 停止、报告失败 Command 与祖先历史变化、失败时进入受限修复模式，见 D01-80/81/97；诊断流程细节待设计。）

特别注意已存在的用户裁决：

（2026-11-19：D01-73 已在 Branch 动态继承与重新重建场景再次确认该规则，见[第 16 章](16-follow-up-review-d01-70-75.md)。）

（V0.4 补充：D01-76~100 进一步确认——Branch 历史重建以选定继承路径为单位连续执行；祖先修改后全局逻辑失效、仅活动路径立即重建；重建失败与继承阻断严格区分并对应不同编辑权限，见[第 17 章](17-follow-up-discussion-d01-76-100.md)。）

## 13.7 Branch 重建调度、Checkpoint 管理与继承路径版本（D01-76~100）

**2026-11-19 更新（D01-76~100）**：以下语义已得到用户阶段性确认（裁决见[第 17 章](17-follow-up-discussion-d01-76-100.md)）——重建单位为选定 Branch 的继承路径连续执行（D01-76）；祖先修改后全局逻辑失效、活动路径优先重建、非活动路径按需重建（D01-94）；重建失败与继承阻断严格区分并对应不同编辑权限（D01-81/96~100）；Checkpoint 逐层复用、携带路径版本、引用保护（D01-77/88/91/92）。

机制方向已定、细节未定，仍需技术设计或用户进一步裁决的事项：

1. 继承路径版本的精确构成、分配与更新算法（D01-86 只确认"按继承路径维护、只更新受影响路径"的方向）。
2. 多 Branch 重建调度的具体策略：并行/串行动态选择的资源、任务数量与缓存评估方法（D01-84 只确认"动态选择且串并行结果必须一致"）。
3. Checkpoint 保存位置与淘汰策略的具体算法（D01-89/90 只确认分叉点优先、淘汰原则与保留优先级因素）。
4. Checkpoint 使用引用的计数机制与异常终止后的引用泄漏恢复（D01-91 明确要求处理，机制未定）。
5. **D01-68 与 D01-92 的规则关系（已明确；引用与淘汰机制待技术设计）**：D01-68 规定失效 Checkpoint"立即删除、不保留"（[第 10 章](10-world-state-cache-and-checkpoint.md)），D01-92 规定有引用时物理数据暂留、引用释放后物理淘汰。两条按 Checkpoint 生命周期的不同阶段统一理解，规则关系已经明确：
   1. Checkpoint 一旦失效，立即失去有效性。
   2. 失效 Checkpoint 不得再被读取为当前有效状态，也不得被用于恢复当前 World State。
   3. 没有任务引用时，立即进行物理淘汰。
   4. 仍有任务引用时，立即逻辑失效，但暂缓物理删除。
   5. 所有引用释放后，进行物理淘汰。
   6. 物理数据暂时存在，不代表 Checkpoint 仍然有效。

   **规则关系已经明确，具体引用计数、引用释放及异常恢复机制仍待技术设计。**
6. 修复模式中"每次修复保存即触发重建"（D01-97）与正常编辑流程"连续修改、用户主动触发重建"（D01-62）的状态边界：语义上按 17.26.2 Branch 操作阶段表区分（正常编辑 vs 自身重建失败），具体交互细节待设计。
7. **D01-82 与 D01-94 的合并理解（已明确；任务调度实现待技术设计）**：D01-82 确立祖先修复成功后自动检查直接后代并向下传播；D01-94 明确非活动 Branch 不立即重建、切换时才重建。两条按"自动传播检查机制"与"实际重建任务启动范围"两个不同概念统一理解，规则关系已经明确：
   1. 祖先修复成功后，系统自动检查受影响的后代 Branch。
   2. 当前活动继承路径上的后代，满足继承条件后自动启动重建。
   3. 非活动 Branch 不因祖先修复成功而立即启动重建。
   4. 非活动 Branch 保持待重建状态，在用户切换到该 Branch 时按需启动重建。
   5. 如果某个后代 Branch 自身重建失败，其后代进入继承阻断状态。
   6. 自动传播检查机制与实际重建任务的启动范围是两个不同概念。

   **规则关系已经明确，具体任务调度实现仍待技术设计。**
8. **D01-77 示例的精确恢复策略（未明确，未自行补充）**：D01-77 仅按原文记录"A@1200 恢复 → 执行 B 的 1200—1500 Command → 恢复 B@1500 → 执行 C 自有 Command"的逐层复用示例；当后代 Checkpoint（如 B@1500）本身有效时，是否可不经祖先起点回放而直接恢复，讨论中未明确，留待后续裁决。（V0.5 注：D01-101~143 明确了 Checkpoint 唯一性、版本与完整性校验及保存内容——D01-143 确认 Checkpoint 保存完整合成 World State、足以独立恢复该时间点状态；但本项所问"继承路径重建中，后代有效 Checkpoint 可否不经祖先起点回放直接恢复"仍未单独裁决，继续保留待后续讨论。）
