# 15. 当前阶段性结论

D01-01 至 D01-75 已形成一套相对完整的讨论方向：

**World View 以 Command 作为权威创作历史，以历史重建得到 World State，以可重建缓存和 Checkpoint 优化性能，以编译器式 Fail-Fast 机制发现设计冲突，并由作者决定如何修复。**

核心边界：

- 作者决定历史。
- Command 记录创作意图。
- State Change 和 World State 是可重建结果。
- 系统检查执行条件。
- 系统发现错误后停止重建。
- 用户修复设计后主动重新重建。
- 系统可以提出单项修复建议，但不能代替作者决定。
- Branch 动态继承父地图历史：继承分叉点及之前（≤分叉时刻）的历史状态，不复制祖先 Command；分叉点之后（>分叉时刻）的父历史新增或修改不影响分支（D01-71）。
- Shared Object 只共享对象身份与基础数据，不等于跨 Branch 共享运行时修改结果（D01-70）。
- 删除后的局部修改规则（持续警告、不自动复活、不阻断）同样适用于 Branch 的动态继承与重新重建（D01-73）。
- 组合地图（Branch 整合）通过历史路径固化形成独立历史：`C = A_latest(≤分叉点) + B_own(>分叉点)`；整合采用 Copy 并换发新 ID、重映射依赖与顺序约束、保留来源追溯；整合后与来源地图相互独立（D01-74/75）。
- 内部历史时间与日历显示分离。
- Branch Checkpoint 按 Branch 归属、保存完整合成 World State，仅是性能优化的派生缓存，不是权威历史（D01-65~69、D01-72）。
- 发布作品与创作工程分离。

**V0.4 增补（D01-76~100）**：后续讨论在上述方向上补充确认：

- 同一时刻只有一条活动 Branch 时间线 / 活动 World State；重建以选定 Branch 的继承路径为单位连续执行 Command，Shared Object 在该路径重建中持续接收 Command 影响，不构成独立的权威历史（D01-76/78）。
- Checkpoint 逐层复用祖先 Checkpoint，仍是完整 World State 的派生缓存；Checkpoint 与重建任务携带完整继承路径版本组合，发布或使用前校验（D01-77/86/87/88）。
- 祖先历史修改触发受影响 Checkpoint 与路径版本的全局逻辑失效，只立即重建当前活动路径，非活动路径切换时按需重建（D01-79/92/94/95）。
- Fail-Fast 约束单条继承路径的重建；重建失败（可进入受限修复模式）与继承阻断（只读）严格区分；一个 Branch 失败只阻断它自己的后代（D01-81/83/100）。
- Command 编辑权限按状态区分：正常 / 正在重建（暂时禁止历史编辑）/ 重建失败（受限修复，仅失败点及之前）/ 继承阻断（只读）/ 修复后重建成功（恢复正常），汇总表见 17.26.2（D01-96~100；重建结果状态汇总见 17.26.1）。
- Checkpoint 由系统自动管理位置与数量（分叉点优先），支持使用引用保护与淘汰；历史有效性与缓存物理生命周期分离（D01-89~92）。

**V0.5 增补（D01-101~143）**：Checkpoint 专题讨论补充确认：

- Checkpoint 是恢复缓存非权威历史：每个 Branch 每个历史时间点最多一个、按 Branch 归属；后代复用祖先分叉点有效 Checkpoint，恢复后继续执行自有 Command；使用前校验完整继承路径版本（不能只查自身版本）；祖先历史变化沿路径传播失效；活动路径优先重建、非活动按需重建（D01-101~108）。
- 创建与发布受唯一性、单一有效生成任务、生成中版本变化即失效、发布前完整校验与原子发布约束；生成失败与不完整数据不得发布或使用（D01-109~114）。
- 数据损坏只影响自身、不沿继承路径连带；祖先损坏不自动使后代失效；活动 Branch 自动恢复、非活动 Branch 逻辑失效后按需重建；不建复杂损坏历史，仅在恢复失败或影响操作时通知（D01-115~122）。
- 用户不能手动删除单个 Checkpoint，可要求重新创建全部 Checkpoint：覆盖当前 Branch 及完整祖先继承路径、按祖先到后代顺序执行；批量重建期间地图级锁定且不得切换 Branch 绕过；支持继续/修复与强制全部两种模式；目标范围启动时固定；进度与错误可查看；失败/取消/再次启动/祖先历史再次变化严格沿用既有裁决（D01-123~137）。
- 单机应用软件：正常关闭或关机时安全停止重建任务、不要求关机期间继续计算；轻量级任务持久化 + 完成标记 + MD5 校验保障完整性，不引入复杂恢复日志（D01-138~142）。
- Checkpoint 保存完整合成 World State（足以独立恢复并继续执行后续 Command），不保存 Command、State Change、顺序约束、可重算警告与隐式依赖、UI 状态；完成标记与 MD5 信息属于完整性管理信息，不属于 World State（D01-143）。

以上均为阶段性讨论结论，状态仍为 Proposed / Discussion（见第 17、18 章）。
