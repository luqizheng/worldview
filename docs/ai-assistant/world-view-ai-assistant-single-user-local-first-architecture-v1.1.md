# World View — 单机单用户与用户自带 LLM 架构补充 V1.1

- 文档状态：产品形态与模型所有权补充基线
- 版本：V1.1
- 日期：2026-11-20
- 适用范围：对《World View 内置 AI Assistant 产品与架构设计 V1.0》的产品部署形态、模型来源和数据边界作明确补充
- 关联文档：`world-view-ai-assistant-product-architecture-v1.0.md`、`world-view-ai-assistant-user-experience-v1.0.md`

## 1. 补充目的

本文件将 World View 的产品形态和 LLM 所有权明确为架构约束，避免将“内置 AI Assistant”误解为 World View 自行托管模型、提供云端 AI 账号，或采用多人 SaaS 架构。

本文件与总体架构 V1.0 配套阅读。若 V1.0 中“云端或本地 LLM 接入”等较宽泛表述可能引起歧义，以本补充文件对产品形态和模型来源的明确约束为准。

## 2. 产品形态：个人单机软件

World View 是面向个人创作者的单用户、单机软件。

- 一个本机用户使用和管理自己的 World View 数据。
- 地图、世界设定、地图对象、图层、布局、任务记录和正式历史由本机 World View 管理。
- 核心地图编辑、保存、导入和导出不依赖 World View 云端账号或在线服务。
- V1 不引入 Tenant、Team、组织成员、多人协作、云端共享工作区或在线多用户权限体系。
- 不把云端同步、跨设备协作和多人并发编辑作为基础产品能力。
- 本机数据目录和备份由用户控制；具体文件组织、自动备份与恢复策略在本机存储专题中设计。

“单机”描述的是产品和数据管理形态，不意味着软件不能通过网络调用用户选择的模型供应商。调用云端模型时，地图数据权威仍留在本机。

## 3. LLM 所有权与供应商接入

### 3.1 用户自带模型连接

- LLM 由用户自行选择并对接主流 LLM 供应商。
- 用户自行管理供应商账号、API Key、模型选择、额度和费用关系。
- World View 不默认提供托管模型账号，不替用户购买或代付模型额度，不将任何单一供应商设为唯一来源。
- 用户没有配置模型连接时，AI Assistant 的模型能力不可用，但 World View 的手工地图编辑和本地数据能力仍然可用。

### 3.2 统一 Provider Adapter

World View 提供内部统一的 Model Provider 接入层，由 Provider Adapter 屏蔽供应商之间的认证、请求/响应格式和能力差异。

用户配置项按供应商实际要求包括：

- 供应商或兼容接口类型；
- 连接名称；
- API Endpoint（供应商或兼容服务需要时）；
- API Key 或其他必要凭据；
- 模型标识；
- 可选的模型用途或默认模型设置。

首批支持范围应以开发和集成测试实际验证的主流供应商为准。产品文档不得提前承诺尚未实现的供应商、模型或能力。

可评估兼容 OpenAI API 风格的接口以扩大可接入范围，但必须检查工具调用、结构化输出、上下文长度和其他能力差异，不能仅凭接口格式相似就宣称完全兼容。

### 3.3 多模型配置原则

允许用户配置多个供应商连接，但 V1 初始体验以一个默认模型即可使用为目标。高级用户可以按用途选择模型；不要求普通用户配置复杂的模型路由、Agent 模型矩阵或多模型协作策略。

本地模型端点可以作为后续可选兼容接入方式评估，但不是 V1 的产品前提，也不改变用户自行配置模型连接的基本原则。

## 4. AI Assistant 与本机领域服务的边界

逻辑调用关系：

```text
本机用户
   |
   v
World View Desktop Application
   |
   +--> AI Assistant / Task Interaction
   |        |
   |        v
   |   Model Provider Adapter
   |        |
   |        v
   |   用户配置的 LLM 供应商（网络调用）
   |
   +--> World View Internal Tools
            |
            v
       Local Domain Services
            |
            v
       本机正式地图数据与历史
```

- AI Assistant 负责理解用户意图、组织上下文、规划步骤、调用模型、协调执行、解释结果和必要时询问用户。
- 用户配置的 LLM 负责语言理解、推理、规划建议和创作内容生成。
- Local Domain Services 负责确定性的地图业务操作、正式数据写入、对象身份、几何/拓扑/语义校验、权限边界和历史机制。
- LLM 不直接访问数据库、不直接修改正式地图文件，也不拥有正式数据权威。
- 模型供应商不可用时，已保存的地图和本机编辑功能不应因此不可用。

## 5. 数据传输与本机隐私边界

调用云端 LLM 时，World View 可能需要向用户选择的供应商发送任务文本和相关地图上下文。必须遵循最小必要原则：

1. 只发送完成当前任务所需的地图对象、属性、空间摘要、设定片段或用户资料。
2. 不默认上传整个地图数据库、整个世界资料库或本机全部文件。
3. 在适当的设置或任务界面向用户说明当前请求将使用哪些类型的上下文。
4. API Key 等凭据不得进入普通任务日志、模型提示词或错误回显。
5. 本机正式地图数据仍以 Domain Services 保存结果为准；供应商响应不是正式数据。
6. 用户可以关闭 AI、切换供应商或删除模型连接，不影响本机地图数据。
7. 供应商侧的数据处理、留存和费用由用户选择的供应商政策决定；World View 不应替供应商作出保证。

## 6. 本机安全与连接设置

- 凭据应使用目标操作系统支持的安全存储机制；不要以明文形式保存在普通配置文件或日志中。
- 设置界面不回显完整 API Key，只显示已配置状态和必要的末尾标识（如适用）。
- 支持连接测试、模型可用性检查、禁用、更新和删除连接。
- 错误信息应区分认证失败、网络失败、模型不存在、限流、超时和供应商服务错误。
- 删除模型连接只删除连接配置，不影响地图、世界设定、任务历史或正式地图历史。

## 7. 对 V1.0 架构文档的解释与优先级

1. V1.0 中“内置 AI Assistant”指 AI 交互和任务能力内置于 World View 应用，不表示 World View 自己托管 LLM。
2. V1.0 中“统一模型接口”应解释为 World View 对用户配置的供应商连接提供统一适配层。
3. V1.0 中“云端或本地 LLM”属于宽泛的未来接入可能性；V1 当前主路径是用户自行配置主流 LLM 供应商，本地模型端点仅作为可选扩展评估。
4. V1.0 中的内部工具/API 是应用内部调用边界，不是要求部署外部 HTTP API、MCP 服务或 Agent Runtime。
5. V1.0 的任务规划、候选、预览、验证和正式应用规则继续有效，但执行主体是本机 World View 内置 AI Assistant 与本机领域服务协同工作。
6. 本补充文件与用户交互 V1.0 配套，进一步明确单机、单用户、用户自带 LLM 的体验约束。

## 8. 不属于当前产品基线的能力

以下内容不属于 V1 核心架构：

- World View 官方托管模型服务或统一代付模型费用；
- 强制绑定某一家 LLM 供应商；
- 依赖云端 World View 账号才能使用地图编辑器；
- 多用户在线协作、团队工作区或组织权限；
- 外部 Agent、Codex、Claude Code、MCP 作为地图制作运行依赖；
- 将地图正式数据的权威存储迁移到模型供应商或第三方云端 Agent 平台。
