- 适用范围：World View 单用户、单机桌面软件
- 上位文档：`world-view-ai-assistant-product-architecture-v1.0.md`、`world-view-ai-assistant-context-builder-v1.0.md`、`world-view-ai-assistant-task-model-and-lifecycle-v1.0.md`

## 1. 目的

本文定义 AI Assistant 如何理解用户请求、构建任务上下文、生成可执行计划并验证计划。

Planner 是一个逻辑模块，不是独立 Agent，也不是独立服务。它与 AI Assistant、Task Coordinator、Tool Executor 协作。

## 2. 规划原则

1. 不是每条用户消息都需要创建 Task。
2. 简单任务与复杂任务使用统一 Task 模型，避免两套执行架构。
3. 默认顺序执行，不建立通用 DAG 工作流引擎。
4. 规划结果必须可解释、可检查、可恢复。
5. AI 可调整方法，但不能擅自改变目标、范围、验收条件或授权。
6. 是否需要人工确认由语义风险、权限和产品规则决定，不由任务复杂度单独决定。

## 3. Planner 的四个逻辑环节

### 3.1 Intent Analyzer

判断用户请求属于哪类意图，以及是否需要创建 Task。

意图类型：

- `General Conversation`：普通对话，不创建 Task。
- `Information Request`：查询或收集信息；根据工作量决定是否创建 Task。
- `Map Operation`：地图操作，通常创建简单 Task。
- `Complex Map Creation`：复杂地图制作，创建完整计划和多个 Step。

### 3.2 Context Builder

收集完成任务所需的最小上下文，例如：

- 用户原始请求与当前对话中明确的约束；
- 当前地图、Branch、时间点和修订状态；
- 相关对象、图层、历史和世界设定；
- 相关 Generation Session / Candidate 引用；
- 可用工具及其能力、权限和前置条件；
- 已有任务结果和必要来源信息。

Context Builder 复用独立的 Context Builder 架构，不在 Planner 内重复实现另一套检索系统。

### 3.3 Plan Generator

生成 Task Plan。每个 Step 至少包含：

- `Objective`：这一步要达成什么；
- `Input`：需要哪些输入和引用；
- `Action`：执行什么动作、需要什么能力；
- `Acceptance Criteria`：如何判断这一步完成。

计划应说明必要的先后顺序、预期输出和失败时可采取的安全处理方式。

### 3.4 Plan Validator

检查计划是否：

- 完整覆盖用户目标；
- 步骤输入和输出明确；
- 顺序合理，前置条件满足；
- 所需工具存在且能力匹配；
- 不违反权限、风险和正式数据边界；
- 验收标准明确且没有被降低；
- 不包含不必要的步骤或过度拆分。

验证失败时要求 Planner 修正，不将不可执行计划交给 Coordinator。

## 4. 复杂度分级

建议使用三级描述规划深度：

- `Simple`：单一、明确、低风险动作，通常一个 Step。
- `Moderate`：需要少量信息收集、分析和多个步骤。
- `Complex`：多阶段地图制作，存在多项输入、验证和候选整理。

复杂度只影响规划深度与拆分粒度，不自动决定是否需要人工批准。

## 5. 执行顺序与依赖

V1.0 默认按 `sequence` 顺序执行。后续 Step 通过前序 Step 的输出引用获得输入。

不引入：

- 通用 DAG 引擎；
- 动态任务调度器；
- 分布式 Worker Pool；
- 多 Agent 自治规划和项目管理体系。

如未来真实用例证明有必要并行，再基于具体瓶颈评估，而不是预先建设。

## 6. 动态重新规划

执行过程中出现工具不可用、数据不足、结果不符合验收条件或前置状态变化时，AI 可以提出新的计划版本。

重新规划规则：

1. 记录触发原因和新旧计划差异。
2. 保留仍然有效的已完成 Step。
3. 只有输入失效、输出不再适用或授权范围内的验收条件变化，才重做已完成 Step。
4. 不得通过重新规划改变用户目标、扩大范围、降低验收要求或绕过人工确认。
5. 超出原目标或授权时暂停并询问用户。

## 7. 人工确认策略

不要求所有 Task 在执行前都由用户批准计划。

- 简单、明确、低风险任务：可以自动规划并执行。
- 复杂但目标明确、权限充分的任务：可展示计划，同时按既定授权执行。
- 缺少必要信息、存在重大语义歧义、涉及高影响操作或超出授权：暂停并请求用户决策。
- 正式地图应用仍遵循 Change Set 和对应确认策略。

## 8. 验收标准

1. 普通聊天不会被强制转换为 Task。
2. 简单和复杂任务共享统一模型。
3. Planner 四个环节职责明确，但不拆成多个 Agent。
4. 每个 Step 有目标、输入、动作和验收标准。
5. 默认顺序执行，不需要 DAG。
6. 计划经过可执行性和权限验证。
7. 允许授权范围内动态重新规划，并保留版本。
8. 目标、范围、验收标准和授权不得由 AI 擅自改变。
