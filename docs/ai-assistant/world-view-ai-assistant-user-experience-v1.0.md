# World View — AI Assistant 用户交互与任务执行体验设计 V1.0

- 文档状态：产品交互设计基线
- 版本：V1.0
- 日期：2026-11-20
- 产品形态：单用户、单机桌面软件
- 适用范围：地图编辑器内置 AI Assistant 的模型配置、任务交互、执行进度、预览确认、异常恢复
- 依赖文档：`world-view-ai-assistant-product-architecture-v1.0.md`、`02-map-generation-specification-v0.2.md`、`03-map-generation-workflow-v0.2.md`、`04-generation-session-lifecycle-v0.2.md`

## 1. 目标与产品前提

World View 是面向个人创作者的单机软件。它不是多人协作平台，不以在线账号体系、团队权限、云端工作区或外部 Agent 服务作为产品成立的前提。

地图、世界设定、地图对象、图层、布局、任务记录和正式历史由用户本机运行的 World View 管理。用户可以在本机创建、编辑、保存和导出地图；AI 能力需要用户自行配置并连接其选择的 LLM 供应商。

World View 内置 AI Assistant 是地图编辑器中的智能交互能力，不是一个独立的云端 AI 服务。它使用用户配置的模型完成自然语言理解、任务规划、创作辅助和结果解释，并通过 World View 内部受控能力请求本机 Domain Services 执行正式地图操作。

本设计的目标是让用户只需描述想制作或修改的地图，AI 就能理解上下文、合理规划、自主完成授权范围内的工作，并在必要时把真正需要用户判断的事项交还给用户。

## 2. 不可违反的产品边界

### 2.1 单用户、单机

- V1 按一个本机个人用户设计，不引入 Tenant、Team、多人协作、在线共享工作区或组织级权限模型。
- 本机用户是地图、世界设定、模型配置和本地数据的控制者。
- 不要求注册 World View 云端账号才能使用核心地图编辑能力。
- 不把云端同步、跨设备协作或多人同时编辑作为基础功能前提。
- 本机文件访问、应用设置和敏感配置遵循操作系统及应用自身的本地安全机制。

### 2.2 LLM 由用户自行对接

- World View 不默认向用户提供托管模型服务，不替用户购买模型额度，也不把某个供应商设为唯一模型来源。
- 用户自行选择并配置其可用的主流 LLM 供应商、模型和连接凭据。
- World View 提供统一的模型连接配置体验和内部模型调用接口；不同供应商的认证、请求格式、模型能力差异由 Provider Adapter 屏蔽。
- 首批支持哪些供应商、各供应商的模型清单及能力差异属于兼容性规划，应以实际验证结果为准，不在产品设计中承诺未经实现的供应商或模型。
- 可优先支持主流供应商的官方接口，并评估兼容 OpenAI API 风格的服务作为扩展接入方式；兼容接口不代表所有模型能力完全一致。
- 用户可以配置多个模型连接，并为不同任务指定默认模型或用途模型；具体路由策略应保持简单，避免要求用户理解复杂的模型编排。
- API Key 等凭据应安全保存在本机，界面默认隐藏；日志、诊断信息和任务记录不得明文泄露凭据。
- 用户可测试连接、查看连接状态、修改模型配置、禁用或删除连接。删除连接不应删除地图数据或正式历史。

### 2.3 AI 不等于地图数据权威

- LLM 不直接读写地图数据库或本地正式数据文件。
- AI Assistant 通过 World View 内部工具/API 请求 Domain Services 执行操作。
- Domain Services 负责权限边界、对象身份、几何与拓扑约束、数据一致性、保存和正式历史。
- 模型输出、候选内容和建议不能被误认为已经写入正式地图。
- 即使模型连接不可用，用户仍应能够手工编辑、保存、导入和导出已有地图。

### 2.4 外部 Agent 不是产品运行条件

Codex、Claude Code、MCP、外部 Agent 或第三方自动化平台不属于核心地图制作运行链路。未来可以作为可选扩展，但用户不需要安装或配置它们才能使用 AI 地图制作。

## 3. AI Assistant 在编辑器中的位置

### 3.1 统一交互入口

AI Assistant 内置于地图编辑器，与地图画布、工具栏、图层树和属性面板协同工作。用户不需要切换到独立的 Agent 管理界面。

推荐桌面交互结构：

- 地图画布仍是主要工作区域；
- AI Assistant 以可展开/收起的侧边面板或底部对话区呈现；
- 用户输入区固定且易于访问；
- 任务执行时显示简明计划、当前步骤、进度和必要的待处理决策；
- AI 提及地图对象时，可定位、选中或高亮对应对象；
- 预览结果直接叠加在地图画布中，用户可以空间化检查，而不是只阅读文字清单。

AI 面板不应长期遮挡主要地图区域。用户可以调整面板尺寸、收起面板，或在需要时重新打开任务上下文。

### 3.2 以地图上下文为中心

AI Assistant 默认感知当前编辑上下文，包括当前地图、Branch、地图时间、视口范围、选中对象、活动图层和当前编辑模式。只读取完成当前任务所需的信息，不把整个地图无差别塞入每次模型请求。

用户可以通过自然语言、当前选中对象、画布框选区域或属性面板发起任务。上下文不足时，AI 应说明它准备操作的对象或区域，避免静默猜测。

## 4. 用户提出地图任务

### 4.1 自然语言优先

用户可以直接输入例如：

- “在这片大陆上生成三条主要山脉和四条大河。”
- “把选中的河流改成蓝色，宽度稍微增加。”
- “为当前地图补充十二个国家，尽量保留现有城市。”
- “检查这张奇幻地图的地形和国家分布是否符合世界设定。”
- “把这一区域整理成适合教学展示的局部地图。”

AI 应结合地图上下文识别任务目标、对象范围、约束、样式意图和验收条件。用户不需要填写技术规格表。

### 4.2 用户可补充的上下文

用户可以选中对象、框选区域、指定图层、引用地图中的标签或对象名称，来缩小任务范围。AI 应优先使用明确的选中状态和用户指向，不应擅自扩大范围。

### 4.3 澄清原则

只有当缺失信息会实质改变结果、导致不可逆影响、违反保护项或产生重大语义分歧时才询问用户。非关键细节可在用户已授权的创作自由度内自主决定，并在完成摘要中说明。

不要把每个任务都转化为多轮问卷。一个问题足以解决歧义时，只问最关键的一个问题。

## 5. AI 理解、计划与自主执行

### 5.1 简单任务直接执行

对于明确、低风险、可逆的操作，例如修改选中对象的颜色、调整标签大小、创建一个普通标注，AI 可以：

1. 确认目标对象和操作含义；
2. 检查当前地图上下文和必要约束；
3. 调用本机 Domain Services 执行；
4. 验证结果并简短反馈。

无需强制显示完整计划、生成候选会话或要求用户再次批准。

### 5.2 复杂任务展示简明计划

对于多阶段或大范围任务，AI 应先展示用户能理解的任务摘要和主要阶段，例如：

1. 分析当前地图与目标区域；
2. 建立自然地理结构；
3. 生成政治区域与聚落；
4. 检查空间和语义关系；
5. 预览并汇总结果。

计划用于建立预期和展示执行方向，不代表用户必须逐项审批。用户可以在开始前修改目标、限制范围或取消任务。

### 5.3 自主执行边界

在用户明确目标、授权范围和保护项之内，AI 可以自主拆分步骤、调用模型、运行确定性算法、检查结果、修复普通质量问题并继续执行。

以下情况应暂停并请求用户决策：

- 关键意图存在多种合理解释，且结果差异显著；
- 需要改变正式世界设定或重大历史事实；
- 将删除或大范围改写既有重要对象；
- 影响共享边界、重要拓扑关系或多个区域；
- 与用户明确保护项或硬约束冲突；
- 操作超出用户授权范围，或后果难以安全撤销。

AI 不得把用户同意任务目标，扩大解释为对未披露高影响变更的授权。

## 6. 任务进度与地图反馈

### 6.1 进度呈现

复杂任务应在 AI 面板中展示：

- 当前任务名称和简短目标；
- 主要步骤及状态：待执行、执行中、已完成、受阻、跳过或失败；
- 当前正在处理的地图区域或对象类型（适用时）；
- 已完成内容和下一步；
- 需要用户处理的问题。

只有存在可信估算时才显示百分比。不要为了视觉效果显示虚假的精确进度。

### 6.2 画布同步反馈

执行过程中可以在地图画布上显示非正式候选预览或临时高亮，明确区分：

- 正式地图内容；
- 尚未应用的候选内容；
- 当前步骤正在处理的区域；
- 验证发现的问题。

临时候选不得被误认为正式保存结果。用户可以关闭预览而不影响正式地图。

### 6.3 用户控制

运行中的任务至少支持：

- 暂停：在安全边界暂停后续步骤；
- 继续：从有效任务状态继续；
- 修改要求：更新任务约束，并重新评估受影响步骤；
- 取消：停止尚未开始的步骤，并安全结束执行中的步骤。

取消任务不会自动撤销已经正式应用的成果。已应用成果按地图编辑器 Undo/Redo 或正式领域操作处理。

## 7. 预览、接受与修改

### 7.1 预览触发条件

大范围生成、批量修改、重要对象删除、共享边界变化、正式世界设定变化或其他高影响操作，应提供可视化预览或明确影响摘要。

普通、明确、低风险且已获授权的操作可以直接应用。

### 7.2 预览界面

预览应直接叠加在地图画布上，并提供必要的差异视图：

- 新增对象；
- 修改对象；
- 删除对象；
- 关系或共享边界变化；
- 图层、标签、符号和样式变化；
- 受影响的既有对象；
- 未通过的质量检查和未解决事项。

用户可以定位单个变更、按对象类型或区域筛选，并查看变化前后状态。

### 7.3 用户决策操作

根据变更的独立性，提供：

- 接受全部；
- 接受选定变更；
- 拒绝全部；
- 要求 AI 修改后重新预览。

用户不应被迫理解 Change Set、Candidate 等内部术语。界面使用“预览结果”“新增内容”“修改内容”“应用到地图”等自然表达。

确认必须绑定具体预览版本。若地图状态或候选内容发生实质变化，旧确认失效，应重新展示差异并取得必要确认。

## 8. 模型供应商与连接设置体验

### 8.1 首次启用 AI

用户首次使用 AI 功能时，如果尚未配置模型连接，显示清楚的引导：

1. 说明 World View 不提供默认托管模型账号；
2. 引导用户选择受支持的供应商或兼容接口；
3. 输入必要的 API 地址、API Key 和模型标识；
4. 测试连接；
5. 选择默认模型并保存本机配置。

不得在没有模型连接时假装 AI 功能已经可用。与此同时，地图编辑器的非 AI 功能仍应正常工作。

### 8.2 配置管理

设置页集中管理模型连接：

- 连接名称；
- 供应商类型或兼容接口类型；
- API Endpoint（供应商需要时）；
- 凭据状态（只显示已配置/未配置，不回显完整密钥）；
- 可用模型标识；
- 默认模型；
- 连接测试结果和最近测试时间；
- 启用/禁用状态。

支持多个连接，但初始体验应保持简单：一个默认模型即可开始使用，其他连接属于可选高级配置。

### 8.3 模型能力差异

不同模型对结构化输出、长上下文、视觉输入、工具调用和响应速度的支持可能不同。World View 应维护能力声明和兼容性检查；不支持某项能力时，应采用可用替代路径或明确告知用户，而不是假设所有模型等价。

### 8.4 费用与数据传输透明度

- 向用户明确提示：使用云端供应商可能产生供应商侧费用，费用由用户与供应商之间的服务关系决定。
- 在发送请求前，应让用户知道哪些任务上下文或资料会被发送给所选供应商。
- 不发送完成任务不需要的地图内容、文件或敏感信息。
- 用户可以关闭 AI 请求、切换模型或删除连接；不应因此影响本机地图数据。

## 9. 异常与恢复体验

### 9.1 模型连接失败

显示可理解的错误原因，例如连接失败、认证失败、模型不可用、请求超时或供应商限流。提供重试、检查设置或切换已配置模型的操作。不要暴露原始密钥或堆栈信息作为普通用户提示。

### 9.2 模型输出无效

当模型返回结构错误、无法解析或不符合领域契约时，World View 应拒绝该输出并尝试有限次数的修复或重试。不得将无效输出写入正式地图。

### 9.3 质量检查失败

将问题分成阻断项、警告项和建议项。阻断项未解决时不得应用相关变更；警告项应说明影响；建议项不应阻止用户继续。

### 9.4 任务部分完成

如果部分步骤成功、部分失败，应准确展示已完成内容、未完成内容和失败原因。允许用户重试失败部分，不要为了重跑全部任务而破坏已经正确完成的成果。

### 9.5 应用前地图已变化

若用户在 AI 生成期间手工修改了相关对象，应用前重新检查基准状态和冲突。不得使用旧候选覆盖新修改；需要时重新生成预览。

### 9.6 应用程序退出或崩溃

任务记录和已正式应用的地图内容应能在应用重启后恢复到可解释状态。未完成候选不得自动应用。恢复时重新检查模型连接、地图基准状态和候选有效性。

## 10. 本地数据、隐私与安全体验

- 地图正式数据和世界设定默认保存在用户本机指定的数据位置。
- 模型 API Key 等连接凭据使用操作系统支持的安全存储能力；具体实现按目标平台确定。
- 用户的地图内容只有在调用云端模型且确有必要时才发送给用户配置的供应商。
- 应在设置或任务上下文中提供清晰的数据发送说明。
- 任务日志记录必要的执行状态和诊断信息，但默认避免保存完整密钥、无关文件内容或不必要的完整模型上下文。
- 用户应能清理可清理的任务日志和临时候选；清理不得删除正式地图历史和必要的数据完整性信息。
- 崩溃报告和诊断信息不得未经明确授权自动上传地图内容。

## 11. 交互文案原则

面向用户的界面不应要求用户学习后台架构术语。优先使用：

| 内部概念 | 用户界面表达 |
|---|---|
| Task Specification | 任务要求 / AI 对任务的理解 |
| Task Plan | 执行计划 |
| Session | 任务 |
| Candidate | 待预览内容 / 生成结果 |
| Change Set | 变更预览 |
| Validation Report | 检查结果 |
| Domain Services | 不向用户展示 |
| Provider Adapter | 模型连接方式（通常不必展示） |

AI 应说明它准备做什么、正在做什么、完成了什么、遇到什么问题；不要向普通用户暴露内部服务调用、编排器或 Agent 拓扑。

## 12. 第一版建议范围

第一版优先形成可用闭环：

1. 本机地图编辑器中的 AI Assistant 面板；
2. 用户自行配置至少一类实际验证过的主流 LLM 连接；
3. 连接测试、默认模型设置和安全凭据保存；
4. 自然语言创建、修改和检查地图对象；
5. 简单任务直接执行，复杂任务展示简明计划；
6. 任务进度、暂停、继续和取消；
7. 候选预览、必要的用户确认和应用结果反馈；
8. 几何、拓扑、语义和任务约束验证；
9. 模型不可用时，手工地图编辑和本地保存仍可正常使用。

后续再扩展多供应商智能路由、视觉模型能力、复杂多阶段生成、模型能力自动评估和更多供应商适配。不得让高级模型路由复杂度阻碍第一版地图制作体验。

## 13. 验收场景

### 场景 A：未配置模型

用户打开 World View，可以正常创建和编辑地图。打开 AI Assistant 时，系统提示配置模型连接；不影响非 AI 功能。

### 场景 B：用户配置云端模型

用户输入自己供应商的连接信息，测试成功后选择默认模型。AI Assistant 能理解任务并调用本机地图领域服务，正式地图数据仍由本机 World View 管理。

### 场景 C：简单编辑

用户选中河流并要求改色。AI 检查选中对象后直接应用，地图画布即时更新，并可通过编辑器 Undo/Redo 撤销。

### 场景 D：复杂生成

用户要求生成大陆自然地理、国家和城市。AI 展示简明阶段计划，自主执行和检查，在画布中展示候选结果；涉及重要设定或高影响变更时暂停请求用户决定。

### 场景 E：模型连接中断

任务执行期间供应商连接失败。系统保留任务状态和未应用候选，显示可操作错误；用户可以重试或切换模型，不能把失败输出写入正式地图。

### 场景 F：地图并发状态变化

AI 生成期间用户手工修改了目标对象。应用前检测到基准变化，系统阻止旧候选覆盖，并要求重新检查或预览。
