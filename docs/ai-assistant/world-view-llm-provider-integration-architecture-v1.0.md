# World View — LLM Provider Integration Architecture

- 文档版本：V1.0
- 日期：2026-11-20
- 状态：技术架构推荐基线（供应商首批支持范围与具体实现仍待工程验证）
- 适用范围：World View 单用户、单机桌面软件；用户自行配置主流 LLM 供应商

## 1. 目的与设计原则

本文定义 World View 如何连接用户自行选择的 LLM 供应商，以及如何在不交出本机地图数据权威的前提下，使用模型完成自然语言理解、任务规划、内容生成和工具调用。

核心原则：

1. **Local-first**：地图、世界设定、对象、图层、布局、任务记录和正式历史由本机 World View 管理。
2. **Bring Your Own Model**：用户自行选择供应商、账号、模型并承担供应商侧费用。World View 不默认托管模型、不代付额度、不锁定单一供应商。
3. **One Assistant**：用户只面对一个内置 AI Assistant；供应商适配和工具执行属于后台实现。
4. **Model is not authority**：LLM 输出是建议、候选或工具请求，不是正式地图数据权威。
5. **Domain Services execute**：所有正式地图操作由本机 Domain Services 执行，遵循领域约束、权限、事务和正式历史机制。
6. **Least-context disclosure**：每次云端请求只发送完成当前任务所需的最小上下文，不默认上传完整地图或全部本机文件。
7. **Graceful degradation**：没有模型连接时，非 AI 地图编辑、保存、导入和导出仍然可用。
8. **Capability-aware**：不能仅凭供应商名称或 API 兼容标签推断能力；必须按实际模型和端点检测、记录并处理能力差异。

## 2. 总体架构

```text
User
  │
  ▼
World View Desktop Application
  ├── Map Editor / Local Project Data
  ├── AI Assistant (conversation, task understanding, planning, result explanation)
  │     ├── Context Builder (minimum necessary context)
  │     ├── Model Gateway
  │     │     └── Provider Adapter(s)
  │     │            └── User-selected LLM Provider / Endpoint
  │     └── Internal Tool Gateway
  │            └── Local Domain Services
  │                   └── Local authoritative map data and history
  └── Local Settings & OS Secure Credential Store
```

职责边界：

- **AI Assistant**：管理用户交互、理解意图、规划步骤、选择可用工具、协调模型请求、解释结果、决定何时向用户询问。
- **Context Builder**：从本机领域服务按任务需要读取地图状态、选中对象、相关世界设定和必要资料；负责裁剪、脱敏提示和上下文预算。
- **Model Gateway**：统一调用入口，管理模型连接选择、能力约束、请求超时、流式响应、重试策略和错误归一化。
- **Provider Adapter**：将统一请求转换为供应商/端点特定协议，并将响应转换为统一内部表示。
- **Internal Tool Gateway**：验证模型提出的工具调用、参数、授权范围和当前地图状态；拒绝越权或不合法请求。
- **Domain Services**：执行确定性地图操作、几何/拓扑校验、正式数据写入、事务和历史记录。
- **Local Settings**：保存非敏感连接元数据；密钥单独存入操作系统安全凭据设施。

LLM 不直接访问本机数据库、地图文件系统或内部任意 API。LLM 只能通过本轮请求明确提供的工具描述提出受控调用；工具调用由 World View 本机代码验证和执行。

## 3. 用户连接配置模型

### 3.1 连接信息

每个模型连接建议包含：

- `connection_id`：本机生成的稳定标识。
- `provider_type`：内置适配器类型或 OpenAI-compatible 自定义类型。
- `display_name`：用户可读名称，例如“我的主力模型”。
- `endpoint_base_url`：供应商 API 基础地址；内置供应商可使用经过验证的默认值，自定义端点由用户明确填写。
- `credential_reference`：指向 OS Secure Storage 中密钥条目的引用，不包含密钥本身。
- `model_id`：供应商侧模型标识，作为字符串原样保存。
- `is_default`：是否为默认连接；V1 同一工作区只设一个默认模型。
- `enabled`：用户是否启用该连接。
- `last_tested_at`、`last_test_status`：最近连接测试状态。
- `capability_snapshot`：最近检测到的能力及检测时间，仅作为运行时参考，不作为永久保证。

密钥不得写入连接配置对象、普通项目文件、导出配置、日志、崩溃报告或提示词。

### 3.2 V1 用户体验

V1 以“配置一个默认模型即可使用”为目标：

1. 用户在设置中选择一个内置供应商，或选择兼容接口类型。
2. 填写/粘贴 API Key，选择或填写 Model ID。
3. 如供应商需要，设置 Endpoint。
4. 点击“测试连接”。
5. 显示连接是否成功、检测到的能力、模型标识及明确的失败原因。
6. 用户保存后，该连接成为默认模型，AI Assistant 使用它完成常规任务。

允许保存多个连接作为用户主动配置的备用项，但 V1 不引入复杂模型路由、自动成本优化、任务类型自动选模或多模型投票等普通用户负担。切换默认模型应由用户明确操作。

### 3.3 首批供应商策略

推荐按“适配器可维护性 + 实际集成测试”确定首批供应商，而不是在产品文案中提前承诺一个未经验证的兼容清单。

建议工程接入顺序：

1. 先实现通用 Provider Adapter 契约和 Mock Provider，稳定内部请求/响应语义。
2. 选择一至两个主流云端供应商实现原生适配器，并验证文本对话、工具调用、结构化输出、流式响应、错误处理和上下文限制。
3. 再评估 OpenAI API 风格兼容端点，明确逐家/逐模型兼容矩阵。
4. 根据真实用户需求和维护成本扩展更多供应商。

具体供应商名称、模型列表、最低能力要求及正式支持状态应在工程验证后另行维护，不在本文件中预先冻结。供应商模型和 API 会变化，支持矩阵必须有验证日期和适配器版本。

## 4. Provider Adapter 与统一调用接口

### 4.1 内部统一请求

建议统一请求对象包含：

- `request_id`：本机生成，用于日志关联，不包含密钥。
- `connection_id` / `model_id`：本次调用所选连接和模型。
- `messages`：统一消息列表，区分 system/developer/user/assistant/tool 等内部角色；映射到供应商协议时由适配器处理。
- `tools`：本轮允许调用的工具定义及 JSON 参数 Schema。
- `response_format`：可选的结构化输出要求。
- `stream`：是否请求流式响应。
- `generation_options`：受支持的温度、输出上限等参数；仅传递适配器确认支持的参数。
- `timeout_policy`：本机请求超时约束。
- `context_policy`：本轮上下文来源、用途和敏感级别的内部元数据，不直接全部发送给模型。

统一响应应包括：

- 文本内容或结构化内容；
- 零个或多个工具调用请求；
- finish reason / stop reason；
- usage（供应商提供时记录输入/输出 token 等）；
- 供应商 request ID（如有）；
- 归一化错误；
- 实际模型 ID、适配器版本和能力快照引用。

统一接口应避免把单一供应商特有字段泄漏到 AI Assistant 业务逻辑。确有供应商特性时，通过受控的 adapter capability/extension 表达，不得让业务层依赖随意拼接的原始 JSON。

### 4.2 Adapter 生命周期

建议适配器提供以下能力：

- `validate_config`：校验端点、模型标识和必填配置。
- `test_connection`：进行最小化连通性测试，不触发地图工具。
- `discover_models`（可选）：在供应商支持且权限允许时列出模型；不能列出时允许用户手动填写 Model ID。
- `probe_capabilities`：检测/验证本次任务需要的能力。
- `send`：发送统一请求并返回统一响应。
- `stream`：将供应商流式事件映射为统一事件流。
- `normalize_error`：把供应商错误转换为稳定的内部错误类别。

Adapter 应有明确版本号、供应商协议版本（如适用）、超时和取消支持。供应商 SDK 可作为实现细节，但不能成为领域层的数据模型。

## 5. 模型能力声明与检测

能力必须以“连接 + 模型 + 端点 + 适配器版本”为维度记录，不得只以供应商为维度。

V1 至少评估以下能力：

| 能力 | 含义 | 缺失时的处理 |
|---|---|---|
| Text chat | 普通文本对话 | 不可作为 AI Assistant 默认模型 |
| Tool / function calling | 返回受结构约束的工具调用请求 | 禁用依赖工具调用的自主执行；可降级为文本建议/人工复制，不得假装已执行 |
| Structured output | JSON / JSON Schema 约束输出 | 使用受控文本解析与严格校验；失败则重试一次或请求修正，仍失败则停止该步骤 |
| Streaming | 流式返回内容 | 使用非流式响应；不影响任务正确性 |
| Vision | 理解图片输入 | 禁用图片理解相关任务，或提示用户提供文字描述 |
| Context window | 可用上下文容量 | Context Builder 按保守预算裁剪，必要时分阶段处理 |
| Output limit | 最大输出容量 | 拆分生成任务或限制输出规模 |
| Cancellation | 中断进行中的请求 | 本机停止等待并标记请求状态；说明供应商端可能仍在处理/计费 |

能力检测分为：

1. **声明能力**：供应商文档或用户配置声称支持。
2. **探测能力**：通过低风险、最小化测试请求验证。
3. **运行时确认**：真实请求成功使用某能力，记录成功/失败证据。

能力快照可能过期，模型版本、端点、账号权限或供应商更新都可能改变结果。连接测试不得把“能返回文本”误报为“支持工具调用和结构化输出”。

## 6. 工具调用安全闭环

工具调用是模型请求 World View 执行操作的提议，不是直接执行指令。

标准闭环：

1. AI Assistant 根据任务选择本轮允许暴露的工具集合。
2. Model Gateway 将工具定义和参数 Schema 交给模型。
3. LLM 返回普通文本或 Tool Call 请求。
4. Internal Tool Gateway 校验工具是否在本轮白名单、参数是否符合 Schema、对象是否存在、地图状态是否仍匹配、用户授权是否覆盖该操作。
5. 对有风险的操作执行风险评估；需要用户决策时暂停并询问。
6. 通过 Domain Services 执行确定性业务操作和验证。
7. 返回结构化工具结果给 AI Assistant；如任务需要，再将必要结果发回模型继续推理。
8. AI Assistant 汇总实际执行结果，明确区分成功、失败、部分完成和仅生成建议。

关键约束：

- 模型不能创建任意工具、扩大权限或自行批准操作。
- 模型不能指定任意本机文件路径、任意 URL、数据库语句或系统命令。
- 工具参数必须经过本机类型、范围、业务规则和授权检查。
- 正式地图写入必须经过 Domain Services；不能由模型直接改数据库或文件。
- 重要操作需具备幂等键/请求关联，避免重试造成重复对象或重复事件。
- 应用候选前必须复核地图基准状态；地图已变化时旧候选标记为 stale，不得覆盖新状态。
- 取消任务不自动撤销已经正式应用的成果；如需恢复，走明确的编辑器 Undo 或正式历史规则。

## 7. 本机凭据与配置安全

### 7.1 密钥保存

API Key 应保存在操作系统提供的安全凭据存储中：

- Windows：优先使用 Windows Credential Manager 或 DPAPI 保护的凭据方案。
- macOS：使用 Keychain。
- Linux：使用 Secret Service / libsecret 等可用的系统凭据服务；若运行环境不具备安全凭据服务，应明确告知用户并提供安全降级决策，不得静默明文保存。

具体实现可根据桌面技术栈和支持的操作系统版本确定，但必须满足：

- 密钥不以明文写入普通配置文件、项目文件、日志、提示词、遥测或错误信息。
- 应用仅在发起请求时从安全存储读取密钥，并尽量缩短明文驻留时间。
- UI 默认掩码显示，禁止通过普通日志或诊断导出回显。
- 支持更新、轮换和删除密钥；删除连接时提供是否同时删除凭据的明确行为。
- 导出/导入连接配置时不包含密钥，只导出非敏感元数据；导入后用户重新提供密钥。

### 7.2 本地配置分离

建议将连接配置与凭据分开：

- 普通本地设置：Provider Type、Endpoint、Model ID、连接名称、默认连接标记、能力快照和测试状态。
- OS Secure Storage：API Key / Token 等秘密。
- 项目数据：不保存供应商密钥；项目可引用用户本机默认模型设置，但不应把凭据嵌入项目包或分享文件。

### 7.3 日志与诊断

日志可以记录 request ID、连接 ID、适配器版本、模型 ID、耗时、usage、错误类别和重试次数；默认不记录完整提示词、完整地图上下文、密钥或供应商响应中的敏感内容。用户主动提交诊断包时，应预览包含的数据并允许排除对话内容。

## 8. Endpoint 与网络请求安全

用户配置自定义 Endpoint 是高风险边界，不能允许模型或生成内容自行指定目标地址。

- Endpoint 只能来自用户设置或受信任的内置供应商配置，模型输出不得修改它。
- 仅允许明确支持的 HTTPS 端点；本地模型端点若未来支持，应作为单独明确配置类型和安全策略，不与任意远程 URL 混为一谈。
- 校验 URL scheme、主机名、端口和重定向目标；禁止向 loopback、link-local、私有网络、云元数据地址等敏感目标发起非预期请求，除非用户明确配置受支持的本地服务模式。
- 限制重定向次数，并对每次重定向重新执行目标校验；不得将 Authorization/API Key 转发到不同 origin。
- DNS 解析和连接目标需防范 DNS rebinding / SSRF；连接建立时校验实际目标地址。
- 限制响应体大小、连接超时、读取超时和并发请求数。
- 连接测试不得执行工具调用，不得携带地图或项目上下文。
- 不接受模型返回的 URL 作为工具执行目标；需要联网检索时应走 World View 明确提供的受控能力（若产品未来支持）。

## 9. 上下文与数据传输控制

### 9.1 最小必要上下文

Context Builder 根据当前用户任务生成上下文，不默认把整个地图、全部世界设定、全部历史、所有本机文件发给供应商。

可按任务需要选择：

- 用户当前指令；
- 当前地图的基础描述和坐标/投影语义；
- 当前视口或选中对象的必要属性与几何摘要；
- 相关图层、对象关系和样式信息；
- 与任务直接相关的世界设定片段；
- 用户明确选定的参考资料或图片；
- 完成当前步骤所需的工具定义和校验结果。

默认排除无关地图区域、无关对象、完整历史记录、未选中的本机文件和密钥。对复杂任务可以分阶段检索上下文，每一步只取必要内容。

### 9.2 透明提示

在首次启用云端模型前，清楚说明：

- 请求会发送到用户选择的供应商；
- 可能发送的内容类别（例如用户指令、选中对象信息、相关地图片段或用户选中的参考资料）；
- 供应商可能按其政策处理或留存请求；
- 模型费用和额度由用户与供应商之间的关系决定。

当任务涉及明显敏感或大范围数据时，应提供可理解的发送范围提示，并允许用户缩小范围或取消。不得把“使用 AI”解释为默认同意上传全部本机项目。

## 10. 请求生命周期、错误与恢复

统一请求生命周期建议为：

`created → preparing_context → sending → streaming/receiving → tool_decision → completed`

可终止状态包括 `cancelled`、`timed_out`、`failed` 和 `interrupted`。该请求生命周期是模型调用内部状态，不等同于地图生成 Session 状态或正式地图历史状态。

错误类别至少包括：

- `authentication_failed`：密钥无效、过期或权限不足；提示用户检查凭据。
- `connection_failed`：DNS、TLS、网络或端点不可达；保留用户输入，不声称任务已完成。
- `rate_limited`：供应商限流；遵循 Retry-After（如有），有限次退避重试。
- `quota_or_billing`：额度或账单限制；提示用户在供应商侧检查，不自动切换到收费未知的模型。
- `model_unavailable`：模型 ID 错误、下线或不可用；允许用户修改模型配置。
- `capability_unsupported`：模型不支持当前所需工具调用、视觉或结构化输出；提供可行降级或明确阻断。
- `invalid_response`：输出无法解析或违反 Schema；有限次修复重试，仍失败则停止并展示原因。
- `context_too_large`：上下文超限；缩小范围或分阶段处理，不静默丢弃关键约束。
- `provider_error`：其他供应商错误；保留安全的错误摘要和 request ID。
- `cancelled` / `timed_out`：停止本机等待和后续步骤；说明远端是否可能仍在处理无法由 World View 保证。

重试原则：只对可重试错误进行有限次数重试；采用退避和总时限；非幂等工具调用不能因模型请求重试而重复执行。模型请求重试与 Domain Service 操作重试必须分离。

## 11. 模型费用、预算与使用控制

World View 不承担供应商费用，也不承诺供应商返回的 usage 或价格完全准确。

V1 建议提供轻量控制：

- 展示供应商提供的 token usage（如可得）。
- 显示本次任务调用次数和可获得的用量摘要。
- 对超大上下文、长任务或多轮工具调用给出使用提示。
- 允许用户设置本机侧单次任务最大模型调用轮数、最大输出 token（在模型支持时）和请求超时。
- 默认限制自动重试和连续调用次数；超过上限时暂停并说明原因。
- 不在 V1 承诺统一货币成本估算，因为各供应商价格、缓存、工具和多模态计费规则变化频繁。

费用控制的目的在于防止失控调用，而不是替代供应商账单。

## 12. 无模型连接时的降级行为

- 地图编辑器所有非 AI 功能继续可用。
- AI Assistant 显示未配置模型/连接不可用状态，并提供前往设置的入口。
- 不创建伪造的模型结果，不把失败请求标记为成功。
- 用户的任务描述和尚未提交的输入应尽可能保留。
- 若任务执行到一半失败，应准确报告已完成、未完成和已正式应用的部分；不自动回滚已正式应用成果。
- 需要工具调用但模型不支持时，不能把自然语言建议误标记为已执行操作。

## 13. OpenAI API 风格兼容端点的边界

可以评估支持 OpenAI API 风格的自定义端点，以降低接入成本，但“兼容 OpenAI API”不是完整兼容保证。

兼容验证至少检查：

- 认证方式与请求头；
- Chat/Responses 等实际采用的 API 路径和消息结构；
- Tool / function calling 的参数格式、并行调用语义和工具结果回传方式；
- JSON Schema / structured output 的支持程度；
- 流式事件格式及结束标志；
- 图片/多模态输入格式；
- 上下文窗口、最大输出和 token usage 字段；
- 错误响应、限流和重试提示；
- 取消请求和超时行为。

对每个端点/模型维护明确的测试结果。兼容端点若只支持文本对话，可以作为文本模型使用，但不能宣称支持 AI 地图自主工具执行。

## 14. V1 范围与非目标

### V1 纳入

- 用户自带供应商连接；
- 一个默认模型即可完成主要 AI Assistant 工作；
- Provider Adapter 与统一 Model Gateway；
- 连接测试、模型 ID 配置、能力检测/记录；
- 文本调用、工具调用、结构化输出及流式响应（按适配器实际能力启用）；
- OS 安全凭据存储；
- 最小必要上下文和数据传输透明度；
- 超时、取消、有限重试、错误归一化和基本用量展示；
- 模型不可用时非 AI 地图功能继续可用。

### V1 不纳入或不作为前提

- World View 官方托管模型或代付模型费用；
- 强制单一供应商或账号体系；
- 多 Agent 产品模型或外部 Agent Runtime；
- Codex、Claude Code、MCP 或外部 HTTP API 作为核心运行依赖；
- 复杂自动模型路由、多模型投票、自动成本竞价；
- 默认上传整个地图/全部本机资料；
- 未经用户明确配置的任意 Endpoint；
- 本地模型服务作为 V1 必备条件；
- 统一的供应商侧费用保证或账单代理。

## 15. 建议验收标准

1. 未配置 LLM 时，用户仍可创建、编辑、保存、导入和导出地图。
2. 用户配置一个受支持的供应商连接后，AI Assistant 能完成基本文本交互。
3. 连接测试不会发送地图内容，也不会执行工具。
4. 模型返回工具调用时，World View 能验证工具白名单、参数、授权和地图状态，再由 Domain Services 执行。
5. 模型无法直接访问数据库、任意本机文件或任意网络地址。
6. 不支持工具调用的模型不会被标记为具备自主地图操作能力。
7. API Key 不出现在普通配置文件、项目导出、日志、提示词和错误回显中。
8. 云端请求只包含当前任务所需上下文，用户能理解发送内容类别。
9. 连接失败、限流、额度不足、超时、取消和无效响应均有明确反馈，不会伪报成功。
10. 地图在候选生成期间发生变化时，旧候选不会覆盖新状态。
11. 配置导出不包含 API Key；导入后要求用户重新配置凭据。
12. 自定义 Endpoint 的协议、重定向和网络目标经过校验，模型不能改变请求目的地。
