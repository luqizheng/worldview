## 1. 审计结论

P2-01 V0.1 不能直接作为当前 Domain Model
的修订底稿。它仍有可保留的领域概念和纯函数重建基础，但其中若干默认假设已被后续
ADR 或 D01 讨论修正。

本轮可以明确判定：

1.  History 统一实体：已由 ADR-002 冻结，不再是待裁决问题。
2.  Branch 分叉时间窗：ADR-005 冻结为
    `effective_time > parent_at`；D01-71
    又明确了父历史修改影响范围的闭区间语义，需合并表达，不能把二者混为一谈。
3.  Shared / Map-local History：ADR-003
    已确立命令驱动、共同时间演进、单线播放、默认排序与用户调整、警告不阻断等产品规则；具体排序算法、命令结构和异常检测仍未完成。
4.  删除后局部修改：ADR-003 V1.2
    已明确允许命令执行、不自动复活对象、持续警告；P2-01 A12
    的"错误/拒绝"旧规则不再适用。
5.  Branch 动态继承、Command 权威、State Change 派生、Checkpoint
    非权威等边界，必须以 D01-01～143 的后续确认更新 P2-01 V0.1。
6.  Storage 设计审计尚不能完成：目前检索到的资料足以确认 D01 的 Storage
    职责要求，但未找到可作为完整对照依据的独立 Storage Architecture
    原始文件。因此不得宣称已完成 P2-09 的逐项冲突核验。

## 3. 对十项冲突登记的结论

### 3.1 State Change 是否独立持久化

建议修订为：

-   Command 是作者创作历史的唯一权威输入。
-   State Change 是 Command 执行产生的状态变化结果/语义，不与 Command
    并列成为第二套作者历史。
-   World State、Dependency、Checkpoint 均属于可重建结果或派生数据。
-   技术实现可以为了性能、诊断或审计持久化派生结果，但必须能从权威输入重建，并记录生成依据/版本；持久化不提升其权威等级。

**状态：领域语义可确定；具体是否持久化 State Change 留待 Storage
技术设计。**

### 3.2 A12 destroy 后再变更

**状态：已解决。** 以 ADR-003 V1.2 A10-09 和 D01-73 为准，旧 A12
规则被替代。

### 3.3 Branch 重建

**状态：已解决到领域规则层。** 采用动态继承，不复制祖先
Command；分叉点之前的父历史变化按闭区间规则传播；沿继承路径重建，逐层执行后代自有
Command；Checkpoint 只能作为经版本和完整性验证的恢复起点。

### 3.4 持续 Command

D01 已明确暂停期间不消耗行动时间，但 P2-01 原提案并未充分定义持续
Command。建议将"持续 Command 的进度、暂停、恢复、执行依据、结束条件"列入
Command 专题，不要把它混同普通瞬时 State Change。

**状态：方向可确定，领域字段和时间推进规则仍需专项设计。**

### 3.5 Fail-Fast

**状态：已解决。** 以 D01-58～64 为准：遇到第一个无法执行的 Command
即停止后续重建；错误之后的结果不得作为完整有效历史展示；不删除或自动修改后续
Command。

### 3.6 World State 纯函数与缓存

**状态：核心原则保留并已补充。** World State
应由权威历史输入确定性重建；缓存和 Checkpoint 非权威。Checkpoint
的完整状态、版本、完整性、发布、引用和淘汰要求以 D01 为准。

### 3.7 时间模型

**状态：旧 P2-01 表达需替换。** 不能继续以抽象 Calendar tick
作为唯一内部权威时间。应以 D01
时间专题中确认的整数累计天数及当天时间偏移为基础；Calendar Configuration
负责日期解释，历法改革不改写内部时间顺序。

### 3.8 Command / Order Constraint / Calendar Configuration / 派生缓存职责

建议边界：

  ---------------------------------------------------------------------------
  对象                                权威职责
  ----------------------------------- ---------------------------------------
  Command                             作者表达的历史操作/意图，创作历史权威

  Order Constraint                    作者明确指定的 Command
                                      顺序约束，属于正式输入

  Calendar Configuration              日历规则与日期解释配置；历法改革
                                      Command 与配置建立明确关系

  State Change                        Command
                                      执行结果，不是第二套创作历史权威

  Dependency                          执行依赖分析结果，可重建

  World State                         指定
                                      Branch/时间点的完整状态结果，可重建

  Checkpoint                          完整 World State
                                      的持久化派生缓存，非权威
  ---------------------------------------------------------------------------

### 3.9 Branch 版本、活动路径与引用保护

**状态：领域规则已形成，具体算法仍属技术设计。**
继承路径版本需可表达路径各段；祖先变化按分叉边界传播失效；只立即重建活动路径、其他路径按需；被任务引用的
Checkpoint 不得物理删除。

### 3.10 Checkpoint 与批量任务存储

**状态：产品/领域约束已形成，文件布局与持久化结构未定。**
原子发布、完成标记、MD5
校验、单机关闭安全停止、轻量级任务记录、启动时检查等均需进入 Storage
Architecture 设计。

## 4. 重要的旧提案误区与修订红线

1.  不得将 State Change 与 Command 并列作为两套权威历史。
2.  不得将 Branch 表达为创建时的静态快照。
3.  不得将 `effective_time > parent_at`
    的自有变更约束误解为父历史继承只采用开区间；D01-71
    的父历史继承边界是闭区间。
4.  不得把 Checkpoint 当作历史权威或 Branch 自有增量片段。
5.  不得把 Shared/Local History 写成固定优先级覆盖或多结果合成。
6.  不得将对象生命周期异常统一硬拒绝；删除后局部修改已有明确执行/不复活/警告规则。
7.  不得将 ADR-002 错误引用为 Shared/Local 合成顺序裁决；相关产品语义由
    ADR-003 确认。
8.  不得把 ADR-004 的批量修复 Undo/Redo 扩展为通用 Command Undo/Redo。
9.  不得把旧 P2-01 中的"建议/默认项"误标为已冻结裁决。
10. 不得因本审计报告生成而修改或覆盖任何现有 ADR。

## 6. 推荐修订顺序

1.  修订 P2-01 V0.1 的领域概念与权威边界：Command、State
    Change、History、Event、World State、Branch、Shared Object。
2.  重写 Historical Time / Calendar 章节，按 D01
    的内部累计时间模型统一。
3.  重写 Branch 重建章节，纳入闭区间继承、动态继承路径、祖先 Checkpoint
    复用和 Fail-Fast。
4.  重写 Shared / Local Command 章节，引用 ADR-003，不重复发明排序规则。
5.  增加 Command 顺序约束、持续 Command、警告与异常的领域边界。
6.  将 Storage 内容移出 P2-01，形成独立 Storage Architecture 设计输入。
7.  完成原 Storage 文档与 D01-125～137 编号核验后，再形成 P2-01 Domain
    Model 修订稿。

## 7. 最终判定

**P2-01 V0.1 的概念框架可作为历史参考，不宜直接增补成 V0.2；应以
D01-01～143 和 ADR-001～005 为当前权威输入，重构一份新的 Domain Model
Proposal。**

本报告的审计结论不修改任何源文件。P2-01
新稿仍需单独审查与用户确认；Storage 设计、Phase B 范围、ADR
更新和开发实施均须分别授权。
