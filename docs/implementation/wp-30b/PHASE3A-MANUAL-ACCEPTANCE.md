## 2. UI-01 — 重复点击窗口关闭按钮

**来源：** 用户提供的完整原文，原意保持不变。

### 目的

验证重复关闭请求不会造成重复清理、死锁或窗口卡死，且 C2 项目关闭流程只执行一次。

### 步骤

1. 启动应用。
2. 打开一个包含地图视口的项目工作区。
3. 确认窗口和视口正常显示，准备关闭项目。
4. 在短时间内连续多次点击项目窗口右上角 X（至少连续 3 次；若窗口在第一次请求后立即禁用输入，则记录实际行为，不强求物理点击全部被处理）。
5. 观察关闭过程，等待窗口最终退出。
6. 检查应用日志、窗口状态和进程退出状态。

### 通过标准

- 窗口最终正常关闭，应用不发生明显卡死。
- C2（`CloseProjectLifetimeAsync`）最多执行一次。
- 多次关闭请求共享同一次关闭操作；后续请求不得重复遍历 Binding、重复关闭 ProjectSession 或重复释放 AssetStore/Database。
- Binding 关闭顺序正确：IsClosed → Coordinator/F-1 屏障 → Publisher → Renderer。
- 无重复释放异常、未处理异常或未观察后台任务异常。
- 最终窗口关闭只有一个成功执行者，不发生无限 Closing/Close 重入。

### 失败判定

出现窗口无法关闭、关闭任务永久等待、C2 重复执行、资源重复释放异常或未观察异常，均判失败。

## 3. UI-02 — C2 完成后窗口正常退出

**来源：** 原始 UI-02 截断内容 + ADR-10 R5；后半段及通过标准为本次补充定义。

### 目的

验证窗口关闭等待逻辑：窗口关闭请求不能绕过 C2，也不能在 C2 完成前导致应用消息循环退出。

### 步骤

1. 启动应用并打开一个包含地图视口的项目工作区。
2. 确认至少一个 Viewport Binding 已创建并正常工作。
3. 通过项目窗口右上角 X 发起一次关闭请求。
4. 观察第一次 Closing：本次同步关闭应被取消，窗口在 C2 完成前保持打开。
5. 观察项目关闭过程：所有存活 Binding 先关闭，随后 ProjectSession 关闭，最后清理 ViewModel 集合并触发窗口关闭通知。
6. 等待关闭编排完成，观察窗口再次关闭及应用退出。
7. 再执行一次“关闭项目”命令入口（如果当前 UI 暴露该命令），确认命令入口与窗口入口汇聚到同一个 C2 编排，而不是两套清理逻辑。
8. 检查日志和退出状态。

### 通过标准

- 第一次 Closing 不直接销毁资源，而是取消本次关闭并接入 C2。
- C2 完成前窗口保持打开，应用消息循环不会提前退出。
- 所有存活 Binding 关闭完成后，才开始 ProjectSession.CloseAsync。
- ProjectSession 关闭后才清理 ViewModel 集合并通知窗口退出。
- 编排完成后窗口正常关闭；应用正常退出，无死锁、无永久等待。
- 命令入口与窗口入口使用同一 C2 任务；重复调用等待首次操作，不重复释放资源。
- 即使关闭编排发生异常，异常也被观察，窗口不会永久无法关闭；日志能留下足以定位问题的诊断信息。

### 失败判定

窗口在 C2 完成前消失、消息循环提前退出、会话先于 Binding 关闭、重复执行 C2、异常未观察或窗口永久卡在关闭流程，均判失败。

## 4. UI-03 — Viewport Detach / Reattach 生命周期

**来源：** ADR-10 §1/§3、Phase 3A 实施报告 §3/§6；本次补充定义。

### 目的

验证视觉树暂时脱离不等于视口永久销毁。Detach / Reattach 必须复用同一未关闭 Binding，不得误关闭 Runtime、Coordinator 或 Publisher。

### 步骤

1. 启动应用并打开一个包含地图视口的项目工作区。
2. 记录当前工作区、视口及其 Binding 的诊断标识（若日志未暴露标识，使用可观测的创建/关闭计数或调试日志）。
3. 通过当前 UI 可实现的方式使视口暂时脱离 rooted visual tree，例如切换工作区/标签、切换承载视图或触发宿主视图重建；不得执行关闭工作区命令。
4. 观察 Detach 期间的 Binding、Runtime 与工作区状态。
5. 将同一视口重新挂载到视觉树。
6. 观察视口是否恢复显示，并检查是否创建了新的 Binding 或发生了意外关闭。
7. 重复 Detach / Reattach 至少 3 次。
8. 最后通过正常方式关闭工作区或项目，确认永久关闭仍能正常执行。

### 通过标准

- Detach 不设置 Binding 的 IsClosed，不调用 Binding.CloseAsync / RequestClose，不 Dispose Runtime。
- Detach 不关闭 Workspace，不影响 ProjectSession。
- Reattach 复用同一个未关闭 Binding / Runtime，不创建重复 Binding。
- Reattach 后视口恢复正常显示；有效尺寸恢复后能推进视口代并请求刷新，不以 0 尺寸发起请求。
- 多次 Detach / Reattach 不产生重复订阅、重复资源释放或绘制异常。
- 真正关闭工作区/项目时，Binding 才进入终态并按既定顺序释放。

### 失败判定

Detach 导致 Binding 关闭、Reattach 无法恢复、同一工作区出现重复存活 Binding、Runtime 被提前释放或最终关闭失效，均判失败。

### 环境限制

如果当前 UI 没有可触发视觉树重建/暂时脱离的用户操作，不得用“切换页面”臆测已经覆盖该场景。应通过测试宿主或专用开发验证入口触发真实 Avalonia Detach / Reattach，并保留证据；不得为此临时修改产品生命周期语义。

## 5. UI-04 — macOS 原生窗口关闭与应用退出行为

**来源：** Phase 3A 实施报告 §8 的 macOS 窗口行为未验证项 + ADR-10 R5；本次补充定义。

### 目的

在真实 macOS 桌面环境中验证 Avalonia 原生窗口关闭行为与 C2 生命周期接线一致，补齐 CI 仅构建、不运行 UI 的证据缺口。

### 步骤

1. 在 macOS 实际桌面环境启动应用，不以 Windows 运行结果代替。
2. 打开一个包含地图视口的项目工作区，确认视口正常显示。
3. 使用 macOS 窗口标题栏关闭按钮发起关闭请求。
4. 观察窗口是否在 C2 完成前保持打开，以及关闭完成后是否正常消失。
5. 若应用还有启动窗口，先关闭启动窗口，再关闭项目窗口，专门验证 ProjectWindow 作为最后一个窗口时的退出路径。
6. 再打开项目工作区，重复一次关闭流程；如应用提供“关闭项目”命令，也验证命令关闭后窗口正常退出。
7. 检查应用是否正常退出、是否残留进程、是否出现系统级崩溃报告或生命周期异常日志。

### 通过标准

- macOS 原生标题栏关闭操作能够进入与 Windows 相同的 C2 编排。
- ProjectWindow 是最后一个窗口时，C2 仍在窗口真正关闭前完成；不依赖 Closed 后 fire-and-forget。
- 窗口最终正常关闭，应用正常退出，无残留进程、崩溃、死锁或未观察异常。
- 关闭顺序和幂等行为符合 UI-01 / UI-02。
- 不因 macOS 原生窗口行为而引入独立清理路径或绕过 Binding 关闭。

### 失败判定

最后窗口关闭导致 C2 中断、应用提前退出、窗口无法关闭、进程残留、崩溃或出现平台专属的重复清理问题，均判失败。

**PASS** 只表示该平台该项的真实人工操作通过。CI 通过、单元测试通过或代码审查通过均不能替代真实窗口证据。未执行必须标记 NOT_RUN，不得标记 PASS。

## 7. 非本清单范围

- 本清单不是新增开发任务，不要求为人工验收临时引入 Avalonia.Headless。
- 不把在飞 Render 回调绝对停止作为通过条件。ADR-10 §5 明确允许关闭前已进入的在飞帧自然完成；验收应检查关闭后的新 Render 入口遵守 IsClosed 守卫。
- 不把单工作区 C1 关闭与整个项目 C2 关闭混为一谈。C1 的兄弟工作区隔离已有自动化测试覆盖；如人工操作中发现异常，应另行记录缺陷。
- 不因验收清单补齐而改变 ADR-07 至 ADR-11 的既定架构决策。

## 8. 最终判定

四项全部在其要求的平台上取得真实人工证据并通过，方可将 WP-30B Phase 3A 的桌面窗口 / Viewport Binding 生命周期人工验收标记为 PASS。

UI-02～UI-04 为本次补充定义，后续若发现真正的历史原文，应以来源证据修订本清单，不得将本次补充内容倒称为历史原文。
