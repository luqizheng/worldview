# World View — Map Generation Specification V0.2

- 文档状态：修订版设计基线
- 版本：V0.2
- 日期：2026-11-20
- 范围：内置 AI Assistant 对地图制作意图的结构化理解与约束表达
- 前序版本：V0.1（保留作为历史讨论记录）

## 1. 目的与定位

本文件定义 World View 内置 AI Assistant 如何把用户自然语言中的地图制作目标、限制条件和创作自由度，整理为可执行、可检查、可追溯的任务依据。

Generation Specification（下称 Spec）是 AI Assistant 在复杂地图任务中使用的内部结构化任务描述。它不是用户必须学习或手工填写的表单，也不是每次简单地图编辑都必须创建的独立产品对象。

简单、明确的编辑可以由 AI Assistant 直接理解并调用相应领域能力。对于多步骤、范围较大、约束较多或需要审阅的任务，AI Assistant 应建立或更新结构化 Spec，供计划、执行和验证使用。

Spec 本身不是正式地图数据，不直接改变地图，也不取代 World View 的正式地图领域模型。

## 2. 设计原则

1. 用户明确提出的要求必须可追踪，不能在理解或执行过程中静默丢失。
2. 区分硬约束、软约束、创作自由度、排除项和保护项。
3. 区分用户明确提供、现有地图、用户资料、AI 推断和 AI 创作等信息来源。
4. 不确定信息必须显式表示，不能伪装成确定事实。
5. 规格应可版本化、可比较，并能说明变更影响。
6. 不因引入 Spec 而增加普通用户的操作负担。
7. Spec 变更不能自动回滚已经正式应用的地图内容。
8. Spec 必须服从当前地图、Branch、时间和正式世界设定的有效性规则。

## 3. Spec 主要内容

根据任务需要，Spec 可包含：

| 部分 | 内容 |
|---|---|
| Identity | Spec 标识、版本、所属地图、创建时间和任务关联 |
| Intent | 用户希望完成的目标 |
| Map Context | 当前地图、Branch、地图时间、Map Space、相关对象和图层 |
| Content Scope | 需要创建、修改、删除或检查的对象领域与范围 |
| Constraints | 硬约束、软约束、排除项和保护项 |
| Style Intent | 地图主题、视觉风格和表达偏好 |
| Spatial Scope | 目标区域、范围、逻辑尺度或空间参考 |
| Provenance | 用户输入、现有地图、外部资料、推断和创作标记 |
| Uncertainty | 未确定事项、争议和待核实内容 |
| Acceptance Criteria | 可验证的结果条件 |
| Authorization Context | 当前用户权限、明确授权范围及需确认事项 |

不是每个任务都必须填满所有字段。无关字段应省略，不得为了满足模板而编造信息。

## 4. 约束分类

### 4.1 硬约束（Hard Constraints）

必须满足。若无法满足，AI Assistant 应指出冲突或不可执行原因，不得擅自放宽。

示例：
- 大陆数量必须为三个；
- 国家数量必须为十二个；
- 指定对象不得修改；
- 指定区域不得超出某一范围；
- 必须保留现有河流和城市。

### 4.2 软约束（Soft Constraints）

尽可能满足。发生冲突时可以权衡，但应说明偏离情况。

示例：
- 山脉尽量沿大陆纵向延伸；
- 城市尽量靠近河流；
- 国家面积尽量均衡；
- 道路尽量减少不必要弯折。

### 4.3 创作自由度（Creative Degrees of Freedom）

用户授权 AI 自主决定的部分。自由度不等于允许违反硬约束、正式设定、事实依据或权限边界。

示例：
- 未指定区域的海岸线细节；
- 尚未命名的普通聚落名称（仅在用户允许 AI 命名时）；
- 装饰性地形细节；
- 不影响主要目标的局部布局。

AI 不得把用户未授权的重大世界设定、政治事实或历史事实当作自由创作空间。

### 4.4 排除项与保护项

- **Exclusion**：不得创建或纳入某类内容。
- **Protection**：不得修改、删除或替换指定对象、区域或关系。

保护项优先于普通生成依赖。若目标与保护项冲突，应说明冲突并请求用户处理，不得擅自覆盖。

## 5. 来源与事实性质

重要内容主张可标记为：

- `user_explicit`：用户明确指定；
- `existing_map`：来自当前有效地图状态；
- `source_material`：来自用户提供或经许可使用的资料；
- `external_source`：来自外部公开资料；
- `world_setting`：来自当前有效的正式世界设定；
- `ai_inferred`：AI 根据上下文推导；
- `ai_created`：AI 在用户授权的创作自由度内创作。

真实地理、历史和现实政治等事实性内容，应尽可能记录来源引用、来源日期、适用时间和空间范围、核验状态。没有可靠依据的内容不得标为已核实事实。

虚构世界内容以当前有效的正式世界设定为主要一致性依据。AI 新提出的设定默认属于候选，不自动成为正式设定。

## 6. 规格解析流程

对复杂任务，AI Assistant 按需执行：

1. 接收自然语言请求和当前地图上下文；
2. 识别目标对象、操作类型、数量、位置、关系、样式和范围；
3. 提取硬约束、软约束、排除项、保护项和创作自由度；
4. 标记信息来源、事实性质和不确定性；
5. 检查内部矛盾、缺失条件、权限和不可执行要求；
6. 对影响结果的重大歧义请求澄清；非关键细节可在明确授权范围内自主决定；
7. 为复杂任务形成内部 Spec 草案；
8. 根据风险和授权规则决定是否需要用户确认，然后进入任务计划与执行。

Spec 草案不意味着必须让用户逐字段批准。AI 应以自然语言摘要呈现重要约束和需要用户决策的事项。

## 7. 规格变更与版本

- Spec 每次实质性修改产生新版本，不覆盖已被任务引用的历史版本。
- 记录修改原因、差异和时间。
- AI Assistant 应识别变更影响的计划步骤、候选结果和验收条件。
- 已经正式写入地图的内容不会因 Spec 修改而自动回滚。
- 重新生成或修改既有内容必须明确变更范围，并遵守保护项和当前地图状态。
- 若地图基准状态变化，执行前重新检查 Spec 中引用的对象和空间条件是否仍有效。

## 8. 验收条件

Acceptance Criteria 应尽量可检查：

- 数量、类型和范围等由系统验证；
- 几何有效性由几何/拓扑领域服务验证；
- 语义关系由领域规则验证；
- 视觉质量可由模型辅助评价，并允许用户检查；
- 史实正确性依赖可靠资料核验，不能只依赖模型自评；
- 虚构内容检查是否符合当前正式世界设定；
- 保护对象不得发生未授权变化。

## 9. 与其他领域的边界

- Spec 表达任务意图，不是 Map Object。
- Spec 不负责正式对象 ID 分配。
- Spec 不代替 Generation Task 的执行状态。
- Spec 不代替 Candidate 或 Change Set 的具体变更内容。
- Spec 不代替正式世界设定，也不自动确认新的世界设定。
- 正式地图写入必须经 World View Domain Services。
