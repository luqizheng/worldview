# World View — Map Generation Workflow V0.2

- 文档状态：修订版设计基线
- 版本：V0.2
- 日期：2026-11-20
- 范围：内置 AI Assistant 的地图制作任务规划、执行、验证与应用工作流
- 前序版本：V0.1（保留作为历史讨论记录）

## 1. 目标与定位

本文件定义 World View 内置 AI Assistant 如何将用户的地图制作请求转化为可执行工作，并将结果安全地落实到正式地图。

地图制作工作流由一个对用户统一呈现的 AI Assistant 负责。AI Assistant 可以在后台分阶段处理任务、调用模型、运行确定性算法，并对互不依赖的步骤进行受控并行；但不要求外部 Agent、Codex、Claude Code、MCP 或多 Agent 系统成为运行前提。

本工作流是产品和逻辑流程，不要求每个阶段都成为独立微服务或用户可见页面。

## 2. 核心原则

1. 以用户任务为单位组织工作，不把工具调用作为主要用户交互。
2. 简单明确的任务可直接执行，不必强制创建完整 Spec、Plan、Candidate 和 Change Set。
3. 复杂多步骤任务应按需形成结构化任务依据和计划。
4. AI Assistant 对用户承担统一的理解、计划、执行和结果解释职责。
5. 正式地图操作经 World View 内部工具/API 和 Domain Services。
6. LLM 不直接写数据库；候选结果不能绕过领域验证。
7. 根据操作风险决定自动执行、预览或用户确认，不默认要求每次变更都人工批准。
8. 失败、取消和部分完成应可解释、可恢复，并保护正式地图数据。

## 3. 总体工作流

```text
User Request
    -> Intent and Context Understanding
    -> (If needed) Structured Task Specification
    -> Plan (for multi-step / complex tasks)
    -> Execute through Internal Tools and Domain Services
    -> Validate
    -> Risk / Authorization Decision
       -> Apply directly when authorized and low-risk
       -> Preview and request confirmation when required
    -> Report Results
```

各阶段可根据任务复杂度合并或跳过。简单编辑不应被强制转换为繁重的生成会话流程。

### 3.1 简单任务

例如“把选中的河流改成蓝色”：

1. 解析当前选中对象和用户意图；
2. 检查权限与对象状态；
3. 调用样式领域服务；
4. 检查结果并反馈。

无需展示完整计划或要求用户批准低风险、明确且可逆的操作。

### 3.2 复杂任务

例如“为这片大陆制作完整的自然地理和十二个国家，并建立主要城市与道路”：

1. 解析意图、地图上下文和约束；
2. 按需建立内部 Spec；
3. 生成简明计划并向用户展示主要阶段；
4. 按依赖执行任务；
5. 形成候选内容并进行结构、几何、空间、语义和内容检查；
6. 根据影响范围形成预览或分组变更；
7. 对重要设定、删除、保护项冲突或高影响操作请求用户决策；
8. 经授权后通过领域服务正式应用；
9. 展示完成摘要和未解决事项。

计划展示不等于要求用户逐项批准。只有确有必要的决策才构成人工关口。

## 4. 计划与分阶段执行

### 4.1 计划输入

AI Assistant 根据需要使用：

- 用户目标和约束；
- 当前地图、Branch、时间和对象上下文；
- 目标区域与空间范围；
- 保护对象和排除项；
- 地图领域规则与空间约束；
- 可用内部工具和确定性算法能力；
- 权限、授权范围和风险策略；
- 可用模型、预算和资源限制。

### 4.2 计划内容

多步骤计划至少说明：

- 主要阶段和任务；
- 任务输入与预期输出；
- 前置依赖；
- 可并行步骤；
- 约束和保护范围；
- 验收条件；
- 失败处理和恢复方式。

计划应保持可理解、可审阅和可追溯。计划更新不能默默改变用户明确提出的硬约束。

### 4.3 推荐生成顺序

按任务需要采用以下依赖顺序：

1. **空间框架**：Map Space、坐标模式、整体范围、区域划分和空间锚点；
2. **自然地理**：大陆、岛屿、海岸线、山脉、河流、湖泊、森林和沙漠；
3. **政治区域**：国家、王国、领土及边界；
4. **人类聚落**：城市、村庄、城堡和港口；
5. **交通网络**：道路、桥梁、渡口和其他连接网络；
6. **制图表现**：标签、符号、主题样式、图例和装饰元素。

这不是所有地图都必须机械执行的流水线。AI 应根据用户目标、现有地图内容和任务依赖裁剪、合并或调整阶段。

## 5. 任务执行与内部能力调用

AI Assistant 是用户可见的统一助手。后台任务执行是其内部实现机制，不向用户暴露多个 Agent 的组织结构。

AI Assistant 通过 World View 内部工具/API 调用：

- 地图对象与几何服务；
- 图层、样式、标签和符号服务；
- 几何运算与拓扑服务；
- 世界设定服务；
- 历史、State Change、Branch 和 Checkpoint 服务；
- Layout 与导出服务；
- 验证和质量检查服务。

对于模型生成的内容，应先形成受控候选或结构化操作输入，再交由 Domain Services 校验和应用。确定性操作尽可能由领域算法完成，不应要求 LLM 自行模拟几何布尔运算或数据库事务。

后台可对独立任务受控并行。并发、预算和速率限制由系统执行；并行不能破坏任务依赖、对象状态或授权边界。

## 6. 候选内容与验证

### 6.1 候选内容

复杂生成任务可产生 Candidate。Candidate 是尚未正式应用的候选对象、几何、属性、样式或关系，使用任务内临时标识，不等同于正式 Map Object。

简单、明确、低风险的编辑可以直接调用领域服务，不必为了形式完整而建立 Candidate。

### 6.2 Generator 输出建议

如采用专门生成步骤，其输出应包含：

- 候选对象类型和临时标识；
- 几何数据及几何类型；
- 对象属性与来源标记；
- 预期图层和样式建议；
- 对象关系候选；
- 生成依据、假设和不确定项；
- 所属任务和 Spec 版本引用。

正式对象身份由 World View 在正式应用阶段分配或确认。

### 6.3 Validator 检查范围

至少包括：

**结构校验**
- 输入输出结构是否符合接口契约；
- 必需字段是否存在；
- 对象类型与几何类型是否匹配。

**几何校验**
- 几何是否有效；
- Polygon 是否闭合且孔洞合法；
- 是否存在不允许的自相交；
- 坐标是否符合当前空间模式；
- 原生直线和贝塞尔控制点数据是否保留。

**空间与拓扑校验**
- 不允许的重叠或空隙；
- 边界相交和邻接规则；
- 共享边界一致性；
- 点、线、区域之间的空间约束。

**语义校验**
- 关系目标是否存在；
- 关系类型是否允许；
- 对象归属是否符合领域规则；
- 不把几何重合自动解释为语义关系。

**任务验收**
- 硬约束必须满足；
- 软约束给出满足程度和偏离说明；
- 保护对象不得发生未授权变化；
- 事实性内容检查来源与核验状态；
- 虚构内容检查与正式世界设定的一致性。

## 7. 预览、Change Set 与用户确认

### 7.1 何时需要预览

对于复杂批量生成、重大几何变化、删除、共享边界修改、正式设定变更或其他高影响操作，应提供预览或清晰的影响摘要。

普通、明确、低风险且已授权的操作可以直接应用，不应把“每次人工批准”设为默认前提。

### 7.2 Change Set

当需要预览或分组批准时，Change Set 可表达：

- 新增对象；
- 修改对象；
- 删除对象及原因；
- 新增、修改或解除的关系；
- 图层和样式变化；
- 受影响的既有对象；
- 校验问题和未解决冲突。

用户可以按区域、对象类型和操作类型查看差异。若变更单元相互独立，可允许部分接受或拒绝。

### 7.3 确认规则

- 用户确认应绑定具体变更内容和版本；
- Change Set 实质变化后，旧确认不得自动沿用；
- 正式世界设定变更按设定领域规则确认；
- 共享边界和高影响拓扑变化应说明受影响对象；
- 普通低风险操作按授权策略自动执行；
- AI 不得把用户对任务目标的同意，扩大解释为对所有未披露高影响变更的同意。

## 8. 正式应用

正式应用必须经 World View Domain Services：

1. 重新检查用户权限和授权范围；
2. 检查目标对象当前状态和基准状态；
3. 检查几何、拓扑、语义和历史规则；
4. 识别预览后发生的并发变化；
5. 对无法安全处理的冲突阻止应用并要求重新预览或人工处理；
6. 以幂等和一致性保护执行正式操作；
7. 记录结果和必要审计关联。

正式写入遵循 World View 的 Command、State Change、Branch 和 Checkpoint 机制。不得另建与正式历史平行的地图状态系统。

## 9. 失败、取消与恢复

- 失败时保留仍然有效的候选和任务上下文，不污染正式地图；
- 可重试操作应具备幂等键或等效去重机制；
- 用户取消后停止未开始的步骤，并在安全边界终止执行中的步骤；
- 部分阶段完成时允许从有效检查点继续；
- 地图上下文、对象状态或 Spec 变化后，重新评估受影响步骤；
- 已正式应用的成果不会因任务取消而自动撤销；
- 需要撤销已应用成果时，使用地图编辑器 Undo/Redo 或相应正式领域操作。

## 10. 进度与用户反馈

进度面向用户展示主要步骤状态：待执行、执行中、已完成、受阻、跳过或失败。

只有存在可信工作量估算时才显示百分比。AI 应说明当前工作、已完成内容、异常和待用户处理事项。

任务完成摘要至少包括创建、修改和删除内容，重要影响、质量检查、来源与不确定性，以及尚未解决的问题。

## 11. 状态概念

任务状态可包括：

`queued / ready / running / paused / blocked / succeeded / partially_completed / failed / cancelled / stale`

这些是建议状态概念，不是已经冻结的枚举。Session、Plan、Task 和正式应用结果应区分状态，不应把“生成完成”等同于“正式写入成功”。
