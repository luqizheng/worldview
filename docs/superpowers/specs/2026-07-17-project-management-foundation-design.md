# 项目管理基础功能设计规格

> 日期：2026-07-17  
> 状态：待书面规格审阅  
> 范围：Godot 4.7.2 mono + C# 的非 UI 项目管理与数据安全能力

## 1. 背景与目标

现有仓库已有 `ProjectLoader`、`ProjectSaver`、`World`、`MapDoc`、`LayerDoc` 及校验器，但缺少统一工程会话、最近项目、脏状态、自动保存、备份与恢复服务。

本设计在不修改任何 UI 场景或 UI 脚本的前提下，补齐以下基础能力：

1. 新建、打开、关闭和跨工程切换的领域/存储流程；
2. 工程内地图切换与新增地图；
3. 未保存状态追踪及结构化关闭决策；
4. 延迟 30 秒、合并触发的基础自动保存；
5. 命名快照与最近 10 份自动轮换备份；
6. 备份完整性校验与非破坏式恢复；
7. 最近工程登记；
8. 统一的临时文件、刷新、校验、原子替换写入流程。

成功标准：后续 UI 只需调用服务接口，不需要直接处理文件系统、备份目录或未保存提示流程。

## 2. 范围外事项

本轮明确不包含：

- 项目中心、ProjectChrome、FileDialog、确认弹窗等任何 UI 修改；
- 自动启动或自动打开最近工程；
- 第三方插件、多人协作、IF 线或并行世界；
- 完整工程重构或替换现有 `ProjectLoader` / `ProjectSaver`；
- 超出当前已支持地图能力的地图类型扩展；
- 恢复点选择界面。

## 3. 设计原则

- 保持领域层不依赖 `Godot.*`；
- UI、存储、调度职责分离；
- 不以自动保存或恢复掩盖手动保存；
- 写操作必须可检测中断并避免半文件；
- 恢复失败不破坏当前工程；
- 服务结果结构化，不依赖弹窗或日志才能判断结果；
- 沿用现有 YAML 数据契约；应用私有索引不写入工程版本库。

## 4. 组件边界

### 4.1 `ProjectSession`

职责：保存当前工程会话状态。

必要状态：

- `ProjectRoot`
- `World`
- `Maps`
- `Layers`
- `CurrentMapId`
- `IsOpen`
- 脏状态服务引用

行为：只维护内存会话，不执行磁盘写入，不通知 UI。关闭成功后重置为未打开状态。

### 4.2 `ProjectService`

提供以下领域操作：

- `CreateProject(rootPath, displayName?)`
- `OpenProject(rootPath)`
- `CloseProject(ProjectCloseDecision)`
- `SwitchMap(mapId)`
- `AddMap(mapType, mapName, usageTags?)`

强约束：

- 创建与打开采用事务式会话替换：失败时当前会话不变；
- `OpenProject` 先校验工程，再加载会话，最后登记最近工程；
- `SwitchMap` 只修改会话级 `CurrentMapId`；
- 新增地图生成稳定 ID、地图文件与必要默认图层；
- `CloseProject` 只执行调用方明确提供的决策。

### 4.3 `DirtyStateService`

提供：

- `MarkDirty()`
- `MarkClean()`
- `HasUnsavedChanges`
- `PrepareClose()`

关闭决策枚举：

```csharp
public enum ProjectCloseDecision
{
    SaveAndClose,
    CloseWithoutSaving,
    Cancel,
}
```

`PrepareClose()` 仅返回结构化决策需求，不创建窗口。UI 后续负责询问用户。

### 4.4 `AutosaveService`

默认配置：延迟 30 秒、合并重复任务。

规则：

- 每次 `MarkDirty` 将截止时间延后 30 秒；
- 截止前再次修改不得产生并发保存任务；
- 保存成功后清空脏状态并记录保存时间；
- 保存失败保留脏状态，并返回错误；
- 支持立即保存，供关闭或切换工程前调用；
- 使用可注入时间源和保存委托，避免服务内部直接依赖 UI 定时器。

### 4.5 `BackupService`

备份分为：

1. 命名快照：名称唯一，默认不覆盖；
2. 打开前轮换备份：自动命名，仅保留最近 10 份。

规则：

- 备份清单保存备份类型、显示名称、创建时间和工程标识；
- 轮换按创建时间删除最旧记录及对应内容；
- 备份失败不阻止打开原工程，但向调用方返回警告；
- 命名快照冲突返回明确错误；
- 备份内容必须排除应用私有运行目录，避免递归复制自身。

### 4.6 `RecoveryService`

提供：

- 列出可用备份；
- 校验备份完整性；
- 将备份恢复为当前工程；
- 从备份内容生成副本或恢复前保护快照。

恢复流程：验证备份 → 创建保护性快照 → 写入暂存目录 → 校验 → 原子替换工程内容 → 重新加载。任何阶段失败均保留原工程可加载状态。

本轮不实现恢复确认 UI，调用方直接传入明确恢复请求。

### 4.7 `RecentProjectService`

路径：应用私有 `.worldview/recent_projects.yaml`。

每条记录仅包含：

- `project_root`
- `display_name`
- `last_opened_at`

规则：

- 最近项目最多 10 项；
- 仅在工程成功加载并建立会话后登记；
- `display_name` 为首次登记快照，不实时读取；
- 重新打开同一路径时刷新路径与打开时间；
- 路径不存在或 `project.yaml` 缺失时标记失效，不自动删除；
- 配置文件损坏时返回错误并使用空清单，禁止覆盖原损坏文件。

### 4.8 `ProjectWriteCoordinator`

统一执行安全写入：

1. 在目标同目录创建临时文件；
2. 写入并刷新持久缓冲区；
3. 从临时文件重新读取并验证；
4. 使用同卷原子替换目标；
5. 失败时清理临时文件并返回原始错误。

多文件工程保存无法仅靠单文件替换实现事务，因此采用“快照恢复”策略：先写暂存工程，校验成功后替换目标；替换中断时使用保护性快照回滚。

## 5. 主要流程

### 5.1 新建工程

1. 验证目标目录为空或不存在；
2. 写入 `project.yaml`；
3. 创建 `maps/` 与第一张最小合法世界地图；
4. 重新加载并校验；
5. 成功后建立会话；
6. 登记最近工程。

任一步失败时清理本轮创建的内容；若目标目录原本非空则不删除用户文件。

### 5.2 打开工程

1. 规范化绝对路径；
2. 验证目录与 `project.yaml`；
3. 尝试创建打开前轮换备份，失败记为警告；
4. 调用 `ProjectLoader.Load`；
5. 有阻断校验错误则拒绝建立会话；
6. 成功后替换当前会话；
7. 登记最近工程并刷新 `last_opened_at`。

若当前会话已有未保存改动，打开流程必须先经过 `PrepareClose`；`Cancel` 时不执行磁盘动作。

### 5.3 关闭工程

- `Cancel`：会话不变；
- `CloseWithoutSaving`：取消自动保存任务并关闭会话；
- `SaveAndClose`：立即保存成功后才关闭；
- 保存失败：保持会话打开并返回错误。

### 5.4 自动保存

编辑调用 `MarkDirty()` 后启动或延后自动保存。自动保存写入工程内容，成功后清空脏状态。自动保存不是用户明确保存，不刷新最近工程时间。

### 5.5 新增与切换地图

新增地图生成稳定 ID，写入 `maps/`，同步工程索引和会话集合，并将新地图设为当前地图。切换地图前执行地图级未保存保存策略；找不到目标地图时不改变当前地图。

### 5.6 恢复

恢复接口接收工程根和备份标识。恢复前必须创建保护性快照；恢复完成后重新加载并校验。恢复结果包含恢复文件数、警告和新校验结果。

## 6. 数据契约调整

### 6.1 `project.yaml`

现有规格要求最低字段：

- `kind: world_view_project`
- `schema_version`

本轮需要把二者正式登记到《数据模型规格》，并补充当前实现已经使用的工程级显示名和地图索引字段。修改数据契约时按仓库纪律升版本，不静默改变字段语义。

### 6.2 最近项目清单

```yaml
schema_version: 1
projects:
  - project_root: "D:/Worlds/MyWorld"
    display_name: "MyWorld"
    last_opened_at: "2026-07-17T10:00:00Z"
```

路径以 YAML 字符串保存；读取后由文件系统 API 规范化，不把 Windows 路径规则写进工程数据格式。

### 6.3 备份清单

备份清单属于应用私有数据，记录：

- `schema_version`
- `backup_id`
- `kind`：`named_snapshot | pre_open_rotation`
- `display_name`
- `created_at`
- `source_project_id`
- `content_root`

`source_project_id` 用于避免把其他工程的备份恢复到当前工程。

## 7. 错误模型

统一使用非 UI 的结果对象，至少区分：

- `InvalidProject`
- `ProjectAlreadyOpen`
- `ProjectHasUnsavedChanges`
- `MapNotFound`
- `SaveFailed`
- `BackupFailed`
- `RecoveryFailed`
- `RecentProjectsCorrupted`

错误包含稳定错误码、可读信息、异常路径或引用（脱敏后由 UI 展示）。服务不吞异常，但也不把底层异常直接暴露为调用契约。

## 8. 并发与一致性

- 一个会话只允许一个正式保存任务；
- 自动保存、手动保存和恢复通过写协调器串行化；
- 保存期间产生的新修改不得被旧保存结果错误标记为 clean；
- 写入成功后再次比较脏状态版本号，版本不一致则保持 dirty；
- 服务不自动终止 Godot 进程，不依赖外部进程状态。

## 9. 测试设计

### 9.1 单元测试

- 新建最小工程可重新加载；
- 非空目录不会被覆盖；
- 地图切换与新增地图状态正确；
- 脏状态与关闭决策正确；
- 30 秒延迟内重复修改只保存一次；
- 保存失败保持 dirty；
- 最近项目新增、更新、去重、上限与损坏恢复；
- 命名快照冲突；
- 轮换备份只保留 10 份；
- 恢复前创建保护快照；
- 恢复失败不破坏原工程。

### 9.2 集成测试

- 使用临时目录完成完整新建→编辑→自动保存→重开；
- 最近工程写入后可在新服务实例中读取；
- 备份→修改→恢复→重开；
- 保存过程中发生写入失败时工程仍可加载；
- 示例工程 `examples/sample_world/` 能通过打开服务校验。

### 9.3 验收边界

不修改 UI 文件；测试直接调用服务和领域接口。Godot 仅用于构建与无头校验，不做视觉验收。

## 10. 实施顺序

1. 正式收敛数据契约与路径规则；
2. 建立结果、错误与写协调器；
3. 扩展工程创建、地图创建与新会话加载；
4. 实现脏状态和自动保存；
5. 实现最近项目；
6. 实现备份与恢复；
7. 接入现有 `EditorController` 的非 UI 生命周期；
8. 完成单元、集成与 Godot 无头校验。

## 11. 风险与处理

- 现有 `ProjectLoader` 与《项目管理规格》对地图索引方式存在差异：以《数据模型规格》和《存储与目录规范》为真源，先修正契约与实现映射；
- 多文件保存不是天然事务：使用暂存工程、校验、保护快照和回滚；
- 备份与自动保存可能写同一文件：统一串行化写入口；
- 工程名可能变化：最近工程显示名固定为首次登记快照，路径是身份键；
- 恢复属于破坏性动作：本轮虽无 UI，但 API 必须要求明确备份标识，并在执行前保护原工程。

## 12. 未来 UI 接入契约

后续 UI 只需：

- 调用 `ProjectService` 执行工程动作；
- 根据 `PrepareClose()` 的结果弹窗并回传决策；
- 调用 `RecentProjectService.List()` 渲染最近工程；
- 调用 `RecoveryService.List()` 渲染恢复列表；
- 订阅结构化状态变化，而非轮询私有字段。

本轮不定义具体控件布局和视觉样式。
