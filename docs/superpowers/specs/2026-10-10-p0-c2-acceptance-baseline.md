# P0-C2 验收基线固化 — 设计规格（轻档）

> 档位：**轻档**（不改 `scripts/` / `scenes/` / `crates/` / `tests/`，纯文档与基线采集）。
> 上位定义：《长期执行计划 v0.1》§5 `P0-C2` 行；流程约束见该文件 §0.3 / §0.4 / §0.6 / §0.7。

> 执行台账：`.superpowers/sdd/2026-10-10-p0-c2-acceptance-baseline/`

## 目标

产出 `docs/acceptance/baseline_v0.1.md`，把当前工程的**基线状态**固化为可对照的真源，使《长期执行计划》§0.5 的 B1–B4 自检从「凭印象」变为「有数可对」：

1. **B1 基线**：`dotnet build` 的 error 数（应为 0）与 warning 总数、按 CS 编号分组的清单。
2. **B2 基线**：测试总数 / 通过数 / 失败数，以及全部失败测试的逐条定性与归属。
3. **B3 / B4 口径**：命令原文与通过判据（照抄 §0.5，含 `--quit-after 120` 与产物不提交约定）。
4. **口径说明**：历史计数（184/20、318/344、19 条转绿等）作废声明——仅本次实测口径有效。

## 非目标

- **不修任何测试、不改任何源码**。§6.4 已定性的 7 条失败，其修复属独立工作项，排在本项之后。
- 不做性能基准（那是 `W-M2-3` / `W-M7-3` 的范围）。
- 不重建 CI 流程（本仓无 CI，基线靠会话内自检维持）。

## 不涉及

- 不动 `docs/acceptance/map_editor_mvp_check.md`（该项为 M1 demo 验收记录，与本基线文档并列存在，互不覆盖）。
- 不修改《长期执行计划》§5 之外的状态列（本项回写仅动 `P0-C2` 行与 §12 变更记录）。
- 不改 `.trae/m1-cleanup-manifest.md`（旧栈清理已完成并关闭）。
