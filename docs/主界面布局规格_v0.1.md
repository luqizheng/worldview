## 0.3 第 3 轮裁定：采纳「底部 = 工具 / 浮动 = 对象属性」分层模型（2026-10-10）

用户提出新的分层心智模型，两位总监评审后**一致建议采纳**（游有方「有条件采纳」／柯桥良「有条件可行」）。
**用户已确认采纳**，并同时确认 B2 修订。

### 模型（分类线 = 「动词 vs 名词」）

| 区 | 语义 | 承载 |
|---|---|---|
| **底部（工具）** | 「**我做什么**」——作用于画布的动作 | 一切工具，以**方块**呈现；地形色块、建筑面板**整体留底部**（不删、不镜像） |
| **浮动面板（属性）** | 「**它是什么**」——对象自身的属性 | 选区驱动；支持**多选 → 交集属性 → 批量统一** |

> 对照原 B3「快切／详细」：原模型按**频次/深度**分，用户看不到标签只能死记（= N1）；
> 新模型按**动作/属性**分，用户可自解释（Blender / Unity Inspector / Paradox 详情窗的成熟划法）。

### 关闭项（用户已确认）

| 项 | 关闭理由 |
|---|---|
| **C1** | 底部**全留**（地形色块、建筑面板都是「工具」）→ 无「删/镜像」之争 |
| **C2** | 选工具 + 选类型**同处底部** → 不跨面板，「点 P 却放出上一个建筑」的混淆消失 |
| **C4** | Inspector / 地图设置 / 多地图标签页 / 呈现模式 → 各成**按需浮出的属性面板**，不抢 4 个页签位 |
| **C6** | 人物 / 载具 / 运输任务 → **选区驱动的浮动面板** |

### 架构收益（两位一致判定）

- **H8（双入口同步）真解决**：底部与浮动承载**不同类别**（动作 vs 属性），物理上不重叠 → 非镜像。
- **H6（页签容量）结构性化解**：「4 页签装 9 面板」的伪问题随「属性按需浮出」自动消失。
- **风险平移**：H6 转为「浮动面板可发现性」（由下方 B2 修订化解）。

### B2 修订（用户已确认）

- 属性面板**维持「默认隐藏」**（保 map-first 画布优先）；
- **新增**：① 选中对象后**自动浮出**属性面板；② 顶栏保留**常驻属性入口**。

### 附带条件（两位合并，逐条可核对）

| # | 条件 | 来源 |
|---|---|---|
| **P1** | **多选交互在代码中完全不存在**（`WorldCanvas` 现仅单格 `NotifySelection`，全库无框选/加选）→ 须新建，**最大前置工作量** | 柯桥良 |

### 二、三分模型（K2 升格后的边界规则）

| 类 | 语义 | 归属 | 例子 |
|---|---|---|---|
| **① 工具** | 「我做什么」（作用于画布的动作） | 底部工具方块区 | 地形 / 道路 / 河流笔刷、建筑放置、**城市图标放置**、**区域圈定**、**选择器**、F11 |
| **② 对象上下文面板** | 「它是什么 + 对它做什么」 | 浮动（选区驱动） | 建筑 / 居民 / 载具属性；地图尺寸·分辨率；**动作区**（生成居民、以此为地点登记事件） |
| **③ 登记·流程面板** | 「造一个新的」（多步向导，引用既有对象） | 按需唤出（非选区驱动） | **事件登记**、人物登记、载具登记、运输任务时间预估 |

> **灰色带逐条套三规则**：笔刷半径→①；地图尺寸/分辨率→②；F11→①；事件登记→③。
> **唯一例外**：**图层可见性 → 独立**（`LayerPanel` 走顶栏入口 Ctrl+L）——不改数据（非①）、不描述被选对象（非②），属**视图控制**，不入三分类。

### 三、世界 / 城市分层（前提级修正）

| 层 | 内容 | 用户操作 |
|---|---|---|
| **世界地图** | 地形、道路、河流 + **城市图标**（一城一图标） | 笔刷绘制 + 放图标；**不放建筑** |
| **城市地图** | 建筑。**普通建筑**（居民楼 / 商业楼，对世界层无意义） | **圈定区域 → 自动生长**（类模拟城市）；**允许空区域** |
| **城市地图 · 特殊** | 皇宫、主角家等剧情性建筑 | **手动逐个放置** |

**对 §11 的冲击**：

1. 游有方 v1 草案的步 2「放置建筑」在**世界层不成立**——世界层不放建筑；建筑只在**城市层**。
2. 新增两类工具：世界层**城市图标放置**、城市层**区域圈定（自动生长）**。

## 0.5 架构可行性评估（柯桥良 E1–E4，2026-10-10）

> 针对第 4 轮新增的「**区域自动生长**」与「**选择器**」两项，技术架构总监给出评估。**总结论：均可做，且确定性基建已存在。**

### E1 · 自动生长可复现 —— ✅ 基建已存在，不是新风险

| 事实 | 证据 |
|---|---|
| 确定性 PRNG 已实现（splitmix64，注释「禁用 .NET 自带随机源」） | `DeterministicRandom.cs:18` |
| 生成器保证「同输入 → 位级相同」 | `WorldGenerator.cs:31-32`（测试 `SameSeed_ProducesIdenticalCells` 锁住） |
| 算法版本号已内置（保旧种子可复现） | `GenerationSpec.Algorithm`（`MapDoc.cs:13`，默认 `coastline_v1`） |
| 参数范围校验已实现 | `GenerationLimits.cs:15-22` |

**推荐「种子 + 结果双存」**（镜像世界生成既有做法）：`ZoneSpec`（几何 + 参数 + 种子）入实体，**同时**物化建筑。

- **非破坏编辑**：生长 = 显式命令 + 可撤销；加载**不重算**，手动编辑不被覆盖。
- **可复现**：种子在手，可随时「重新生成」（作为**显式破坏性命令**走撤销栈）。

> 🔴 **红线：绝不在加载路径上无条件重算生长**——否则用户对生长建筑的编辑会被静默覆盖，直接违反「非破坏编辑」。

**与时间轴**：MVP **不冲突**（生长是空间结构，非时间态；回放态只读）。远期观察点：若「城市随时代生长」成为时间轴语义，二者会耦合。
**与 UndoStack**：一次「区域生长」= **1 个撤销单位**；`BeginBatch/EndBatch` 已够（`UndoStack.cs:76/90`）。**推荐专用 `GrowZoneCommand`**（重做时不重跑生成，确定性风险面更小）。

### E2 · Zone 实体 —— 🟡 真缺口，但只需「加字段 / 加类」

> **⚠️ 锚点更正（主理人任务书错误）**：本仓库**不存在 `WireJson.cs`**（全库检索零命中）——序列化 / ACL 层实为 **`scripts/Storage/Yaml/YamlSchemas.cs`**（+ Loader / Saver）。主理人派单时误引了**另一项目**（ShadowEmpire sim）的 ACL 文件名，此处更正。

### 11.3 「选择器」落位（对应 Q1 / Q2）

| 选择器 | 选择域 | 可批量改 | 归位 |
|---|---|---|---|
| **地形选择器** | 地形格 `(x,y)[]` | 地形类型等 | 底部工具方块区（①类） |
| **建筑选择器** | 建筑 `BuildingId[]` | 建筑类型 / 来源等 | 底部工具方块区（①类） |
| ❌ 混合选择 | — | **不支持**（P4：混合后无「共同属性」） | — |

> 多选统一入口：选择器框选 → 选区变化（**依赖 P0**）→ 对象上下文面板浮出 → **属性区显示交集属性** → 批量统一（**K3**：交集 +「（多个值）」占位 + 1 步原子撤销 + 选区计数）。

### 11.4 三个重点说明

**① 「自动生长」在哪一步触发？**
- **触发点 = 底部工具「区域圈定」的确认动作**（步 4）；生长为**即时**（一次生成一批），非逐帧。
- **区域实体不存在**——当前 `MapDoc` 无 Zone 概念（承重缺口）。

**② 生长结果如何被用户微调？**
- 用**建筑选择器**选中个别建筑 → 对象上下文面板改属性 / 删。
- ✅ **已裁定（R2，定案）**：用户手动改过的「生长建筑」**转固定（override 层），不参与重算**——非破坏编辑的硬要求。柯桥良 E1 亦明确「用户覆盖存 override 层，不被重算冲掉」。

**③ 与「非破坏编辑」「时间轴驱动」如何共处？**
- **非破坏**：区域保留**生成参数 + 种子** → 重算可复现；用户手工改动以**覆盖层**附加，不删除生成参数。
- **时间轴**：生长**不自动随时间轴重算**（否则历史跳变）——只在**用户显式重算**时改变；时间轴只回放既有事件。

### 11.5 视线转移与风险

- **世界层**：视线**不离开底部 + 画布**（0 次跨面板）。
- **城市层**：主链路 **0 次**跨面板（工具在底部、属性浮出在近处）。
- **唯一 > 1 次**：步 9 用 Ctrl+E 从零登记时（对象面板 → 登记面板）。
- **「选工具与选目标跨面板」风险**：**已消除**——C1 / C2 保证工具与目标同在底部。
