# 事件与人物登记规格 v0.1

> 事件与人物是世界观的「魂」。两者通过时间轴与地点互相引用：事件发生在时间与地点上、由人物参与，事件结果又反过来修改人物属性。
> 字段定义以 [数据模型规格](数据模型规格_v0.1.md) 的 §5（人物）与 §6（事件）为唯一真源。

---

## 1. 事件登记系统

### 1.1 登记流程

1. **选择时间**——在时间轴上取一个时间点或时间段；可按地图粒度决定精度（世界地图可只填到年/月并标记**模糊时间**，城市地图可到小时，室内可到分钟）。
2. **选择地点**——在地图上点击拾取坐标，或从列表选择城市 / 建筑 / 区域 / 地下层。
3. **添加参与者**——参与者、目击者、发起者。
4. **填写描述与结果**——`description`（自由文本）+ `outcome`（自由文本结果）。
5. **填写影响范围**——`scope`（circle / polygon / rect）。
6. **关联前置/后续事件**——`prev_events` / `next_events`，形成事件链。
7. **保存**——写入 `events/` 目录，并在地图的事件层与时间轴上显示标记。

### 1.2 地点拾取（多粒度）

地点按精度从粗到细任选其一（见 [数据模型规格 §6.1](数据模型规格_v0.1.md)）：

| 粒度 | 交互 |
|---|---|
| 世界地图坐标 | 在世界地图上直接点击拾取 `x`/`y` |
| 城市 | 从城市列表选择，或点击世界地图上的城市标记 |
| 建筑 | 在城市地图中点击建筑 |
| 区域 | 从区域地图选择 |
| 地下层 | 从地下/洞穴图选择 |

### 1.3 结构化影响（`effects`）

事件可修改（**结构化**，非自由文本）：

| 可修改对象 | `target_kind` |
|---|---|
| 人物属性 | `character_attribute` |
| 势力疆界 | `border` |
| 城市归属 | `city_ownership` |
| 建筑状态 | `building_state` |
| 图层可见性 | `layer_visibility` |
| 载具状态 | `vehicle_state` |

**为什么必须结构化**：时间轴回放靠「重演 effects」重建状态（见 [时间轴系统规格 §3.3](时间轴系统规格_v0.1.md)）。自由文本无法重演，故 `outcome` 只作叙事，**一切状态改变必须落到 `effects`**。

### 1.4 时间轴联动

- 保存事件后：在地图**事件层**生成事件点与影响范围；在**时间轴**上生成标记。
- 若事件带 `effects`，拖到该事件之后的时间点，地图状态随之改变。

### 1.5 关联关系

```
        prev_events ──▶ [本事件] ──▶ next_events
                            │
        ┌───────────────────┼───────────────────┐
     时间/时间段          地点               人物
     (timeline)        (map/city/        (participants/
                         building)        witnesses/instigator)
                            │
                            ▼
                        effects ──▶ 修改人物属性 / 疆界 / 城市归属 / 建筑状态 / 图层
```

### 1.6 运输事件（`is_transport`）

运输任务本身可作为事件登记（见 [数据模型规格 §10](数据模型规格_v0.1.md)）：

- 事件置 `is_transport: true`，并关联 `vehicle_ref`（载具）、`route_ref`（路线）、`depart_time` / `arrive_time`（出发/到达时间）、`mid_events`（中途事件列表）。
- **中途事件**（出发、经过驿站、休息、遭遇袭击、天气变化、载具损坏、到达等）是普通事件，通过 `mid_events` 挂在运输事件下，各带自己的 `time`，可关联人物/势力/地图坐标。
- 中途事件可带 `effects`（如 `vehicle_state`：载具损坏状态、货物增减、乘员增减），挂到时间轴后可回放。
- 登记入口见 [界面与交互规格](界面与交互规格_v0.1.md) §时间预估面板（可一键创建运输事件）。

## 2. 人物登记系统

### 2.1 登记流程

1. **新建人物**——填写基础信息（姓名、别名、性别、生卒时间等）。
2. **选择性格倾向**——可自定义标签（`traits`）。
3. **定义自定义属性模板**——如 HP、MP、力量、智力、声望（见 §2.2）。
4. **设置人物关系**——家族、盟友、敌人、师徒、恋人（见 §2.3）。
5. **关联居住地、所属势力、参与事件**。
6. **保存**——写入 `characters/` 目录。

### 2.2 属性模板机制（Event 可修改）

**属性名完全自定义**。每个属性由属性模板定义：

| 字段 | 说明 |
|---|---|
| `key` | 稳定键（如 `hp`） |
| `label` | 显示名（如 `HP`） |
| `type` | `number` / `text` / `enum` / `bool` |
| `default` | 默认值 |
| `min` / `max` | 数值边界 |
| `unit` | 单位 |
| `options` | `enum` 的可选值 |
| `scope` | `character` / `event` |

**示例模板**：

```yaml
attribute_templates:
  - { key: hp,       label: HP,   type: number, default: 100, min: 0, max: 999, unit: 点, scope: character }
  - { key: mp,       label: MP,   type: number, default: 50,  min: 0, max: 999, unit: 点, scope: character }
  - { key: strength, label: 力量, type: number, default: 10,  min: 1, max: 30,  scope: character }
  - { key: fame,     label: 声望, type: number, default: 0,   min: -100, max: 100, scope: character }
  - { key: camp,     label: 阵营, type: enum,   options: [帝国, 商会, 教廷, 中立], default: 中立, scope: character }
```

> 属性模板建议置于**工程级**配置（全工程复用），而非每个人物各写一份——避免定义漂移。具体放置见 [存储与目录规范](存储与目录规范_v0.1.md)。

**事件修改人物属性**：通过事件 `effects`（`target_kind: character_attribute`）的 `op`（`set`/`add`/`mul`）实现。

### 2.3 关系网（Relation）

| 关系 | `kind` | 通常方向 |
|---|---|---|
| 家族 | `family` | 双向 |
| 盟友 | `ally` | 双向 |
| 敌人 | `enemy` | 双向 |
| 师徒 | `mentor` / `disciple` | 单向 |
| 恋人 | `lover` | 双向 |

- 每条关系含 `target` / `kind` / `direction` / `notes`，可选 `valid_from` / `valid_to`（关系可随时间变化）。
- 关系网以**图**呈现；双向关系只存一份（存于 `id` 较小者一侧，或由存储层统一归一，见存储规范 §引用校验）。

### 2.4 人物状态随时间变化

- **生卒**：`birth_time` / `death_time`，回放时据此判定是否在世。
- **属性**：由事件的 `effects` 修改，回放时重演。
- **所属势力 / 居住地**：可由事件修改（可扩展 `effects` 支持，见待标定项）。

回放到某时刻，可查看该人物**当时**的属性与状态（见 [时间轴系统规格 §4](时间轴系统规格_v0.1.md)）。

## 3. 事件 ↔ 人物 双向联动

| 方向 | 机制 |
|---|---|
| 事件 → 人物 | 事件的 `participants`/`witnesses`/`instigator` 引用人物；`effects` 修改人物属性 |
| 人物 → 事件 | 人物详情页列出该人物参与的事件（由事件索引反向构建，见 [数据模型规格 §5](数据模型规格_v0.1.md) 派生数据说明） |
| 载具 ↔ 人物 | 载具的 `driver`（驾驶者）/`crew`（乘员）/`capacity.min_guards`（护卫）引用人物；人物属性可影响载具速度、休息与消耗 `[待标定]` |
| 运输任务 ↔ 人物 | 运输任务的 `characters` 引用参与人物；中途事件可修改人物状态（`effects`） |

**一致性要求**：`event_refs`（人物侧）为派生数据，禁止与事件的参与者字段双写不一致。实现时由存储层的引用索引统一生成。

## 4. 校验规则

- [ ] 事件的 `time` 或 `time_range` 至少有一个（且只有其一）。
- [ ] 事件的 `location` 至少给出一个粒度，且引用 ID 存在。
- [ ] `participants` / `witnesses` / `instigator` 引用的都是存在的人物 ID。
- [ ] `effects` 的 `target` 存在；`attr` 在属性模板中已定义；`value` 落在 `[min, max]` 内。
- [ ] 人物 `relations` 的 `target` 存在，且双向关系不重复登记。
- [ ] 人物 `custom_attributes` 的键都能在属性模板中找到定义（否则报「未定义属性」）。
- [ ] 运输事件 `is_transport: true` 时，`vehicle_ref`/`route_ref` 存在；`mid_events` 引用的都是存在的事件；`depart_time <= arrive_time`。
- [ ] 载具的 `driver`/`crew` 引用的都是存在的人物 ID；运输任务 `characters` 引用的都是存在的人物 ID。

## 5. 待标定项

| 项 | 说明 |
|---|---|
| 属性模板的存放层级 `[待标定]` | 工程级统一 vs 人物级覆盖 |
| 事件修改「所属势力/居住地」 | 当前 `effects` 未覆盖，需扩展 `target_kind` |
| 关系网可视化布局 | 力导向 vs 分组层级 |
| 同刻多事件的稳定排序 | 建议 `time` + `id`，待定案 |
