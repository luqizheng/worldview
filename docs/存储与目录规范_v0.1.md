# 存储与目录规范 v0.1

> 「目录即工程」——一个文件夹就是一个完整世界工程。本文件规定目录布局、文件划分与引用规则，是**存储层的唯一真源**。
> 字段含义以 [数据模型规格_v0.1.md](数据模型规格_v0.1.md) 为准。

---

## 1. 工程目录布局

```

├── project.yaml               # 工程元数据（Project：名称/版本/作者/纪元/默认时间/索引）
├── maps/                      # 地图
│   ├── world/                 #   世界地图 / 区域地图
│   │   ├── main.yaml          #     地图定义（含 grid 网格/距离、time 时间设置、anchor 坐标映射、图层、标记、city_refs）

│   │   ├── main.height.yaml   #     高度图数据（独立文件；小图/稀疏）
│   │   ├── main.terrain.chunks/   # 地形二进制分块目录（大图 chunked 编码，见 §5.3）

│   │   │   └── 1_0.bin

│   │       └── 0_0.bin
│   ├── city/                  #   城市地图
│   │   └── port_aurora.yaml
│   ├── street/                #   街区地图（可选层级，城市与建筑之间）
│   │   └── market_district.yaml
│   ├── building/              #   建筑/室内图
│   │   └── tavern_03.yaml
│   └── underground/           #   地下/洞穴图
│       └── mine_shaft.yaml
├── characters/                # 人物（一人一文件）
│   ├── _templates.yaml        #   属性模板（工程级，见 §4）
│   └── lin_yu.yaml
├── vehicles/                  # 载具（一载具一文件）

│   └── silk_road.yaml
├── transport/                 # 运输任务（一任务一文件）
│   └── silk_road_run_01.yaml
├── events/                    # 事件
│   └── 1042_aurora_riot.yaml
├── timeline/                  # 时间轴与快照
```

**根目录必需项**：`project.yaml`。其余目录在首次写入时按需创建。

## 2. 文件划分原则

| 原则 | 说明 |
|---|---|
| **元数据与体量数据分离** | 地图定义（`main.yaml`）只放索引与配置；地形/高度等大网格放独立文件（`.terrain.yaml` / `.height.yaml`） |
| **YAML 源 + 二进制分块混合** | 元数据、索引、跨文件引用**一律 YAML**；超大地图的**数值数组**用二进制 `.bin` 分块（`encoding: chunked`），块索引与类型声明仍留在 YAML，格式见 [二进制格式规格](二进制格式规格_v0.1.md) |
| **一人一文件、一事件一文件** | 便于 Git diff、便于手改、便于并行编辑 |
| **载具/路线/任务各自成文件** | `vehicles/`、`routes/`、`transport/` 下各对象一文件一对象，便于引用与并行编辑 |
| **模板集中** | 属性模板等全工程复用配置放 `characters/_templates.yaml`，不要每人各写一份 |
| **可重建的不入库** | `.worldview/cache/` 派生数据可由源文件重建，建议 Git 忽略 |

> **为什么大网格要分文件**：世界地图可能有百万级网格点。写进一个 YAML 会导致 diff 巨大、手改不可能、Git 仓库膨胀。分离后，只有真正改动的地图才会产生 diff。

## 3. 引用规则（关键约束）

### 3.1 两种引用方式，禁止混用

| 方式 | 形式 | 用途 |
|---|---|---|
| **路径引用 `ref`** | 相对工程根的路径，如 `maps/city/port_aurora.yaml` | **跨文件、跨类型**（城市地图、室内图、资源） |
| **ID 引用 `id`** | 稳定 ID，如 `char_lin_yu` | **同类型对象之间**（人物↔人物、事件↔事件） |

**规则**：

1. 引用地图/资源文件 → 用 `ref`（相对路径）；载具/运输任务的「当前所在地图」「出发地/目的地地图」也用 `ref`。
2. 引用人物/事件/势力/载具/路线 → 用 `id`。
3. 一个字段只用一种方式，**不得混用**（如不得用路径去指人物，也不得用 ID 去指地图文件）。
4. 所有 `ref` 必须是**相对工程根**的路径，使用正斜杠 `/`；**禁止绝对路径**、禁止 `..` 逃出工程根。
5. 所有 `id` 在**工程内全局唯一**（跨类型也不重复，便于校验与全局搜索）。

### 3.2 引用解析

- 路径引用相对于**工程根**解析，与当前打开的文件位置无关（避免「移动文件后全断」）。
- 工程根由 `project.yaml` 所在目录确定；打开工程时先定位 `project.yaml`。

### 3.3 断链与删除

- **删除前检查依赖**：删除人物/事件/地图前，先扫描全工程反向引用。
- 存在依赖时：提示「被 N 处引用」，给出引用清单，要求用户确认（或提供「替换引用」选项）。
- 已存在的断链（用户手改 YAML 造成）：保存/打开工程时由校验器报出，**界面显式提示**，不静默失败。

## 4. 属性模板存放

属性模板（见 [事件与人物登记规格 §2.2](事件与人物登记规格_v0.1.md)）建议**工程级集中**存放于 `characters/_templates.yaml`，全工程复用，避免定义漂移。

```yaml
# characters/_templates.yaml
attribute_templates:
  - { key: hp,   label: HP,   type: number, default: 100, min: 0, max: 999, unit: 点, scope: character }
  - { key: fame, label: 声望, type: number, default: 0, min: -100, max: 100, scope: character }
```

> 存放层级（工程级统一 vs 人物级覆盖）列入待标定项，见 §8。

## 5. 大网格数据的编码（混合存储）

地形与高度图支持三种编码（地图 YAML 中 `terrain_data.encoding` / `height_data.encoding` 声明）。这是原则 3「YAML 为主 + 大网格二进制例外」在存储层的落地。

| 编码 | 结构 | 载体 | 适用 |
|---|---|---|---|
| `grid` | 二维数组 / 游程编码（RLE） | YAML | 小地图；对 diff 不友好 |
| `sparse` | 只列「非默认值」的单元 `cells: [{x,y,...}]` | YAML | 中等地图（默认值占多数时体量大减） |
| `chunked` | 定长分块 `.bin` + YAML 索引 | **二进制 + YAML 索引** | 超大地图（世界/区域，百万级网格点） |

### 5.1 YAML 编码（`grid` / `sparse`）

- 默认值写在 `default` 字段；**建议**：小地图（城市/室内）用 `grid`，中等地图用 `sparse`。
- **约束**：YAML 编码序列化后必须**可读、可手动编辑、diff 有意义**——这是 YAML 原则的直接要求。

#### 5.1.1 `default` 字段（必填）

- **必填**：YAML 编码（`grid` / `sparse`）时 `terrain_data` / `height_data` 必须声明 `default` 单元；`height_data` 在 MVP 阶段固定 `{height: 0}`，无高度层时按 0 处理。
- `default` 含义：未在 `cells` 中列出的单元 = `default`。**MVP 默认值**：`{type: plain, move_cost: 1, buildable: true}`（见 [数据模型规格 §3.1](数据模型规格_v0.1.md)）。
- 落盘时若 `cells` 为空 → 整张图按 `default` 生成，文件不写 `cells` 键。

#### 5.1.2 sparse 编码策略（避免 Git diff 噪声）

sparse 的目标是「**只存与默认不同的部分**」，避免每次编辑都重写整张网格。

- **保存策略**：遍历内存网格，对每个单元与 `default` 比较；**等值于 default 的单元不写入**。
- **编码决策阈值（MVP 落地口径）**：
  - **小图**（`grid.width × grid.height ≤ 1024`）：使用 `grid` 编码（二维数组 `cells[row*W+col]`）。
  - **中图**（`1024 < 总单元数 ≤ 1024×1024`）：使用 `sparse` 编码。
  - **大图**（`总单元数 > 1024×1024`）：MVP 阶段**提示**「MVP 未启用 `chunked`，建议使用 `sparse`」；不自动切换。
- **手动切换**：用户在地图设置面板可手动选 `grid` / `sparse` / `chunked`（MVP 不实现 chunked）。切换是显式操作，**不得默默改写**。
- **笔刷覆盖 default 值**：笔刷把单元写为 `default` 值时，**从 sparse `cells` 中删除该条目**（保持稀疏性）。
- **cells_ref 一致性**：保存时若 `cells_ref` 指向的文件与 `terrain_data.encoding` 声明的格式不符（如声明 sparse 但文件是 grid），校验器必须报错并阻止保存。

#### 5.1.3 grid 编码（默认策略）

- 二维数组 `cells[row*W+col]`；行优先；下标越界视为非法数据。
- 适用于**网格规模小**或**非默认值占比高**（sparse 优势消失）的场景。
- MVP 默认对小图采用此编码（64×48、128×128、512×512）。

#### 5.1.4 字段顺序

sparse 的 `cells[]` 元素按 `(y, x)` 升序排列（即先按行再按列），便于手改时定位与 Git diff 收敛。

### 5.2 二进制分块（`chunked`）

当网格数组超出 YAML 可承载体积，改用二进制分块：

- **每块固定 `chunk_size`×`chunk_size` 格**（默认 `64`，可配置），一块一个 `.bin` 文件，命名 `<cx>_<cy>.bin`（块坐标）。
- **块内数值连续存储**（行优先），单元类型由 `dtype` 决定（`u8`/`i16`/`u16`/`f32`）；地形类型用整型、高度用浮点。
- **索引留在 YAML**：`chunk_dir`、`chunk_size`、`dtype`、`chunk_index`（`{cx, cy, ref, crc32, dtype}`）与 `default` 一律写在地图 YAML 里，块文件只承载数值。

```yaml
# maps/world/main.yaml（片段）
terrain_data:
  encoding: chunked
  chunk_size: 64
  chunk_dir: maps/world/main.terrain.chunks/
  dtype: u8
  default: { type: plain, move_cost: 1, buildable: true }
  chunk_index:
    - { cx: 0, cy: 0, ref: maps/world/main.terrain.chunks/0_0.bin, crc32: 0x1a2b3c4d, dtype: u8 }
    - { cx: 1, cy: 0, ref: maps/world/main.terrain.chunks/1_0.bin, crc32: 0x5e6f7a8b, dtype: u8 }
```

**约束**：

- **「索引在 YAML、数据在二进制、声明可校验」**：块文件不得承载任何语义配置（图例、单位、引用），语义永远来自 YAML。
- 文件头、字节序（统一 **little-endian**）、坐标→块映射、校验与版本，以 [二进制格式规格](二进制格式规格_v0.1.md) 为准。
- **何时启用**：`grid`/`sparse` 序列化后体积或 diff 成本超过可接受上限时（上限 `[待标定]`）改 `chunked`；切换编码属显式操作，须同步更新 YAML 声明，不得默默改写。

## 6. 自动保存、备份与导入导出

| 能力 | 说明 |
|---|---|
| **自动保存** | 写入 `.worldview/autosave/`，间隔与保留策略由 `settings.autosave` 控制 |
| **手动备份** | 全工程快照到 `.worldview/backup/`，保留 `settings.backup_keep` 份 |
| **导入** | 从外部 YAML/图片导入（如导入地图底图到 `assets/`） |
| **导出** | 导出工程子集（如「只导出某城市+其居民+相关事件」） |
| **Git 版本管理** | 工程目录本身即仓库；`.worldview/cache/` 建议忽略，`autosave/` 由策略决定 |

**导入导出的引用处理**：

- 导入外部资源时，复制进 `assets/` 并**改写引用为工程内相对路径**。
- 导出子集时，必须**连带解析引用闭包**（导出城市 → 连带其居民、相关事件），否则导出结果断链。
- 导出含 `chunked` 地图时，须**连带块目录**（`*.chunks/*.bin`）与 YAML 索引；只导 YAML 会留下不可读的空网格。

## 7. 校验器（保存/打开工程时执行）

- [ ] `project.yaml` 存在且 `project_version` 受支持。
- [ ] 所有 `ref` 指向的文件存在；所有 `id` 引用可解析。
- [ ] 所有 `ref` 为相对工程根且不逃逸（无绝对路径、无 `..` 越界）。
- [ ] `id` 全局唯一（跨类型不重复）。
- [ ] 地图 `city_refs[].map_ref` / 建筑 `interior_ref` 可达（断链显式报错）。
- [ ] 属性值落在模板 `[min, max]`；`enum` 取值在 `options` 内。
- [ ] 事件 `effects` 的 `target` 存在（见 [事件与人物登记规格 §4](事件与人物登记规格_v0.1.md)）。
- [ ] 时间轴范围与事件时间一致（见 [时间轴系统规格 §7](时间轴系统规格_v0.1.md)）。
- [ ] 载具 `map_ref` 指向的地图存在；运输路线 `map_ref`/`child_map_refs` 可达；运输任务 `vehicle_ref`/`route_ref` 可解析。
- [ ] 运输任务 `depart_time <= arrive_time`；`mid_events` 引用的都是存在的事件。
- [ ] `chunked` 编码：`chunk_index` 覆盖完整（无缺块/重叠）、块文件可达、`crc32` 与实际文件一致、`chunk_size`/`dtype` 与块文件头一致（见 [二进制格式规格](二进制格式规格_v0.1.md)）。
- [ ] 地图存在 `anchor` 时 `parent_map` 必填；`parent_x`/`parent_y` 应落在父图 `grid` 范围内；`extent` 与 `anchor` 派生结果一致（冲突以 `anchor` 为准并告警）。

**错误输出要求**：指明**文件名 + 键路径 + 行号**，便于手改用户定位。

## 8. 待标定项

| 项 | 说明 |
|---|---|
| 自动保存间隔与保留份数 `[待标定]` | 默认策略 |
| 属性模板层级 | 工程级集中 vs 人物级覆盖 |
| 超大网格的 YAML 承载上限 `[待标定]` | 超过则改用 `chunked` 二进制分块（编码切换为显式操作） |
| 二进制分块尺寸 `chunk_size` `[待标定]` | 默认 `64`；权衡单块体积与块数量（I/O 次数） |
| 分块文件是否随 Git（LFS） | `.bin` 为二进制，diff 无意义；建议配合 Git LFS 或忽略重生成 |
| `anchor` 越界策略 | 子图锚点是否允许落在父图 `grid` 范围外（用于扩展世界边界）`[待标定]` |
| `.worldview/` 是否随 Git | 建议忽略 cache，autosave 按策略 |

## 9. 与数据模型的对应

| 数据模型对象 | 落盘位置 |
|---|---|
| Project | `project.yaml` |
| Map（世界/区域/城市） | `maps/world/*.yaml`、`maps/city/*.yaml` |
| Map（街区，可选层级） | `maps/street/*.yaml` |
| Map（建筑室内） | `maps/building/*.yaml` |

| Timeline / 基准 / 差异 | `timeline/main.yaml`、`timeline/base_*.yaml`、`timeline/diff/*.yaml` |
| 资源 | `assets/**` |
