# World View 总体设计 v0.1

> 本文是 World View（软件 0.1）的**总纲**：定位、设计原则、技术架构（技术中立）、里程碑、风险与对策。
> 数据结构以 [数据模型规格_v0.1.md](数据模型规格_v0.1.md) 为唯一真源；存储以 [存储与目录规范_v0.1.md](存储与目录规范_v0.1.md) 为准。
> 阅读顺序与待决项见根 [AGENTS.md](../AGENTS.md)。

---

## 1. 项目定位

World View 是一个**单机优先、目录化存储、YAML 驱动**的世界构建工具。

面向人群：小说作者、TRPG 主持人、游戏策划、世界观创作者。

它同时管理四个维度，核心目标是**让地理、时间、人物、事件四者互相引用、互相驱动**：

| 维度 | 内容 |
|---|---|
| **地理空间** | 世界地图、区域地图、城市地图、建筑布局 |
| **时间维度** | 时间轴、历史事件、状态变化 |
| **人物维度** | 角色、性格、自定义属性、关系网 |
| **事件维度** | 时间、地点、人物、结果 |

**一句话定位**：以地理为底、时间轴为骨、人物与事件为魂的单机世界编辑器。

**运输维度**（v0.1 纳入，见 §7 M8）：运输系统是连接「地理空间」与「时间轴」的关键模块——回答「谁、用什么载具、走哪条路、走多久、需要休息几次、何时到达」。载具、路线、运输任务三者把地理与时间真正联动起来（见 [数据模型规格](数据模型规格_v0.1.md) §8–§10）。

**非目标（明确不做）**：多人在线协作、服务器端存储、云端账号体系、实时同步。v0.1 不引入任何网络依赖。

## 2. 设计原则（七条，不可动摇）

1. **单机可运行**：无需服务器，直接读写本地目录。
2. **目录即工程**：一个文件夹就是一个完整世界工程。
3. **YAML 为主格式**：人类可读，可手动编辑，可 Git 版本管理。
4. **多地图层级**：世界地图 → 区域地图 → 城市地图 → 建筑/室内地图。
5. **图层化编辑**：地形、疆界、影响力、道路、事件点等分层管理，可独立开关、锁定、调透明度与叠加顺序。
6. **非破坏编辑**：笔刷、方框、圆形选区可撤销、可重做、可保存快照。
7. **时间轴驱动**：拖动时间轴，地图图层、人物状态、势力范围可随时间变化。

**衍生的工程约束**（由原则推导，实现时强制）：

- 由原则 3 → 所有字段必须有**稳定语义 + 可校验**，不能依赖运行时隐式状态；手改 YAML 出错必须能被校验器定位到文件与行。
- 由原则 2 → 工程内所有引用必须**自包含**（相对路径或稳定 ID），不得出现指向工程外的绝对路径。
- 由原则 5 + 7 → 图层与时间轴必须解耦设计：图层声明「有效时间范围」，时间轴决定「当前时刻」，渲染层只做交集。
- 由原则 4 → **每个地图层级独立配置网格、距离单位与时间粒度**（世界用公里、城市用米、室内用厘米；世界按日/月/年、城市按小时、室内按分钟）；进入子地图时自动切换网格、比例尺、单位、吸附与时间轴粒度，返回父地图时切回（见 §5、[数据模型规格](数据模型规格_v0.1.md) §2.2/§2.3）。

## 3. 分层架构（技术中立）

只描述**职责与依赖方向**，不绑定框架。

```
┌─────────────────────────────────────────────┐
│  界面层  UI / Interaction                    │  主界面、时间轴滑块、图层开关、属性面板
├─────────────────────────────────────────────┤
│  编辑层  Editing                             │  笔刷、选区、道路/建筑放置、撤销重做栈
├─────────────────────────────────────────────┤
│  领域层  Domain（数据模型 + 规则）            │  工程/地图/地形/图层/人物/事件/时间轴
│          贴合算法 · 影响力衰减 · 居民生成      │  载具/路线/运输任务（时间计算）
│          运输时间计算                          │  ← 纯逻辑，可脱离 UI 测试
├─────────────────────────────────────────────┤
│  存储层  Storage                             │  YAML 序列化、目录工程、引用校验、快照、备份
├─────────────────────────────────────────────┤
│  渲染层  Render                              │  Canvas 或 WebGL；瓦片/矢量绘制、图层合成
└─────────────────────────────────────────────┘
```

**依赖方向自下而上单向**：界面 → 编辑 → 领域 → 存储；渲染层只读领域数据，不反向修改。

**关键约束**：

- **领域层是纯逻辑**，不依赖 UI 与渲染；贴合、裁剪、居民生成等算法应能脱离界面单测。
- **存储层是唯一 I/O 出口**，领域层对象不直接碰文件。
- **时间轴不直接改数据**：回放时按「基准状态 + 差异事件」在内存中重建视图，不改写磁盘上的基准（见 §6、[时间轴系统规格](时间轴系统规格_v0.1.md)）。
- **呈现与编辑分层**：地图呈现（编辑/预览/回放模式、视图与坐标系统、测量工具）属界面/渲染层职责，只读领域数据；呈现模式的规格见 [地图编辑器规格](地图编辑器规格_v0.1.md) §5/§7。

### 3.1 技术选型（已收敛；2026-10-09 反转 P0-1 / P0-2）

| 形状 | 选型 | 承担职责 |
|---|---|---|
| 桌面壳 / 编辑器宿主 | **Godot 4.7.2 mono**（`.NET` / `C#`） | 单机桌面壳；编辑器主界面；2D 渲染宿主 |
| 主语言 | **C#**（.NET 8 / Godot SDK 配套） | UI、编辑器交互、YAML 解析（YamlDotNet）、空间索引、寻路、网格重采样、命令栈、引用校验 |
| 重计算（可选） | **Rust**（`crates/` 保留骨架） | 仅当 C# 出现明显瓶颈（M2+ 实测）时下沉；二进制分块读写、CRC 校验、空间索引加速等**留作可选加速层**，不参与 v0.1 主流程 |
| 渲染 | **Godot 内置 2D**：`Node2D` / `CanvasItem` / `TileMap` / `TileSet` + 自定义节点（`Sprite2D` / `Polygon2D` / `Line2D`） | 地图瓦片、矢量叠加、图层合成；PixiJS **全面下线** |
| 数据契约 | **YAML + 二进制分块（`.bin`）** | 见 [二进制格式规格](二进制格式规格_v0.1.md) |
| 文件系统 | Godot `DirAccess` + C# `System.IO` | 直接读写工程目录；无网络、无服务器 |
| 版本管理 | Git | 工程目录即仓库 |

**修订说明**（2026-10-09 反转）：

- 放弃 Tauri：**Godot 整体接管客户端 UI + 渲染 + 编辑器**。Tauri / WebView / TypeScript / Vite / `src/` / `src-tauri/` **一并撤销**。
- 放弃 PixiJS：**Godot 内置 2D 渲染足够**；`CanvasItem` 体系下的图层叠加、`TileMap` 分块、`Polygon2D` / `Line2D` 矢量绘制覆盖原计划。Web 导出路径同步作废（v0.1 仅桌面端）。
- Rust 降级为「可选加速层」：`crates/` 目录保留为空骨架,便于未来把重计算下沉;C# 处理 v0.1 的全部主流程。
- **数据契约中立原则不变**：C# / Godot / .NET 专有概念**只允许出现在本节与各规格的「实现」小节**,**不得污染《数据模型规格》的字段定义**。

**纪律**：

- **数据契约以中立字段为准**（[数据模型规格](数据模型规格_v0.1.md)）：Godot / C# / YamlDotNet 等框架专有概念**只允许出现在本节与各规格的「实现」小节**，**不得污染字段定义**。
- **视图 = 纯 2D 俯视 / 正交**：v0.1 不做 2.5D、不做 3D 预览。Three.js / Godot 3D 节点 **不引入**。
- **视图模式**：仅 `view_mode = 2d`；`isometric` / `3d` 为设计预留，不实现。
- **视觉增强（光照 / 天气）**：数据声明进 [图层系统规格](图层系统规格_v0.1.md)，**渲染留空**；是否启用 Godot `CanvasItem` 自定义 shader / `CanvasModulate` 留到 M3+ 决定，避免污染数据模型。
- **WebGPU 非硬性要求**：Godot Forward+ / Mobile 渲染器都覆盖 2D 俯视,选其一即可,默认 `Forward+`。
- 选型结论已在根 [AGENTS.md §3](../AGENTS.md) 第 3 节待决项表中标记 P0-1 / P0-2 已反转收敛；详细定案理由见 [技术基调确认_v0.1.md](技术基调确认_v0.1.md) §1 / §3 的「2026-10-09 反转说明」。

### 3.2 数据形态（已收敛）

**网格 + 矢量混合**：

- **网格**：地形、高度图——需要笔刷批量写入与邻域查询。
- **矢量**：疆界、道路、影响力范围——需要平滑曲线与拓扑关系。
- **大网格二进制分块**：超出可承载上限时落 `.bin`（`encoding: chunked`），索引与语义在 YAML，格式见 [二进制格式规格](二进制格式规格_v0.1.md)。

存储规则以 [存储与目录规范](存储与目录规范_v0.1.md) §5 为准。

**性能纪律**：M1 即引入分块思路（地形 / 高度 `encoding: chunked`），但不实现 LOD；LOD 与按需加载留到 M7。

**时间轴纪律**：M1 只做时间轴 UI 骨架 + 单地图的简单回放；**全量重算** 的性能问题留到 M7。

> 详细定案理由见 [技术基调确认_v0.1.md](技术基调确认_v0.1.md) §4 / §8。

### 3.5 统一地图内核（Common Kernel）

所有地图类型共用一套**地图内核**，**类型化扩展点**由各类地图自行实现差异部分：

**统一地图内核**（Common Kernel）：

| 能力 | 说明 |
|---|---|
| **坐标系统** | 世界坐标（工程基准）→ 地图坐标（本图格）→ 网格坐标（整数格）→ 屏幕坐标（像素）；跨地图通过 `anchor` 互转（见 [数据模型规格 §2.10](数据模型规格_v0.1.md)） |
| **网格与距离单位** | 每张地图独立设置；内部统一归一至 `base_unit` 再计算（见 [数据模型规格 §2.2](数据模型规格_v0.1.md)） |
| **图层系统** | 显示、隐藏、锁定、透明度、`z_order` 叠加；`valid_from`/`valid_to` 时间有效性（见 [图层系统规格](图层系统规格_v0.1.md)） |
| **时间轴** | 全局统一，地图级粒度（见 §6、[时间轴系统规格](时间轴系统规格_v0.1.md)） |
| **引用系统** | 人物 / 事件 / 载具 / 势力 / 子地图；统一 `ref`（相对路径）与 `id`（稳定 ID），断链校验 |
| **撤销 / 重做** | **命令模式**（Command Pattern）：每次编辑产生可序列化命令对象，支持多步撤销/重做与快照保存 |
| **空间索引** | **四叉树 / R 树**（按地图规模切换）：邻域查找、视口裁剪、命中测试 |
| **寻路** | **A\***、**导航网格（NavMesh）**：用于运输路线、事件移动、AI 路径 |

**类型化扩展点**（每种地图类型自带）：

| 扩展点 | 说明 |
|---|---|
| **数据格式** | 默认 `grid` / `sparse` / `chunked` 编码（见 [数据模型规格 §3](数据模型规格_v0.1.md)） |
| **渲染策略** | Godot 2D `TileMap` 瓦片 / `Sprite2D` + 矢量 / `Polygon2D` / `Line2D` 等（见 [地图类型规格](地图类型规格_v0.1.md)） |
| **编辑工具** | 笔刷、道路、建筑、居民生成等（见 [地图编辑器规格](地图编辑器规格_v0.1.md)） |
| **默认图层** | 地形 / 疆界 / 道路 / 建筑 / 影响力 等的开关与顺序 |
| **默认时间粒度** | 世界 `month`、城市 `hour`、建筑 `minute` 等（见 [数据模型规格 §2.3](数据模型规格_v0.1.md)） |
| **缩放层级** | 每类地图的 LOD 区间与图标 / 瓦片 / 精灵切换阈值 |

> 注意：「类型化扩展点」是**内建机制**（每类地图自带画像），不是第三方插件；后者属 [AGENTS.md](../AGENTS.md) §3 P1-3。

## 4. 核心对象总览

核心对象，详细字段见 [数据模型规格_v0.1.md](数据模型规格_v0.1.md)：

| 对象 | 一句话职责 | 关键关系 |
|---|---|---|
| **工程（Project）** | 一个世界工程的根元数据 | 持有纪元、默认时间、各索引 |
| **地图（Map）** | 一个可编辑空间，分四层级 | 可有父地图；可引用子地图文件；声明运输通行设置 |
| **地形（Terrain）** | 地图网格上的一个单元 | 挂在图层上；驱动贴合与通行 |
| **图层（Layer）** | 一类空间数据的容器 | 声明时间有效性；参与渲染合成 |
| **人物（Character）** | 一个角色及其可扩展属性 | 关联居住地、势力、事件、关系网；可驾驶/乘坐载具 |
| **事件（Event）** | 时间轴上的一个事实 | 关联时间、地点、人物；可修改状态；可为运输事件 |
| **时间轴（Timeline）** | 多粒度时间的坐标系 | 挂载事件；按粒度驱动回放 |
| **载具（Vehicle）** | 一种运输工具及其速度/载力/休息规则 | 属势力/人物；按路线行进；被运输任务引用 |
| **运输路线（Route）** | 绑定地图的一条通行路径 | 引用道路/航线/水域/传送点；分陆上/飞行/水上/地下/传送 |
| **运输任务（TransportTask）** | 载具 + 路线 + 时间预估 | 关联人物/势力/事件；输出出发/到达时间 |

**互相驱动的核心闭环**：

```
时间轴 ──指向时刻──▶ 事件 ──发生于──▶ 地点（地图/城市/建筑）
   ▲                    │
   │                    └──参与者──▶ 人物 ──属性被事件修改──▶ 回到人物
   └──────────────── 事件结果改写疆界/城市归属/建筑状态 ──▶ 反映到图层

运输任务 ──载具+路线──▶ 时间计算（速度/距离/休息）──▶ 出发/到达时间 ──挂载──▶ 时间轴
     │                                                      │
     └──经过地图/图层──▶ 陆上沿道路、飞行直线、水上沿航线 ──▶ 中途事件（可改载具/货物/乘员）
```

## 5. 多地图层级与引用

```
世界地图 (world)
  └── 区域地图 (region)          ※ 可选层级
        └── 城市地图 (city)
              └── 街区地图 (street)      ※ 可选层级
                    └── 建筑/室内图 (building / interior)
地下/洞穴图 (underground) 可交叉引用以上任一层级
```

- 世界地图上的城市条目**记录城市地图文件路径**；点击城市弹出基础信息，再「进入编辑」切换到城市地图。
- 城市地图中的特殊建筑可继续**记录室内地图路径**。
- 每张地图**独立设置**网格与距离单位（世界用公里、城市用米、室内用厘米）及**默认/最小时间粒度**；进入子地图时自动切换网格、比例尺、距离单位、吸附规则与时间轴粒度，返回父地图时切回（见 [数据模型规格](数据模型规格_v0.1.md) §2.2/§2.3）。
- 跨地图事件**共享同一全局时间轴**，绝对时间不因地图切换而改变，仅展示粒度随当前地图变化。
- 跨地图**坐标映射**：进入子地图时，子图 `anchor` + `grid` 决定其在父图的落点与范围；返回父地图时以 `extent` 定位最近绘出点；坐标公式见 [数据模型规格 §2.10](数据模型规格_v0.1.md)。
- 引用规则、路径表示与断链处理，以 [存储与目录规范](存储与目录规范_v0.1.md) 为准；编辑操作见 [地图编辑器规格](地图编辑器规格_v0.1.md)。

## 6. 时间轴驱动机制（总览）

- **时间刻度**：纪元、年、月、日、时、分、秒；历法（每年月数、每月天数、时/分/秒换算、闰规则）**可自定义**。
- **多粒度**：时间轴支持从「年」缩放到「分」；每张地图有各自的**默认/最小时间粒度**（世界按日/月/年、城市按小时、室内按分钟），进入地图自动切换（见 §5）。
- **模糊时间**：事件时间可只精确到年或月，标记为**模糊时间**并按粒度分组展示，避免虚假精度。
- **存储与显示分离**：磁盘只存绝对时间，展示按地图粒度格式化。
- **事件挂载**：事件可绑定**时间点**或**时间段**。
- **回放**：拖动滑块，地图上的疆界、影响力、事件点、城市归属随时间变化。
- **历史状态**：人物状态、势力范围、城市人口、建筑状态可随时间改变。
- **快照**：可为关键时间点保存地图快照，便于对比。
- **分支时间线**（可选，P1-2）：平行世界、IF 线、多结局。

**实现要旨**：不保存每个时刻的完整状态（会状态爆炸），只保存**基准状态 + 差异事件**，回放时重建。详见 [时间轴系统规格_v0.1.md](时间轴系统规格_v0.1.md)。

## 7. 开发里程碑

| 里程碑 | 目标 | 主要产出 |
|---|---|---|
| **M1** | Godot mono 工程骨架、YAML + 二进制分块读写、Godot 2D 基础地图显示 | 可创建/打开工程；地图渲染到 `Node2D` 树；空间索引（quadtree）C# 实现可用；`anchor` 跨图跳转 |
| **M2** | 世界地图笔刷、地形、高度信息 | 笔刷绘制地形；高度值读写与显示；YAML 与二进制分块互转 |
| **M3** | 图层系统、疆界自动贴合、影响力圆形裁剪、空间索引（R 树）、寻路 A\* | 图层开关/透明/顺序；贴合与裁剪算法；A* 用于路径预览 |
| **M4** | 城市地图、街区地图（可选）、建筑放置、居民生成 | 城市与街区编辑模式；按规则生成居民名单 |
| **M5** | 人物登记、自定义属性、关系网 | 属性模板机制；关系图 |
| **M6** | 事件登记、时间轴联动、地图标记 | 事件落到地图与时间轴；回放生效；视觉增强（昼夜/迷雾）绑定时轴 |
| **M7** | 多地图引用、导入导出、LOD 与分块加载 | 层级跳转；大世界性能（分块/LOD/图集/缓存） |
| **M8** | 载具登记、运输路线、运输时间计算、NavMesh | 载具/路线/运输任务模型；陆上沿路/飞行直线/水上沿航线寻路；按速度·距离·休息自动估算全程时间并挂到时间轴 |

**demo 验收口径**（每阶段必须给出一个可观察的 demo 形态）：

| 阶段 | 验收 demo |
|---|---|
| M1 | 加载一张示例 YAML 地图，能平移、缩放、显示网格与坐标 |
| M2 | 用圆形笔刷涂一片高度值，能撤销 / 重做并刷新显示 |
| M3 | 放一个图章，看它在图层顺序里被正确遮挡；影响力圆按疆界裁剪 |
| M4 | 在城市地图放一栋带 `interior_ref` 的建筑，能跳入室内图 |
| M5 | 给一个人物加 HP / 力量属性，并建立两条关系，导出 YAML |
| M6 | 拖动时间轴滑块，看疆界 / 影响力按时间变化 |
| M7 | 父图点城市条目能跳入城市图；导出模块生成 Godot 可读资产 |
| M8 | 一条运输任务从出发到到达的时间轴事件全部挂上 |

**依赖关系**：M1 → M2 → M3 为主线；M4 依赖 M2/M3；M5 可部分并行（仅依赖 M1 的存储）；M6 依赖 M4/M5（需要地点与人物才能挂事件）；M7 收口；M8 依赖 M1/M3/M6（需要地图、道路层与时间轴才能计算运输时间）。

**范围纪律**：M1–M8 之外的功能（分支时间线、第三方插件、多人协作）未经明确授权不得实现。

## 8. 风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| **自动贴合算法复杂** | 疆界需沿山脊线/河流/海岸贴合，纯规则难以完美 | v0.1 先实现**基于高度阈值 + 山脊线 + 河流的简化规则**，后续迭代；算法阈值全部可配置 |
| **大数组 YAML 慢** | 大世界网格数据 | **混合存储 + 二进制分块**（M1 即引入分块索引） |
| **笔刷性能** | 大面积笔刷频繁重绘 | Godot 2D **脏区重绘 + `ViewportTexture`**，只重绘被笔刷触碰的 `CanvasItem` 子树 |
| **图层过多** | 多图层合成卡顿 | **图层合成缓存 + 按需重绘**；按 `z_index` 分批下发给 `CanvasItem` |
| **图片资源大** | 用户上传大量图章 / 建筑图 | **缩略图 + Godot `AtlasTexture` + 按需加载** |
| **性能问题** | 大世界网格与多图层合成易卡 | **分块加载 + LOD + 延迟渲染 + 图集**；图层按需合成；C# 承担空间索引与寻路，Rust 仅作可选加速层 |
| **跨地图引用混乱** | 城市 / 室内引用断链 | **统一世界坐标 + 地图注册表** + 引用校验 |
| **数据一致性** | 跨文件引用可能断链（删了城市地图，世界地图仍引用） | **引用校验**；删除前检查依赖；断链在界面上显式提示而非静默失败 |
| **YAML 手动编辑冲突** | 用户手改可能写出非法结构 | 提供**校验器 + 自动备份**；错误定位到文件与行 |
| **时间轴状态爆炸** | 每个时刻存全量状态不可行 | **只记录差异，不保存完整快照**（快照 = 基准 + 差异序列） |
| **二进制格式漂移** | `.bin` 格式变化导致历史工程不可读 | `format_version` 严格管理；不破坏性扩展；未知版本拒绝读取（见 [二进制格式规格 §6](二进制格式规格_v0.1.md)） |
| **坐标映射断链** | 子图 `anchor` 越界、改父图网格未同步子图 `extent` | 校验器强制检查（见存储规范 §7）；`extent` 冲突以 `anchor` 为准并告警 |
| **导出格式变更** | Godot 端协议升级 | **版本号 + 迁移脚本** |
| **视觉增强污染数据模型** | 把光照 / 天气塞进《数据模型规格》字段 | **数据声明进《图层系统规格》、渲染实现留空；实现需明确授权** |
| **选型悬置** | 技术栈未定会阻塞 M1 | P0-1/P0-2 已反转收敛（**Godot 4.7.2 mono + C# + Godot 内置 2D**）；P0-3 保持（网格 + 矢量 + 二进制分块） |

## 9. 总结

本规划书定义了一个以地理为底、时间轴为骨、人物与事件为魂的单机世界编辑器：

- 支持**世界地图与城市地图双层（可扩区域/室内）编辑**，每张地图独立配置网格与距离单位，并各有独立的时间粒度；
- 支持**全局统一时间轴 + 地图级粒度**：事件存绝对时间、按地图粒度展示，跨地图切换自动适配；
- 支持笔刷地形、高度、道路、街道、巷子、建筑、居民、特殊建筑；
- 支持疆界与影响力自动贴合；
- 支持**地图呈现**：编辑/预览/回放三种模式（演示与观察者视角为设计预留），统一视图与坐标系统（世界/地图/网格/像素），比例尺与坐标显示，距离/面积/路径/时间/运输耗时测量；
- 支持**载具、运输路线与运输任务**：按速度、距离、休息规则与地形/天气修正自动计算全程时间，输出精确到年/月/日/时/分并挂到时间轴，让世界「动起来」；
- 补充了大量 RPG 可用图层（见 [图层系统规格](图层系统规格_v0.1.md)）；
- 数据以**目录 + YAML** 为主，可单机运行、可多地图引用、可随时间轴回放与修改。

**下一版（v0.2）应做的事**：把设计文档中的 `[待标定]` 阈值标定，并按 M1 落地工程骨架（**Godot mono + C#**）。P0-1 / P0-2 已在本轮反转收敛，P0-3 保持（详见 [技术基调确认_v0.1.md](技术基调确认_v0.1.md) §10）。
