## 1. 编辑器形态

| 项 | 结论 |
|---|---|
| 形态 | **Godot 4.7.2 mono 桌面应用**（单机优先，无服务器依赖） |
| 主语言 | **C#**（.NET 8 + Godot SDK；UI / 编辑器 / 数据契约 / 业务逻辑 / YAML 解析 / 空间索引 / 寻路 / 网格重采样 / 命令栈 / 引用校验 全部走 C#） |
| 重计算 | **Rust 留作可选加速层**（`crates/` 保留空骨架；M2+ 实测若 C# 出现瓶颈再下沉二进制分块读写、CRC、空间索引加速） |
| 视图 | **纯 2D 俯视 / 正交**，不做 2.5D、不做 3D 预览 |

**2026-10-09 反转说明**：放弃 Tauri + TypeScript + PixiJS 路线。Tauri 桌面壳、WebView 容器、TS / Vite / `src/` 全部撤销；2D 渲染改用 Godot 内置 `CanvasItem` / `TileMap` / `Polygon2D` / `Line2D`,PixiJS 全面下线。

**纪律**：技术专有 API（Godot / C# / .NET / YamlDotNet）只允许出现在《总体设计》与各规格的「实现」小节，**不得污染《数据模型规格》的字段定义**；数据契约仍以中立字段为准。

## 3. 渲染策略

| 项 | 结论 |
|---|---|
| 渲染库 | **Godot 内置 2D**（`Node2D` / `CanvasItem` / `TileMap` + `TileSet` / `Sprite2D` / `Polygon2D` / `Line2D`） |
| 是否引入 Three.js / Godot 3D 节点 | **不引入**，v0.1 不做 2.5D / 3D |
| 视图模式 | 仅 `2d`（俯视）；`isometric` / `3d` 为设计预留，不实现 |
| 视觉增强（光照 / 天气） | **数据声明** 进《图层系统规格》；**渲染留空**，留到 M3+ 再决定是否启用 Godot 自定义 shader / `CanvasModulate` |
| 渲染器 | Godot `Forward+` 或 `Mobile` 均可覆盖 2D 俯视；默认 `Forward+`,**WebGPU 非硬性要求** |

**2026-10-09 反转说明**：PixiJS 全面下线；Web 导出路径不再保留（v0.1 仅桌面端）。Godot Web 导出仅作为设计预留,不进 v0.1 验收。

**约束**：高度信息仍保留在数据模型中，但**只用于 2D 表现**（地形阴影、河流方向、疆界贴合），不用于 3D 透视。

## 4. 数据核心

| 项 | 结论 |
|---|---|
| 元数据 / 配置 / 矢量 | **YAML** |
| 大网格数组（地形 / 高度） | **二进制分块**（索引在 YAML、数据在二进制） |
| 格式契约 | 以 [二进制格式规格_v0.1.md](二进制格式规格_v0.1.md) 为准 |
| 数据形态 | **网格 + 矢量混合** |
| 引用规则 | 跨文件引用使用**相对工程根路径**或**稳定 ID**，二者不得混用 |

## 5. 导出目标

| 项 | 结论 |
|---|---|
| 导出目标 | **Godot 可读的 2D 地图资产** |
| 导出内容 | 仅地图相关数据：地形类型数组、高度数组、道路路径、建筑位置与类型、疆界边界、影响力范围、事件点坐标（可选）、载具路线（可选）、子地图引用关系 |
| **不导出** | 人物详细数据、事件详细描述、故事文本、势力背景、时间轴历史 |
| 导出格式 | 直接走**二进制分块 + JSON 索引**，**不复用**「简单方案 JSON」；复用现有《二进制格式规格》定义的格式契约，Godot 端用 TileMap / Sprite 重建 2D 地图 |
| 格式迁移 | 导出格式变更须带**版本号 + 迁移脚本** |

## 6. 地图层级与编辑器核心范围

### 6.1 地图层级

v0.1 注册的地图类型与层级关系：

```
world          世界地图
  └── region        区域地图（可选层级）
        └── city          城市地图
              └── street        街区地图（可选层级，与 region 同级可选）
                    └── building      建筑 / 室内图
  underground   地下 / 洞穴图（可交叉引用以上任一层级）
```

- `region` 与 `street` 为**可选层级**，具体登记口径见 [地图类型规格_v0.1.md](地图类型规格_v0.1.md)。
- 全部为 2D 编辑。

### 6.2 编辑器核心功能范围

| 模块 | v0.1 范围 |
|---|---|
| **笔刷** | 圆形 / 方形 / 套索 / 魔术棒 / 填充 / 橡皮；大小 / 强度 / 衰减 / 平滑；地形绘制、高度抬升 / 降低；实时预览 |
| **图章** | 建筑 / 植被 / 岩石 / 道具 / 标记；用户上传图片；缩放 / 旋转 / 翻转 / 透明度；变体：白天 / 夜晚、正常 / 损坏 |
| **图层** | 地形 / 高度 / 水域 / 植被 / 道路 / 建筑 / 疆界 / 影响力 / 事件 / 人物 / 载具与路线 / 时间快照；显示 / 隐藏 / 锁定 / 透明度 / 叠加顺序 / 时间有效性 |
| **疆界与影响力** | 方框 / 套索粗略绘制；基于高度、山脊、河流自动贴合（[图层系统规格](图层系统规格_v0.1.md) §贴合 规则）；影响力圆形、衰减、裁剪到疆界 |
| **道路与街道** | 世界：官道、小径、商路、航线、传送路径；城市：主街、次街、巷子、广场、桥梁、城墙 |
| **建筑与室内** | 建筑模板自定义；图片上传；放置、旋转、吸附；特殊建筑引用室内地图；室内图继续 2D 编辑 |
| **时间轴联动** | 全局时间轴；地图级时间粒度；事件点、疆界、影响力、城市归属随时间变化；回放模式 |
| **运输与载具** | 载具登记；路线绘制；时间计算；载具沿路线 2D 动画移动 |
| **数据管理** | 人物登记、事件登记、势力管理、载具管理、路线管理；全部 YAML 存储 |

## 7. 架构分层

```
┌─────────────────────────────────────────────┐
│              Godot mono 桌面应用 (C#)         │
│  ┌──────────────────┐  ┌──────────────────┐ │
│  │  编辑器 UI        │  │  2D 地图画布      │ │
│  │  (Control 节点)   │  │  Node2D / TileMap │ │
│  │  工具栏 / 图层    │  │  CanvasItem 体系  │ │
│  │  时间轴 / 属性    │  │  笔刷 / 图章 / 选区│ │
│  │                  │  │  图层合成 / 实时预览│ │
│  └──────────────────┘  └──────────────────┘ │
│  ┌──────────────────────────────────────────┐│
│  │  C# 业务层（Godot Node + Plain C# 类）     ││
│  │  · 编辑命令栈（Command Pattern）           ││
│  │  · 空间索引（quadtree / R 树）             ││
│  │  · 寻路 A* / NavMesh                       ││
│  │  · 时间轴回放 / 快照                       ││
│  │  · 引用校验 / 断链提示                      ││
│  │  ⚠ UI 状态与领域数据严格分层               ││
│  └──────────────────────────────────────────┘│
│  ┌──────────────────────────────────────────┐│
│  │  存储层 (C# + System.IO + YamlDotNet)      ││
│  │  · YAML / 二进制分块读写                   ││
│  │  · 目录工程管理                            ││
│  │  · 引用校验 / 快照 / 备份                   ││
│  │  · Rust 可选加速层（crates/,留作骨架）     ││
│  └──────────────────────────────────────────┘│
├─────────────────────────────────────────────┤
│                本地文件系统                   │
│  maps/ characters/ events/ assets/ ...       │
└─────────────────────────────────────────────┘
```

**2026-10-09 反转说明**：原 Tauri 前端 + Rust 后端的双进程架构作废。Godot 单进程承载 UI / 编辑器 / 渲染 / 业务 / 存储,Rust 仅作可选加速层骨架。

**关键约束**：

- **领域数据 ≠ UI 状态**。地图 / 图层 / 人物 / 事件 / 载具 / 路线等**领域数据**必须走《数据模型规格》的中立字段；Godot 节点属性与 C# UI 状态类**只承载**地图视图、选中、工具状态等**呈现状态**，不得把 `Node2D` / `CanvasItem` 对象混入数据模型。
- **存储层是唯一 I/O 出口**，领域层对象不直接碰文件。
- **时间轴不直接改数据**：回放时按「基准状态 + 差异事件」在内存中重建视图，不改写磁盘基准。

## 8. 开发里程碑（M1–M8 验收口径补全）

> 本节补入 [总体设计 §7](总体设计_v0.1.md#L165-L179) 的里程碑**验收口径**，每阶段必须给出一个可观察的 demo 形态。

| 阶段 | 目标 | 主要产出 | 验收口径（demo） |
|---|---|---|---|
| **阶段一 / M1** | 工程目录、YAML 读写、基础地图显示 | 可创建 / 打开工程；地图能渲染到 Godot `Node2D` 树 | 加载一张示例 YAML 地图，能平移、缩放、显示网格与坐标 |
| **阶段二 / M2** | 世界地图笔刷、地形、高度信息 | 笔刷绘制地形；高度值读写与显示 | 用圆形笔刷涂一片高度值，能撤销 / 重做并刷新显示 |
| **阶段三 / M3** | 图层系统、疆界自动贴合、影响力圆形裁剪 | 图层开关 / 透明 / 顺序；贴合与裁剪算法 | 放一个图章，看它在图层顺序里被正确遮挡；影响力圆按疆界裁剪 |
| **阶段四 / M4** | 城市地图、建筑放置、居民生成 | 城市编辑模式；按规则生成居民名单 | 在城市地图放一栋带 `interior_ref` 的建筑，能跳入室内图 |
| **阶段五 / M5** | 人物登记、自定义属性、关系网 | 属性模板机制；关系图（C# 关系图控件 + `Polygon2D` / `Line2D` 渲染） | 给一个人物加 HP / 力量属性，并建立两条关系，导出 YAML |
| **阶段六 / M6** | 事件登记、时间轴联动、地图标记 | 事件落到地图与时间轴；回放生效 | 拖动时间轴滑块，看疆界 / 影响力按时间变化 |
| **阶段七 / M7** | 多地图引用、导入导出、地图呈现、性能优化 | 层级跳转；编辑 / 预览 / 回放呈现模式 + 视图与坐标显示 + 测量工具；大世界性能（分块 / LOD） | 父图点城市条目能跳入城市图；导出模块生成 Godot 可读资产 |
| **阶段八 / M8** | 载具登记、运输路线、运输时间计算 | 载具 / 路线 / 运输任务模型；陆上沿路 / 飞行直线 / 水上沿航线寻路；按速度·距离·休息自动估算全程时间并挂到时间轴 | 一条运输任务从出发到到达的时间轴事件全部挂上 |

**性能纪律**：M1 即引入**分块思路**（地形 / 高度 `encoding: chunked`），但不实现 LOD；LOD 与按需加载留到 M7。

**时间轴纪律**：M1 只做时间轴 UI 骨架 + 单地图的简单回放；**全量重算** 的性能问题留到 M7。

## 9. 风险与对策（沿用并补全）

| 风险 | 说明 | 对策 |
|---|---|---|
| 大数组 YAML 慢 | 大世界网格数据 | **混合存储 + 二进制分块**（M1 即引入分块索引） |
| 笔刷性能 | 大面积笔刷频繁重绘 | Godot 2D 脏区重绘（按 `CanvasItem` 子树局部刷新），**只重绘脏区** |
| 图层过多 | 多图层合成卡顿 | 图层合成缓存，**按需重绘**；按 `z_index` 分批下发给 `CanvasItem` |
| 图片资源大 | 用户上传大量图章 / 建筑图 | **缩略图 + Godot `AtlasTexture` + 按需加载** |
| 导出格式变更 | Godot 端协议升级 | **版本号 + 迁移脚本** |
| 跨地图引用混乱 | 城市 / 室内引用断链 | **统一世界坐标 + 地图注册表** + 引用校验 |
| 视觉增强 / 时间光照 | 数据声明进入图层 | **渲染层留空**，避免污染数据模型；实现需明确授权 |
