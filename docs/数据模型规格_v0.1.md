# 数据模型规格 v0.1

> **本文件是 World View 全部数据结构、字段与枚举的唯一真源。** 任何涉及字段增改的需求，先改本文件，再同步其他文档与实现。
> 存储路径与文件划分见 [存储与目录规范_v0.1.md](存储与目录规范_v0.1.md)；算法规则见 [图层系统规格_v0.1.md](图层系统规格_v0.1.md)。

---

## 0. 通用约定

- **命名**：YAML 键名一律 `snake_case`；ID 一律字符串，采用 `<类型>_<slug>` 形式（如 `map_world_01`、`char_lin_yu`）。
- **ID 稳定**：ID 一经创建不可更改；显示名放 `name` 字段，可随便改。
- **引用表示**：跨文件引用统一用 `ref`（相对工程根的路径）或 `id`（同类对象稳定 ID），**不得混用**，详见 [存储与目录规范](存储与目录规范_v0.1.md) §3。
- **时间值**：统一用**绝对时间**（纪元 + 年 + 月 + 日 + 时 + 分 + 秒，见 §7.2），不用「距今 N 年」这类相对表达；**存储绝对时间、显示按地图粒度**，二者分离，事件可标注时间精度与是否模糊（见 §6、§7）。
- **距离与网格**：每张地图**独立配置**网格与距离单位（见 §2.2）；一切长度内部统一换算到该地图的 `base_unit` 基础单位（如米）再计算，避免多次换算误差，仅显示时换算回用户单位。
- **未标定数值**：算法阈值标注 `[待标定]`。
- **可空**：字段未填时省略键，不用 `null`（便于手写 YAML 与 Git diff）。

## 1. 工程（Project）

工程根元数据，是整个世界工程的入口。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `project_version` | string | ✔ | 工程模式版本，如 `0.1` |
| `name` | string | ✔ | 工程名称 |
| `author` | string | | 作者 |
| `description` | string | | 简介 |
| `era` | object | ✔ | 纪元设定，见 §1.1 |
| `default_time` | object | ✔ | 默认/初始时间点，见 §7.2 |
| `map_index` | array<ref> | ✔ | 地图文件索引 |
| `character_index` | array<ref> | | 人物文件索引 |
| `event_index` | array<ref> | | 事件文件索引 |
| `vehicle_index` | array<ref> | | 载具文件索引（见 §8） |
| `route_index` | array<ref> | | 运输路线文件索引（见 §9） |
| `transport_index` | array<ref> | | 运输任务文件索引（见 §10） |
| `timeline` | ref | | 时间轴文件 |
| `settings` | object | | 工具级设置（自动保存、备份策略等） |

### 1.1 纪元（era）

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 纪元名，如「创世历」 |
| `start_year` | int | 纪元年份起点 |
| `months_per_year` | int | 每年月数（自定义，如 12 或 10） |
| `days_per_month` | array<int> | 每月天数（支持不规则历法；各月等长时可只写一个值） |
| `hours_per_day` | int | 每日小时数（默认 24；奇幻历法可自定义，如 30） |
| `minutes_per_hour` | int | 每小时分钟数（默认 60） |
| `seconds_per_minute` | int | 每分钟秒数（默认 60） |
| `leap` | object | 闰年/闰月规则（可选），如 `{ every: 4, month: 2, add_days: 1 }` |

### 1.2 YAML 示例

```yaml
project_version: "0.1"
name: 艾瑟兰世界
author: 张三
description: 一个以航海贸易为核心的低魔世界

era:
  name: 创世历
  start_year: 1
  months_per_year: 12
  days_per_month: [31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31]
  hours_per_day: 24
  minutes_per_hour: 60
  seconds_per_minute: 60
  leap: { every: 4, month: 2, add_days: 1 }

default_time:               # 绝对时间点，低位字段缺省为 0
  year: 1042
  month: 3
  day: 12

map_index:
  - maps/world/main.yaml
  - maps/city/port_aurora.yaml
character_index:
  - characters/lin_yu.yaml
event_index:
  - events/1042_aurora_riot.yaml
timeline: timeline/main.yaml

settings:
  autosave: true
  backup_keep: 10
```

| `building_refs` | array<object> | | 仅城市/街区地图：建筑条目，见 §2.6 |
| `travel` | object | | 运输与通行设置，见 §2.7 |
| `presentation` | object | | 呈现与视图设置（视图模式/主题/观察者视角等），见 §2.8 |

### 2.1 地图类型（`type` 枚举）

| 值 | 含义 |
|---|---|
| `world` | 世界地图 |
| `region` | 区域地图 |
| `city` | 城市地图 |
| `street` | 街区地图（城市与建筑之间的**可选层级**） |
| `building` | 建筑室内图 |
| `underground` | 地下 / 洞穴图 |

> **街区层级**：街区是位于 `city` 与 `building` 之间的**可选层级**，枚举为 `street`。它既可以是城市地图的高精度局部档，也可以是独立地图文件（`parent_map` 指向所属城市）。实现见 [地图类型规格 §街区](地图类型规格_v0.1.md)。

### 2.2 网格与距离设置（`grid`）

每张地图**独立**设置网格与距离，使世界地图、城市地图、室内图各自保持合适的编辑精度（世界用公里、城市用米、室内用厘米）。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `width` | int | ✔ | 网格宽度（列数，单位：格） |
| `height` | int | ✔ | 网格高度（行数，单位：格） |
| `cell_distance` | number | ✔ | **单格物理距离**，支持任意小数（如 `1.32`），不限于整数 |
| `distance_unit` | string | ✔ | 距离单位（开放取值）：`km`/`m`/`cm`/`mm`/`mile`/`ft`/`里`/`丈`/`尺` 或自定义 |
| `base_unit` | string | ✔ | **内部基础单位**（换算基准，如 `m`）；一切长度内部先归一到该单位再计算 |
| `height_unit` | string | | 高度单位（如 `m`/`km`/`cm`）；缺省与 `base_unit` 一致 |
| `origin` | object | | 坐标原点 `{x, y}`，默认 `{x: 0, y: 0}` |
| `show` | bool | | 是否显示网格，默认 `true` |
| `snap` | bool | | 是否吸附到网格，默认 `true` |
| `scale_label` | string | | 比例尺显示文本，如 `1 格 = 1.32 km`；缺省由 `cell_distance` + `distance_unit` 生成 |

**按地图类型的推荐默认值**（可逐图覆盖；技术画像见 [地图类型规格](地图类型规格_v0.1.md)）：

| 地图类型 | 网格宽×高（格） | 单格距离 | 距离单位 | 内部基础单位 |
|---|---|---|---|---|
| `world` | 512×512 或 1024×1024 | 10–50 | km | m |
| `region` | 1024×1024 | 1 | km | m |
| `city` | 1024×1024 或更大 | 1–10 | m | m |
| `city` 的街区档（`street`） | 城市地图局部 | 0.5–1 | m | m |
| `building` | 视房间尺寸而定 | 0.5–1 | m | m |
| `underground` | 视洞穴范围而定 | 1–5 | m | m |

> **数值纪律**：`cell_distance` 为浮点数；跨单位换算一律先归一到 `base_unit` 再计算，**不得**在多种单位间反复换算。
> **单格形状**：v0.1 假定单格为正方形，`cell_distance` 为边长；非正方形格（物理宽 ≠ 高）留待后续扩展。
> **大网格存储**：当网格数组超出 YAML 可承载体积时，`terrain_data` / `height_data` 可用二进制分块（`encoding: chunked`，见 §3.4）；**索引与元数据仍留在 YAML**，格式以 [二进制格式规格](二进制格式规格_v0.1.md) 为准。

### 2.3 地图级时间设置（`time`）

每张地图设置自己的**默认时间粒度**与**最小时间粒度**；进入该地图时时间轴与事件排序自动切换。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `default_granularity` | enum | ✔ | 默认时间粒度，见 §7.1 |
| `min_granularity` | enum | ✔ | 最小时间粒度（编辑下限），见 §7.1 |
| `display_format` | string | | 时间显示格式，如 `YYYY年M月D日 H时` |
| `event_sort_unit` | enum | | 事件排序单位，见 §7.1 |
| `inherit_calendar` | bool | | 是否继承工程历法（`era`），默认 `true` |
| `allow_fuzzy` | bool | | 是否允许模糊时间，默认 `true` |

**按地图类型的推荐默认值**（可逐图覆盖）：

| 地图类型 | 默认粒度 | 最小粒度 | 典型用途 |
|---|---|---|---|
| `world` | `month` | `day` | 国家兴亡、战争、王朝更替 |
| `region` | `day` | `day` | 区域冲突、灾害、迁徙 |
| `city` | `hour` | `hour` | 案件、对话、城市事件顺序 |
| `building` | `minute` | `minute` | 密室、战斗、会议 |
| `underground` | `day` | `minute` | 探索、休息、遭遇 |

### 2.10 坐标映射与锚点（`anchor` / `extent`）

多地图层级需要把「本图坐标」映射回「父图坐标」（世界 ↔ 城市 ↔ 室内），这是跨地图引用、进入/返回、小地图定位与城市标记显示的基础。**坐标系统分四层**：世界坐标（工程统一基准）→ 地图坐标（本图格）→ 网格坐标（整数格）→ 屏幕坐标（像素）；四者互转规则由本节的 `anchor` + `grid` 决定。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `parent_x`,`parent_y` | number | ✔ | 本图**原点**在父地图中的坐标（**父图格坐标**） |
| `scale` | number | | 相对父图的比例倍率（默认 `1`） |
| `rotation` | number | | 相对父图旋转角度（度，默认 `0`） |

**映射公式**（本图格坐标 → 父图格坐标）：

```
父坐标 = anchor.parent + (本图坐标 - grid.origin) × anchor.scale × grid.cell_distance(本图) / grid.cell_distance(父)
```

- 距离先归一到各自 `base_unit` 再取比值（见 §2.2），避免单位不一致。
- `rotation` 非 0 时**先旋转再平移**；具体矩阵写在实现层，YAML 只存上述四个参数。
- **`extent` 为派生值**：`{x, y, w, h}` = 本图在父图中的覆盖矩形，可由 `anchor` + 本图 `grid.width/height` 派生；显式记录便于校验与小地图定位，冲突时**以 `anchor` 为准**。
- **城市条目 `x`/`y` 与 `anchor` 的关系**：`city_refs[].x/y`（§2.5）是城市在世界（父）图上的**显示坐标**；创建城市地图时，其城市地图的 `anchor.parent_x/parent_y` 应与之一致（二者语义等价，写入时保持一致，避免双写漂移）。
- 无 `parent_map` 的顶层地图**不需要** `anchor` / `extent`。

### 2.11 世界生成参数（`generation`，可选）

每张地图可独立记录一次「世界生成」所用的参数；缺省时整张地图视为「未指定生成参数」（`MapDoc.Generation == null`），加载器在反序列化时直接得到 `null`，旧工程文件无需任何迁移。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `algorithm` | string | | `coastline_v1` | 生成算法版本号；同一种子在不同 `algorithm` 下产出**完全不同**的地图，因此必须**显式持久化**以保证「同种子可复现」跨版本/跨机器不变 |
| `seed` | int | | `0` | 随机种子（64 位整数，YAML 中以整型字面量保存） |
| `land_ratio` | number | | `0.35` | 目标陆地占比，合法区间 `[0.05, 0.80]` |
| `ruggedness` | number | | `0.5` | 地形崎岖度（噪声振幅倍率），合法区间 `[0, 1]` |
| `min_island_cells` | int | | `8` | 最小岛屿格数；生成后小于此值的孤岛会被合并到相邻地形 |
| `min_lake_cells` | int | | `6` | 最小湖泊格数；生成后小于此值的内湖会被合并到相邻地形 |
| `erosion` | int | | `1` | 海岸侵蚀步数（每步对「水-陆」边界做一次细化），合法区间 `[0, 3]`；`0` 表示不侵蚀 |

**纪律**：

- **缺省即不存在**：若整张地图未指定生成参数，YAML 中**不写 `generation:` 键**（不是写空映射或 `null`），反序列化得到 `null`。
- **算法版本与种子绑定**：`algorithm` 一旦变化，旧种子产出的地图**不应**被解释为新算法下的同一种子；存盘时永远带上 `algorithm` 才能让「同种子可复现」承诺成立。
- **细化参数分离**：海岸细化（`erosion`）的步数与崎岖度（`ruggedness`）是**两个独立旋钮**——前者是「先粗后细」里的细化阶段，后者是噪声振幅；不要为了「少一个字段」把它们合并。
- **范围校验由 `GenerationLimits` 集中维护**：见 [总体设计 §3](总体设计_v0.1.md) 与 `scripts/Domain/Generation/GenerationLimits.cs`；越界时 `DescribeViolation` 返回中文描述，UI 弹窗展示。

**YAML 示例**（写入示例工程时使用）：

```yaml
# 出现在 maps/world/world_kael.yaml（或其他地图文件）的顶层，
# 与 terrain_data / layers 同级。
generation:
  algorithm: coastline_v1
  seed: 14631366567179368864        # 64 位种子（示例值）
  land_ratio: 0.42
  ruggedness: 0.6
  min_island_cells: 12
  min_lake_cells: 9
  erosion: 2
```

## 3. 地形（Terrain）

### 3.1 地形类型（`terrain_type` 枚举）

山、森林、平原、丘陵、水域、沙漠、沼泽、冻原、盆地、海岸、河流。

> 枚举值（英文键）：`mountain` / `forest` / `plain` / `hill` / `water` / `desert` / `swamp` / `tundra` / `basin` / `coast` / `river`。

### 3.2 地形单元（Terrain Cell）

每个网格单元包含：

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | enum | 地形类型（§3.1） |
| `height` | number | 高度值（单位取自地图 `grid.height_unit`，见 §2.2）或高度层级（`height_level`，二者取一，按地图配置） |
| `move_cost` | number | 通行成本；`-1` 表示不可通行（如深水、断崖） |
| `resources` | array<string> | 资源标签，如 `iron`/`timber`/`fertile`/`crystal` |
| `buildable` | bool | 是否可建造 |

### 3.3 高度图（Height Data）

- `min` / `max` 描述值域；单位由地图 `grid.height_unit` 统一规定（见 §2.2），不在高度数据内重复声明。
- 高度用于：生成山脉、河流走向、气候带、疆界贴合（见 [图层系统规格](图层系统规格_v0.1.md) §贴合）。
- 大网格数据**不内嵌在地图 YAML 中**，用 `cells_ref` 指向独立文件（见 [存储与目录规范](存储与目录规范_v0.1.md) §大网格数据）；超大时用**二进制分块**（`encoding: chunked`，见 §3.5）。

### 3.4 YAML 示例（稀疏表示）

```yaml
# maps/world/main.terrain.yaml
encoding: sparse
default: { type: plain, move_cost: 1, buildable: true }
cells:
  - { x: 10, y: 12, type: mountain, height: 2400, move_cost: 4, resources: [iron], buildable: false }
  - { x: 11, y: 12, type: mountain, height: 2610, move_cost: 4, buildable: false }
  - { x: 40, y: 33, type: river, height: 120, move_cost: -1, resources: [freshwater], buildable: false }
```

### 3.5 二进制分块编码（`chunked`）

当网格数组体积超出 YAML 可承载范围（世界 / 区域地图的地形与高度），`terrain_data` / `height_data` 可用**二进制分块**：索引与元数据留在 YAML，数值落在 `.bin` 分块文件。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `encoding` | enum | ✔ | `grid` / `sparse` / `chunked` |
| `chunk_size` | int | `chunked` 时必填 | 每块边长（默认 `64`，即 64×64 格；可配置） |
| `chunk_dir` | ref | `chunked` 时必填 | 块文件目录（相对工程根），如 `maps/world/main.terrain.chunks/` |
| `chunk_index` | array<object> | `chunked` 时必填 | 块索引：`{cx, cy, ref, crc32, dtype}`；`cx`/`cy` 为块坐标，`ref` 为块文件相对路径 |
| `dtype` | enum | `chunked` 时必填 | 单元数据类型：`u8` / `i16` / `u16` / `f32`（地形类型用整型，高度用浮点） |
| `default` | object | | 默认单元（语义同 `sparse`），用于未列出的块/单元 |

**约束**：

- **「索引在 YAML、数据在二进制、声明可校验」**：`chunk_index`/`chunk_size`/`dtype`/`default` 永远留在 YAML；二进制块**只承载原始数值，不承载任何语义配置**（详见 [总体设计 §3](总体设计_v0.1.md) 原则 3 例外条款）。
- 块内单元顺序、文件头、字节序（统一 **little-endian**）、坐标→块映射与校验，以 [二进制格式规格](二进制格式规格_v0.1.md) 为准。
- 校验器须验证：`chunk_index` 覆盖完整（无缺块/重叠）、`crc32` 一致、块文件可达（见 [存储与目录规范 §7](存储与目录规范_v0.1.md)）。

## 5. 人物（Character）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✔ | 稳定 ID |
| `name` | string | ✔ | 姓名 |
| `aliases` | array<string> | | 别名/绰号 |
| `gender` | string | | 性别（开放取值） |
| `age` | int | | 年龄（展示用；随时间轴回放应以 `birth_time` 计算） |
| `birth_time` / `death_time` | object | | 出生/死亡时间；`death_time` 为空表示存活 |
| `faction` | id | | 所属势力 |
| `residence` | object | | 居住地，见 §5.2 |
| `personality` | object | | 性格倾向，见 §5.1 |
| `appearance` | string | | 外貌描述 |
| `background` | string | | 背景故事 |
| `relations` | array<Relation> | | 关系网 |
| `custom_attributes` | map<string, AttributeValue> | | 自定义属性，见 §5.3 |
| `event_refs` | array<id> | | 参与过的事件（可由事件反向维护，见说明） |

> **派生 vs 存储**：`event_refs` 与 `relations` 的对方侧为**派生数据**，实现时可由事件/关系文件索引反向构建，避免双写不一致。是否落盘由存储层决定（见存储规范 §引用校验）。

### 5.1 性格倾向（Personality）

`traits` 为**可自定义标签数组**（开放枚举），例如 `honest`/`greedy`/`loyal`/`cruel`/`cautious`。工具不预置封闭枚举，允许用户自定义并复用。

```yaml
personality:
  traits: [loyal, hot_headed, generous]
  notes: 重义气，但易冲动
```

### 5.2 居住地（Residence）

地点引用采用**多粒度**（与事件地点一致，见 §6.1）：

```yaml
residence:
  map_ref: maps/city/port_aurora.yaml   # 城市地图
  building_ref: bld_tavern_03           # 建筑（可选）
  x: 120                                # 坐标（可选，城市地图内）
  y: 88
```

### 5.3 自定义属性与属性模板（Attribute Template）

属性名**可自定义**（HP、MP、力量、智力、声望、好感度……）。每个属性由「属性模板」定义类型与约束。

**属性模板（AttributeTemplate）字段**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `key` | string | 稳定键，如 `hp` |
| `label` | string | 显示名，如 `HP` |
| `type` | enum | `number` / `text` / `enum` / `bool` |
| `default` | any | 默认值 |
| `min` / `max` | number | 数值类型的最小/最大值 |
| `unit` | string | 单位，如 `点`/`%` |
| `options` | array<string> | 仅 `enum` 类型：可选值 |
| `scope` | enum | `character`（人物属性）/ `event`（事件属性），见 §6 自定义属性 |

**属性值（AttributeValue）**：

- `number` → 数值
- `text` → 字符串
- `enum` → 取自 `options`
- `bool` → 布尔

**修改来源**：事件结果可修改人物属性（见 §6.3 `effects`），修改记录到时间轴的差异序列中，回放时按时间重演。

### 5.4 关系（Relation）

| 字段 | 类型 | 说明 |
|---|---|---|
| `target` | id | 对方人物 ID |
| `kind` | string | 关系类型：`family`/`ally`/`enemy`/`mentor`/`disciple`/`lover`…… |
| `direction` | enum | `directed`（单向）/ `mutual`（双向）；家族/恋人通常双向 |
| `notes` | string | 备注 |
| `valid_from` / `valid_to` | object | 关系有效时间（可选，支持关系随时间变化） |

### 5.5 YAML 示例

```yaml
id: char_lin_yu
name: 林语
aliases: [阿语, 沉默的剑客]
gender: female
birth_time: { year: 1018, month: 5, day: 3 }
faction: fac_merchant_league

  map_ref: maps/city/port_aurora.yaml
  building_ref: bld_inn_07
personality:
  traits: [loyal, cautious, taciturn]
appearance: 短发，左臂有旧伤
background: 曾是佣兵，因一次背叛退隐
relations:
  - { target: char_chen_hao, kind: mentor, direction: directed }
  - { target: char_mei_er, kind: lover, direction: mutual }

  hp: { value: 120 }
  strength: { value: 14 }
  fame: { value: 35 }
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✔ | 稳定 ID |
| `title` | string | ✔ | 标题 |
| `time` | object | ✔ | **绝对时间**：`time`（TimePoint）或 `time_range`（TimeRange），二者取一，见 §7.2 |
| `time_precision` | enum | | **时间精度**：事件时间能确定的最高精度（`year`/`month`/`day`/`hour`/`minute`/`second`），见 §7.1 |

| `mid_events` | array<id> | | 中途事件列表 |
| `location` | object | ✔ | 地点（多粒度），见 §6.1 |
| `participants` | array<id> | | 参与者（人物 ID） |
| `witnesses` | array<id> | | 目击者（人物 ID） |
| `instigator` | id | | 发起者（人物 ID） |
| `description` | string | | 描述 |
| `outcome` | string | | 结果（叙事文本） |
| `effects` | array<Effect> | | **结构化影响**，见 §6.3 |
| `scope` | object | | 影响范围（地图上的区域，用于事件层显示） |
| `prev_events` / `next_events` | array<id> | | 关联的前置/后续事件（事件链） |
| `tags` | array<string> | | 标签 |
| `custom_attributes` | map<string, AttributeValue> | | 自定义属性（模板 `scope: event`） |

### 6.1 地点（Location，多粒度）

地点可指定为以下**任一**粒度（按精度从粗到细）：

| 粒度 | 字段 | 说明 |
|---|---|---|
| 世界地图坐标 | `map_ref` + `x`/`y` | 直接给世界地图坐标 |
| 城市 | `city_ref` | 城市条目 ID |
| 建筑 | `building_ref` | 建筑 ID（需同时给 `map_ref`） |
| 区域 | `region_ref` | 区域地图 ID |
| 地下层 | `map_ref`（`type: underground`） | 地下/洞穴图 |

```yaml
location:
  city_ref: city_port_aurora
  building_ref: bld_warehouse_02
  # 或：world 坐标
  # map_ref: maps/world/main.yaml
  # x: 620, y: 410
```

### 6.2 影响范围（`scope`）

描述事件在地图上的空间影响，用于事件层渲染与「事件修改疆界」类效果：

```yaml
scope:
  map_ref: maps/world/main.yaml
  shape: circle            # circle | polygon | rect
  center: { x: 620, y: 410 }
  radius: 30
```

### 6.3 结构化影响（Effect）

事件结果可修改**人物属性、势力疆界、城市归属、建筑状态、图层可见性**：

| `target_kind` | 说明 | 关键字段 |
|---|---|---|
| `character_attribute` | 修改人物自定义属性 | `target`(人物 id)、`attr`、`op`(`set`/`add`/`mul`)、`value` |
| `border` | 修改势力疆界 | `faction`、`region_patch` |
| `city_ownership` | 修改城市归属 | `city_ref`、`faction` |
| `building_state` | 修改建筑状态 | `building_ref`、`state` |
| `layer_visibility` | 修改图层可见性 | `layer`、`visible` |

```yaml
effects:
  - target_kind: character_attribute
    target: char_lin_yu
    attr: hp
    op: add
    value: -30
  - target_kind: city_ownership
    city_ref: city_port_aurora
    faction: fac_royal_navy
  - target_kind: layer_visibility
    layer: layer_curfew
    visible: true
```

> **要点**：`effects` 是**结构化**的，不是自由文本——这是时间轴能「重演」状态的根本。自由文本放 `outcome`。

### 6.4 YAML 示例

```yaml

  - target_kind: city_ownership
    city_ref: city_port_aurora
    faction: fac_royal_navy
  - target_kind: character_attribute
    target: char_lin_yu
    attr: fame
    op: add
    value: 10

  map_ref: maps/city/port_aurora.yaml
  shape: rect
  rect: { x: 80, y: 60, w: 90, h: 70 }

```

## 7. 时间轴（Timeline）

### 7.1 时间单位与粒度（Granularity）

时间单位层级（由工程历法 `era` 定义，可自定义）：**纪元 → 年 → 月 → 日 → 时 → 分 → 秒**。

**粒度枚举（`granularity`）**：`era` / `year` / `month` / `day` / `hour` / `minute` / `second`。

**时间轴缩放级别**（由远及近，相邻级别展开）：

| 缩放级别 | 主刻度 | 次刻度 |
|---|---|---|
| 最远 | 纪元 / 世纪 | 年 |
| 远 | 年 | 月 |
| 中 | 月 | 日 |
| 近 | 日 | 时 |
| 最近 | 时 | 分 |

**地图自动切换**：进入某张地图时，时间轴按该地图 `time.default_granularity` 定位（世界 →「年 / 月」，城市 →「日 / 时」，室内 →「时 / 分」，见 §2.3）。

### 7.2 时间点（TimePoint）

| 字段 | 类型 | 说明 |
|---|---|---|
| `era` | string | 纪元（跨纪元工程必填；单纪元可省略） |
| `year` | int | 年 |
| `month` | int | 月（默认 1） |
| `day` | int | 日（默认 1） |
| `hour` | int | 时（默认 0） |
| `minute` | int | 分（默认 0） |
| `second` | int | 秒（默认 0） |

**时间段（TimeRange）**：`{ from: TimePoint, to: TimePoint }`。事件挂载可任选时间点或时间段。

**时间精度与模糊时间**：

- 未填写的低位字段表示「未知」；事件以其**最高已知单位**作为 `time_precision`（如只填到年 → `year`）。
- 当 `time_precision` 粗于地图 `default_granularity` 时，该时间视为**模糊时间**（`fuzzy: true`）：展示为时间段，按该粒度分组并落在对应区间内，排序不产生虚假精度。
- **绝对时间与显示时间分离**：磁盘只存 `time`（绝对时间）；`display_time` 为可覆盖的展示文本，缺省由 `time` + 地图 `time.display_format` 派生。

### 7.3 时间轴文件（Timeline）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 时间轴 ID |
| `era_ref` | — | 引用工程 `era` |
| `default_granularity` | enum | 全局默认时间粒度（缺省 `day`）；各地图可覆盖，见 §7.1 |
| `range` | object | `{ start: TimePoint, end: TimePoint }`，时间轴覆盖范围 |
| `branches` | array<Branch> | 分支时间线（可选，P1-2），见 §7.5 |
| `snapshots` | array<Snapshot> | 快照列表，见 §7.4 |

### 7.4 快照（Snapshot）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 快照 ID |
| `time` | TimePoint | 快照对应的时刻 |
| `label` | string | 标签（如「开战前夕」） |
| `base_ref` | ref | 基准状态引用 |
| `diff_ref` | ref | 差异序列引用 |

> **不存全量**：快照 = 基准状态 + 到该时刻为止的差异序列，避免状态爆炸。详见 [时间轴系统规格](时间轴系统规格_v0.1.md)。

### 7.5 分支（Branch，可选）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 分支 ID |
| `name` | string | 分支名（如「IF：林语未背叛」） |
| `forked_at` | TimePoint | 分叉时刻 |
| `parent_branch` | id | 父分支 |
| `event_overrides` | array | 该分支下被改写的事件 |

### 7.6 YAML 示例

```yaml
id: timeline_main
default_granularity: day
range:
  start: { year: 1000, month: 1, day: 1 }
  end:   { year: 1100, month: 12, day: 30 }

snapshots:
  - id: snap_before_riot
    time: { year: 1042, month: 3, day: 11, hour: 20 }
    label: 暴动前夕
    base_ref: timeline/base_1040.yaml
    diff_ref: timeline/diff/snap_before_riot.yaml

branches:
  - id: br_if_lin_stays
    name: "IF：林语未离开佣兵团"
    forked_at: { year: 1038, month: 7, day: 20 }
    parent_branch: main
```

## 8. 载具（Vehicle）

载具是独立对象，可被事件、人物、势力、运输任务引用，也可跨地图引用（用「当前所在地图 + 坐标」表示）。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✔ | 稳定 ID |
| `name` | string | ✔ | 显示名 |
| `type` | enum | ✔ | 载具大类，见 §8.1 |
| `subtype` | string | | 子类型（开放）：`horse`/`carriage`/`sail_ship`/`airship`/`dragon`… |
| `owner` | id | | 所属势力或所有者（势力 id / 人物 id） |
| `driver` | id | | 驾驶者（人物 id） |
| `crew` | array<id> | | 乘员列表（人物 id） |
| `speed` | object | | 速度参数，见 §8.2 |
| `capacity` | object | | 运输能力，见 §8.3 |
| `rest_rule` | object | | 休息规则，见 §8.4 |
| `consumption` | object | | 消耗：`{food, water, fuel, magic}`（按单位时间或距离） |
| `status` | enum | | `idle`（空闲）/`moving`（行进中）/`resting`（休息中）/`damaged`（损坏）/`missing`（失踪） |
| `map_ref` | ref | | 当前所在地图 |
| `x`,`y` | number | | 当前坐标（格） |
| `icon` | ref | | 地图图标资源（可选；呈现用） |
| `notes` | string | | 备注 |
| `custom_attributes` | map<string, AttributeValue> | | 自定义属性 |

### 8.1 载具类型（`type` 枚举）

| 值 | 含义 | 子类型示例（开放） |
|---|---|---|
| `land` | 陆行 | 马、马车、牛车、商队、骑兵、步行 |
| `air` | 飞行 | 飞艇、狮鹫、龙、飞行器、魔法飞毯 |
| `water` | 水上 | 帆船、桨帆船、商船、渔船、潜艇 |
| `underground` | 地下 | 矿车、地下船、隧道车 |
| `teleport` | 传送 | 固定传送阵、单向门、秘境入口 |
| `special` | 特殊 | 载人轿、雪橇、沙漠舟 |

### 8.2 速度（`speed`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `base` | number | 基础速度 |
| `unit` | string | 速度单位：`km/h`/`km/day`/`cell/h`/`cell/day`/`m/min` 或自定义 |
| `max` | number | 最大速度 |
| `cruise` | number | 巡航速度 |
| `accel_time` | number | 加速时间 |
| `terrain_factor` | number \| map | 地形影响系数（单值，或按地形类型的系数表） |

> 速度单位与地图距离单位（`grid.distance_unit` / `grid.base_unit`）自动换算；跨地图计算先归一到统一基础单位。

### 8.3 运输能力（`capacity`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `max_passengers` | int | 最大载人数 |
| `comfort_passengers` | int | 舒适载人数 |
| `max_cargo` | number | 最大载货量 |
| `cargo_unit` | string | 载货单位：`kg`/`t`/`box`/`unit` 或自定义 |
| `max_load` | number | 最大载重 |
| `requirements` | array<string> | 特殊限制：`road`/`water`/`magic`…… |
| `min_drivers` | int | 最低驾驶人数 |
| `min_guards` | int | 护卫人数 |

### 8.4 休息规则（`rest_rule`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `max_continuous` | number | 连续行进上限（小时） |
| `rest_duration` | number | 单次休息时长（小时） |
| `max_daily_travel` | number | 每日最大行进时长（小时） |
| `daily_forced_rest` | number | 每日强制休息时长（小时） |
| `fatigue_penalty` | number | 疲劳惩罚：超过连续上限后的速度下降系数 `[待标定]` |
| `night_travel` | bool | 夜间是否行进 |
| `terrain_rest_effect` | string \| number | 地形对休息的影响 |
| `weather_rest_effect` | string \| number | 天气对休息的影响 |

### 8.5 YAML 示例

```yaml
id: veh_merchant_cart_01
name: 商会货车一号
type: land
subtype: carriage
owner: fac_merchant_league
driver: char_lin_yu
crew: [char_chen_hao]
speed:
  base: 30
  unit: km/day
  max: 40
  cruise: 30
  accel_time: 0.5
  terrain_factor: 0.7      # 山地等恶劣地形减速

  max_passengers: 2
  comfort_passengers: 2
  max_cargo: 500
  cargo_unit: kg
  max_load: 800
  requirements: [road]

  min_guards: 1

  max_continuous: 4
  rest_duration: 1
  max_daily_travel: 10
  daily_forced_rest: 8
  fatigue_penalty: 0.6
  night_travel: false

y: 410
```

### 9.1 各类型路线规则

| 类型 | 寻路依据 | 专属参数（`params`） |
|---|---|---|
| `land` 陆上 | 沿道路层（`follow_road`）；无道路时按地形 `move_cost` | 途经驿站/关隘/桥梁 |
| `air` 飞行 | 两点直线或折线航点 | `altitude`（高度）、`range`（续航）、`landing_points`（降落点） |

## 10. 运输任务（TransportTask）

运输任务 = 载具 + 路线 + 时间预估，并可与事件、人物、势力联动。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✔ | 稳定 ID |
| `name` | string | ✔ | 名称 |
| `vehicle_ref` | id | ✔ | 载具（见 §8） |
| `from` / `to` | object | ✔ | 出发地/目的地（地点多粒度引用，见 §6.1） |
| `route_ref` | id | | 路线（见 §9） |
| `route_type` | enum | | `land`/`air`/`water`/`underground`/`teleport` |
| `depart_time` | object | | 出发时间（TimePoint） |
| `arrive_time` | object | | 到达时间（TimePoint） |
| `total_distance` | number | | 总距离 |
| `total_duration` | object | | 总耗时 `{days, hours, minutes}` |
| `rest_count` | int | | 休息次数 |
| `mid_events` | array<id> | | 中途事件列表（事件 id） |
| `characters` | array<id> | | 关联人物 |
| `faction` | id | | 关联势力 |
| `event_ref` | id | | 对应的运输事件（见 §6） |
| `status` | enum | | `planned`（计划中）/`in_transit`（运输中）/`arrived`（已到达）/`cancelled`（取消） |

### 10.1 时间计算规则

```
总时间 = 纯行进时间 + 休息时间 + 特殊等待时间
纯行进时间 = 总距离 ÷ 实际速度
实际速度 = 基础速度 × 地形系数 × 天气系数 × 载重系数 × 疲劳系数
```

- **距离**：来自地图 `grid`（世界按公里、城市按米、室内按米/厘米）；跨地图先归一到 `base_unit` 再累加。
- **休息点**：按 `rest_rule` 自动插入（连续行进上限、每日最大行进、强制休息、夜间规则）。
- **时间输出**：结果精确到 年/月/日/时/分，并与全局时间轴联动（出发/到达/中途时间点）。
- **中途事件**：出发、经过驿站、休息、遭遇袭击、天气变化、载具损坏、到达等，自动或手动插入并挂到时间轴，可关联人物/势力/地图坐标。

> 时间计算为**纯逻辑**（领域层），可脱离 UI 单测；系数与阈值一律可配置、标注 `[待标定]`。

### 10.2 YAML 示例

```yaml
id: task_silk_road_01
name: 极光港 → 王都 商队运输
vehicle_ref: veh_merchant_cart_01
from: { city_ref: city_port_aurora }
to:   { map_ref: maps/world/main.yaml, x: 300, y: 200 }
route_ref: route_silk_01
route_type: land
depart_time: { year: 1042, month: 4, day: 1, hour: 8 }
arrive_time: { year: 1042, month: 4, day: 11, hour: 14 }
total_distance: 240
total_duration: { days: 10, hours: 6, minutes: 30 }
rest_count: 8
mid_events: [evt_depart, evt_rest_camp, evt_bandit_ambush, evt_arrive]
characters: [char_lin_yu]
faction: fac_merchant_league
event_ref: evt_transport_01
status: planned
```
