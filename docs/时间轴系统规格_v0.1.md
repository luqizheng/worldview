# 时间轴系统规格 v0.1

> 时间轴是 World View 的「骨」。它把地理、人物、事件串成可回放的历史。
> 时间数据字段以 [数据模型规格 §7](数据模型规格_v0.1.md) 为唯一真源。

---

## 1. 时间刻度与粒度

层级：**纪元 → 年 → 月 → 日 → 时 → 分 → 秒**。

- 纪元定义在**工程**的 `era` 字段（`name` / `start_year` / `months_per_year` / `days_per_month[]` / `hours_per_day` / `minutes_per_hour` / `seconds_per_minute` / `leap`），全工程共用。
- 支持**不规则历法**：`days_per_month` 为数组，每月天数可不同；亦支持奇幻历法（如 1 年 10 月、1 月 40 天、1 天 30 时）。
- 统一用**绝对时间**表示：`{year, month, day, hour, minute, second}`，不用相对表达。
- **粒度枚举（`granularity`）**：`era` / `year` / `month` / `day` / `hour` / `minute` / `second`。

### 1.1 多粒度与地图级默认粒度

- 时间轴支持从「年」缩放到「分」；相邻级别展开：年/月 → 月/日 → 日/时 → 时/分。
- 每张地图在 `time.default_granularity` / `min_granularity` 声明自己的默认与最小粒度；**进入某张地图时时间轴自动定位**到该粒度。推荐：

| 地图类型 | 默认粒度 | 最小粒度 |
|---|---|---|
| `world` | `month` | `day` |
| `region` | `day` | `day` |
| `city` | `hour` | `hour` |
| `building` | `minute` | `minute` |
| `underground` | `day` | `minute` |

### 1.2 模糊时间与显示分离

- 事件时间可只精确到年或月；未填写的低位字段表示「未知」，以其**最高已知单位**为 `time_precision`。
- 精度粗于地图默认粒度时标记为**模糊时间**（`fuzzy: true`），展示为区间，排序落在该粒度内，不产生虚假精度。
- **存储绝对时间、显示分离**：磁盘只存 `time`；`display_time` 为可覆盖的展示文本，缺省按地图 `time.display_format` 派生。

## 2. 事件挂载

事件可通过两种方式挂载到时间轴：

| 方式 | 字段 | 说明 |
|---|---|---|
| 时间点 | `time` | 精确到某一时刻（`{year, month, day, hour, minute, second}`） |
| 时间段 | `time_range` | `{from, to}`，用于持续事件（战争、瘟疫、工程建设） |

**挂载规则**：

- `time` 与 `time_range` 二者取一，不得同时出现。
- 事件可标注 `time_precision` / `time_granularity` / `fuzzy` / `display_time` / `time_system_map`（见 [数据模型规格 §6](数据模型规格_v0.1.md)）；展示按所属地图粒度格式化，世界地图事件可只精确到年/月（模糊时间）。
- 时间段事件在回放时，只要「当前时刻 ∈ [from, to]」，就视为**进行中**。
- 事件的 `prev_events` / `next_events` 形成**事件链**，时间轴不强制链条时序（允许倒叙/伏笔），但会校验并提示时序矛盾。

### 2.1 运输任务与中途事件挂载

运输任务（见 [数据模型规格 §10](数据模型规格_v0.1.md)）计算出的**出发时间 / 到达时间 / 各中途时间点**都挂到同一全局时间轴：

- 运输任务给出 `depart_time` / `arrive_time`；若任务对应一个运输事件（`Event.is_transport = true`），二者写入事件的 `depart_time` / `arrive_time`。
- **中途事件**（出发、经过驿站、休息、遭遇袭击、天气变化、载具损坏、到达等）自动或手动生成，每个中途事件带自己的 `time`，通过 `mid_events` 挂在任务下，并作为普通事件出现在时间轴上（可关联人物/势力/地图坐标）。
- 运输任务的时间**存储为绝对时间**；展示按当前地图 `time.default_granularity`（世界地图按日/月/年、城市地图按小时、室内按分钟）。
- **回放**：拖动时间轴，运输任务按出发/到达/中途时间点分段呈现「在途状态」（载具 `status` 可由中途事件 `effects` 改变）。

## 3. 时间轴浏览与回放

### 3.1 交互

主界面顶栏提供**时间轴滑块** + 时间显示：

- 拖动滑块 → 当前时刻改变 → 地图随之更新。
- 支持跳转（输入具体时间）、步进（按当前地图粒度：上一月/上一天/上一小时）、**播放 / 暂停 / 倒放**（自动推进/回退，速率 `[待标定]`）。
- 支持**跳转关键时间点**：一键跳到某事件时刻或某快照时刻。
- 时间轴随当前地图粒度缩放（见 §1.1）；进入地图时自动定位到该地图 `time.default_granularity`。

### 3.2 回放时变化的对象

拖动滑块时，以下内容**随时间变化**：

| 对象 | 变化依据 |
|---|---|
| 图层可见性 | 图层的 `valid_from` / `valid_to` 与当前时刻求交（见 [图层系统规格 §1](图层系统规格_v0.1.md)） |
| 疆界 | 疆界图层的多边形带有效时间；历史事件的 `effects`（`border`）改变疆界 |
| 影响力 | 影响力图层的有效时间与事件修改 |
| 事件点 | 只显示「当前时刻已发生」（`time <= now` 或进行中）的事件 |
| 城市归属 | `city_refs[].faction` 随事件 `effects`（`city_ownership`）变化 |
| 城市人口 | 随事件与时间变化 |
| 人物状态 | 生卒（`birth_time`/`death_time`）+ 属性被事件 `effects` 修改 |
| 建筑状态 | 建筑 `state` 随事件 `effects`（`building_state`）变化 |
| 运输任务/载具 | 按 `depart_time` / `arrive_time` / 中途时间点分段呈现；载具 `status`（空闲/行进中/休息中/损坏/失踪）由运输事件与中途事件的 `effects` 改变 |

### 3.3 重建模型（关键设计）

**不保存每个时刻的完整状态**（会状态爆炸）。采用：

```
基准状态（base）            ：工程创建时的初始世界
        +
差异序列（diff events）    ：按时间排序的全部事件及其 effects
        ↓
在内存中把 now 之前的所有 effects 依次重演
        ↓
得到「当前时刻」的世界视图（只读）
```

**要点**：

- 回放是**只读重建**，不回写磁盘上的基准世界。用户在回放态若要修改，须显式「在此刻登记新事件」。
- 差异序列**按时间排序**，同一时刻的多个事件需定义**稳定排序**（建议：先按 `time`，再按 `id`），否则回放结果不确定。
- 派生字段（如由 `birth_time` 计算的年龄）在重建时计算，不落盘。

## 4. 历史状态

「历史状态」= 上述重建视图在查询某时刻时的快照结果。支持查询：

- 某时刻的人物状态（属性值、生死、所属势力、居住地）
- 某时刻的势力范围（疆界多边形）
- 某时刻的城市人口与归属
- 某时刻的建筑状态

**查询接口约定**（领域层，技术中立）：

```
stateAt(world, timePoint) -> WorldView
```

- 纯函数、无副作用；相同输入必然相同输出（确定性）。
- 实现必须能脱离 UI 单测。

## 5. 快照

快照用于**关键时间点的对比**与**性能优化**（避免每次都从基准重演）。

| 字段 | 说明 |
|---|---|
| `id` / `label` | 标识与标签 |
| `time` | 快照时刻 |
| `base_ref` | 基准状态引用 |
| `diff_ref` | 该时刻为止的差异序列引用 |

**语义**：快照 = `base_ref` + `diff_ref`，**仍不存全量状态**。快照是「加速重演的检查点」，不是「一份完整世界副本」。

对比能力：选取两个快照 → **差异视图**（疆界变了哪些、城市归属变了哪些、人物属性变化），成对展示同一地图在不同时期的状态。

> 回放控制（播放/暂停/倒放/跳转关键时间点）见 §3.1；呈现模式（编辑/预览/回放/演示）见 [地图编辑器规格 §7](地图编辑器规格_v0.1.md)。

## 6. 分支时间线（可选，P1-2）

用于平行世界、IF 线、多结局。

| 字段 | 说明 |
|---|---|
| `id` / `name` | 分支标识与名称 |
| `forked_at` | 分叉时刻 |
| `parent_branch` | 父分支 |
| `event_overrides` | 该分支下被改写/忽略的事件 |

**规则**：

- 分支从 `forked_at` 时刻起**独立演化**：该时刻之后的差异序列可能与父分支不同。
- 重建时沿 `parent_branch` 链回溯到分叉点，再叠加本分支差异。
- **v0.1 默认不实现**（P1-2）。设计上预留字段，实现需明确授权。

## 7. 校验规则

时间轴相关的**引用与一致性校验**（保存工程时执行）：

- [ ] 所有事件的时间落在时间轴 `range` 内。
- [ ] `time_range.from <= to`。
- [ ] 事件引用的地点/人物/建筑 ID 存在。
- [ ] 同刻事件排序稳定（按 `time` + `id`）。
- [ ] 事件链无环（`prev_events`/`next_events` 不构成循环引用；若刻意设计循环需显式标记）。
- [ ] 快照的 `time` 落在 `range` 内，且引用的 `base_ref`/`diff_ref` 存在。
- [ ] 运输任务 `depart_time <= arrive_time`；`mid_events` 引用的都是存在的事件；中途事件时间落在 `[depart_time, arrive_time]` 内。
