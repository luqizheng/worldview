## 1. 背景与边界

### 1.1 为什么借鉴

本仓《美术资源规范 v0.1》已定义 **What**（资源规格、命名、生成器），缺 **Why**（视觉总纲、风格定位、拒绝清单）和 **Check**（合规审计）。CCGS 的三个 skill 恰好补齐这两环：

| CCGS skill | 本仓对应物 | 落地形态 |
|---|---|---|
| `/art-bible`（视觉总纲） | 《美术资源规范》§1 加风格定位 + 拒绝清单 | **本文 §3** + 编辑《美术资源规范》§1 |
| `/asset-spec`（按资产生成 spec） | 《美术资源规范》§3-§7 已经是 spec | **无需新增**（已覆盖） |
| `/asset-audit`（合规审计） | 缺失 | **新建**《美术资源审计清单》`docs/美术资源审计清单_v0.1.md` |
| `art-director` agent | 文档级的「视觉守护者」角色 | **本文 §2** 角色清单 |
| `technical-artist` agent | `scripts/Editor/TileSetLoader.cs` + `_tools/make_tiles.py` 已是该角色代码 | **无需新增** |

### 1.2 为什么不全盘照搬

| 维度 | CCGS | 本仓 |
|---|---|---|
| 运行时 | Claude Code CLI + subagent + hook | DeepSeek Harness 工作流 + MCP 工具 |
| 协作机制 | `AskUserQuestion` × N 轮 + Write per-section | AGENTS.md §8「简洁直接、问最少」 |
| 真源 | `project.yaml` | 《数据模型规格 v0.1》 |
| 美术产物形态 | 游戏运行资源（PNG/VFX/shader） | 世界构建工具的**示例资源 + Theme** |
| 主受众 | 游戏开发工作室 | TRPG / 小说作者 / 世界观构建者 |

直接 `git clone` 会污染本仓布局；CCGS 的多轮交互流程与 DSH 的中文简洁纪律冲突。**借鉴方法论，保留工具栈独立性**。

## 2. 美术三层角色清单（角色文件层面）

CCGS 是 `art-director → technical-artist / ux-designer / prototyper` 四级。本仓是工具不是游戏，降维成**文档级角色**，每个角色落到一个文件 + 一个执行点：

| 角色 | 守护文件 | 执行点 |
|---|---|---|
| **art-director（视觉守护者）** | `docs/美术资源规范_v0.1.md` | 该文档的 §1 设计原则 + §4.4 UI 主题色 + 拒绝清单（本轮 §3 加） |
| **technical-artist（资产管道）** | `_tools/make_tiles.py` + `_tools/make_marker_icons.py` + `scripts/Editor/TileSetLoader.cs` | TileSet 加载、atlas 生成、`.png.import` 落盘 |
| **ux-designer（界面守护者）** | `docs/界面与交互规格_v0.1.md` + `scenes/Main.tscn` + `scripts/Ui/**/*.cs` | 主界面 / Inspector / BottomPalette / ProjectChrome |
| **prototyper（实验田）** | `_tools/make_marker_icons.py`（独立生成 PNG，不污染运行资源） | 一次性脚本输出，不进运行资产 |

执行点解释：
- art-director 的「守护」= 任何视觉相关 PR 必须引用 §1/§4.4 并自检拒绝清单；
- technical-artist 的「执行」= atlas / Theme 改完后必须跑《美术资源审计清单》全勾；
- ux-designer 的「执行」= UI 改完后必须能经 `mcp__wincu__windows_computer_use_snapshot` 截图复检；
- prototyper 的「执行」= 新美术实验先在 `_tools/` 出 PNG，**不直接写** `examples/sample_world/assets/`。

## 3. 风格定位 + 拒绝清单（落《美术资源规范》§1）

直接追加在 `docs/美术资源规范_v0.1.md` §1 表格之后：

### 3.1 风格定位

- **目标受众**：TRPG 主持人 / 小说作者 / 世界观构建者——气质偏「羊皮卷 + 工坊」，**不**做软件渲染写实风、不做赛博朋克霓虹、不做 3D 写实渲染
- **核心隐喻**：羊皮纸 + 像素风 = 「手工绘制的世界」——视觉强度低、信息密度高、长时间编辑不疲劳
- **默认风格 ID**：`jrpg`（16×16 像素，已在 `assets/textures/tiles/styles.yaml:2` 登记）
- **变体预留**：`_fallback_solid_color`（无资产时的纯色兜底）；后续可加 `crpg_24`、`realistic_64` 等……v0.1 不实现

#### 3.1.1 三套内容美术风格（v0.1 增补，与 `theme` 正交）

> 字段定义、示例、Map 类型默认值：[数据模型规格 §2.8/§2.9](数据模型规格_v0.1.md)；编辑器交互与三套资源状态：[地图编辑器规格 §7.2.1](地图编辑器规格_v0.1.md)；资源契约 / Palette 文件 / 待办：[美术资源规范 §1.1/§2/§4.3/§8.2](美术资源规范_v0.1.md)。
> **本轮 JRPG 优先**——`western_fantasy` / `ink_wash` 只挂画像 + YAML 占位 + 骨架 Palette，资源 / 色值标定 / 拒绝清单 / 审计增量 全部推迟到 T-ART-7 / T-ART-8 / T-ART-9 / T-ART-12。

| ID | 气质 | 建筑 | 地形 | 地标 | 室内陈设 |
|---|---|---|---|---|---|
| **`jrpg`**（默认/已实装） | 童趣、冒险、轻量化；TRPG 即开即玩感 | 茅草顶木屋、石顶房、城堡塔尖；16×16 marker + 64×64 主瓦片 | 像素色块 + 8×8 dot stipple + 2px 描边；`jrpg_palette.yaml` 色系（11 terrain + 7 marker + 4 ui 内容层 + 4 accent = 26 hex，2026-10-09 落地）；视觉契约见 [美术资源规范 §4.8](美术资源规范_v0.1.md) | 城堡主塔+红城旗、遗迹残柱、传送门蓝紫光晕（**光晕 2px 渐变是唯一破例**，符合魔法粒子质感；其余禁渐变） | 简单俯视 TileMap；木质家具简化描边；室内陈设契约见 [美术资源规范 §4.8.5](美术资源规范_v0.1.md) |
| `western_fantasy`（v0.1 占位） | 厚重史诗、严肃奇幻；中世纪油画 + 工坊插画；**不**走 3D 写实 / CG / 霓虹 | 石砌城堡（锯齿城垛 + 飘旗）、半木结构民居（Fachwerk）、哥特式教堂（尖拱+玫瑰窗轮廓）、塔楼与要塞；屋顶**斜面分层**区分 | 写实色阶过渡 + **柔和**等高线阴影；海岸线细白沫边；植被以色块为主 | 城堡=多塔剪影+飘旗；神庙=尖拱立面+日轮徽；遗迹=断柱+攀藤 | 俯视+木质地板纹理；家具**带材质暗示**（木桌=赭黄+木纹条、铁炉=深灰+火光） |
| `ink_wash`（v0.1 占位） | 留白、写意、远观；宋元山水 + 工笔白描；**不**走重彩、不走工笔重描 | 飞檐翘角（微翘即可，不堆装饰）、白墙黛瓦（灰阶三档）、木构廊桥、塔与楼阁（层檐清晰）；轮廓优先、填色次之 | **大面积留白** + 墨韵渐变（单色从浓到淡的呼吸感）；山以**皴法暗示**（几笔斜线+墨点）；水域**留纸白+等亮**而非蓝绿 | 塔=层檐+铃铎；寺=山门+碑；遗迹=残塔+古柏；关键辨识特征是飞檐弧线与留白比例 | 极简：一案一榻一屏；**木纹**用单色横纹（1px）暗示；**禁**繁复家具堆叠 |

**三套共性**：共享 `Marker.icon` 帧名（7 帧：village / town / capital / ruin_site / quest_marker / portal_arch / faction_marker）；共享 TileSet 像素契约（`TileSize = (64, 64)`，`TextureRegionSize = (64, 64)`）；共享 UI 主题 `parchment_theme.tres`（**2026-10-09 收敛**：Dark.tres 已下线,项目仅 1 套主题）——**与 `Map.presentation.theme` 正交**，可任意组合（如「parchment UI + ink_wash 内容」）。

**未知 ID / placeholder 退化**：用户选了 `western_fantasy` / `ink_wash` 但对应资源未交付（`styles.yaml` 中 `path: _placeholder`），走 `TileSetRegistry` 既有 fallback（退 `jrpg` + 纯色块），不抛错；`art_style: jrpg` 等价于旧行为，回归风险 ≈ 0。

### 3.2 拒绝清单

> 任何美术资源 / Theme / UI 控件若触犯下列任一条，须改回或显式标注 `[已知违反：原因]`，不得静默放过。

| # | 拒绝项 | 理由 |
|---|---|---|
| 1 | 渐变（除单像素抗锯齿过渡外） | 像素风一致性 |
| 2 | drop-shadow blur > 2px | 风格统一 + 性能 |
| 3 | 字号 < 10px（accessibility floor） | WCAG / 中文可读性 |
| 4 | 红色滥用（仅作强调/危险态，正文用深褐） | 与羊皮底 `#f4f0e4` 对比过强，长时间阅读疲劳 |
| 5 | 单一图标尺寸 > 32px（在画布上） | 破坏「地图优先」视觉层级（见《界面与交互规格》§1） |
| 6 | mipmap 自动生成 | `process/mipmaps/generate = false`（《美术资源规范》§5，硬约束） |
| 7 | 不写 `.png.import` 直接放 PNG | Godot 4 找不到 `.import` 会自动重建，uid 漂移 |
| 8 | 大于 1KB 的元数据落二进制 | 违反「YAML 为主格式」（AGENTS.md §2 原则 3） |
| 9 | 同一资产出现两个主题色版本 | 单一主题变量驱动，色值只允许来自 `parchment_palette.yaml` |
| 10 | `BottomPalette` / `DockLayout` / `ProjectChrome` 控件超过 3 层 Container 嵌套 | UI 重设计 W1–W4 已收敛嵌套深度 |

## 5. 与本仓纪律的兼容性自检
