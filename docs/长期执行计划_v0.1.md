# World View 长期执行计划 v0.1

> 本文是**给 AI 长期执行用的路线图**：跨多次会话、跨多轮模型，逐步推进到 v0.1 完整交付。
> 设计真源不变：数据结构以《数据模型规格》为唯一真源，本计划**只编排做什么、按什么顺序、怎么验收**，不重新定义任何字段。
> 阅读本文件前先读根 [AGENTS.md](../AGENTS.md)（原则 / 待决项 / 文档索引 / 外部依赖）。
> 本文件自身也是设计文档：改计划先升版本号，在 §12 变更记录追加一行，不原地覆盖语义。

## 0. 计划的执行方式（AI 长期执行协议）

本节是本文件的核心。任何 AI 会话执行本计划前，必须先走完本节。

### 0.1 会话启动序列（每次会话固定执行，顺序不可换）

1. 读根 [AGENTS.md](../AGENTS.md)（永远先读，§3 待决项与 §6 当前进度是硬约束）。
2. 读本文件 §1「当前基线快照」与 §5「工作项总表」，确定**唯一当前活跃项**（`ST` 状态 = `active` 的那一行）。
3. 读该活跃项对应的设计规格章节（§5 工作项表列出了「必读文档」列）。
4. 若该活跃项已有 spec / plan：读 spec → 读 plan → 按 plan 的任务推进（见 §0.4）。
5. 若该活跃项**没有** spec / plan：先按 §0.3 走「规格化门」，不得直接写生产代码。
6. 执行前跑一次基线自检（§0.5），确认基线是绿的；基线红先修基线。

### 0.2 状态机（每个工作项只允许一种状态）

| 状态 | 含义 | 允许的下一步 |
|---|---|---|
| `backlog` | 已登记，未开始 | → `spec`（仅当前里程碑内且前序项全绿） |
| `spec` | 正在写设计 spec | → `planned`（spec 通过 §0.3 规格化门） |
| `planned` | spec + plan 齐备，未开工 | → `active` |
| `active` | 正在实现 | → `verify`（plan 全任务完成且自测绿） |
| `verify` | 验收中（自动化 + 人工 demo） | → `done` / → `active`（验收打回） |
| `done` | 验收通过，已回写文档 | 无（只可被 `reopen`） |
| `blocked` | 被外部条件卡住 | → 前一状态（条件解除） |
| `reopen` | 验收后发现回归 | → `active` |

**铁律**：

- **同一时刻最多一个 `active` 项。** 遇到必须并行的依赖（如文档回写），作为同一项的子任务，不开第二个 `active`。
- 状态推进只能在本计划 §5 的表里改（改 `ST` 列 + 记一行 `HIS`），**不允许**只在会话里口头宣布完成。
- `done` 的判定 = §0.6 验收门全绿 **且** §0.7 回写门全部落盘 **且** git 已提交。
- **首项启动规则（bootstrap）**：当全表无 `active` 项时，按 §11 交接卡（或 §5 顺序）取第一个 `backlog` 项，经用户确认后直接转 `active`；卫生/文档类项免规格化门（见 §0.3 豁免条），代码类项仍须先过 §0.3。

### 0.3 规格化门（`spec` → `planned` 的通过条件）

沿用本仓已验证的 superpowers 工作流，落在固定路径：

- spec 存 `docs/superpowers/specs/YYYY-MM-DD-<slug>.md`
- plan 存 `docs/superpowers/plans/YYYY-MM-DD-<slug>.md`
- 执行台账存 `.superpowers/sdd/YYYY-MM-DD-<slug>/progress.md`（pre-flight 表 + rulings + ledger）

通过条件（缺一不得转 `planned`）：

1. spec 明确列出**目标 / 非目标 / 不修改项 / 验收 / 风险**（若既有的在途 spec（如 `2026-10-10-ui-three-layer-restructure.md`）用「背景/目标/风险/不在本轮」替代其中某些标题，视作等价骨架，但语义必须齐全；本计划立项后新增 spec 一律用上述五要素标题）。
2. plan 含五要素头：Goal / Architecture / Tech Stack / Spec 链接 / **Global Constraints**（从 AGENTS.md §2 七原则与 §5 纪律逐条抄具体值，不写"遵循最佳实践"这类空话）。
3. plan 的每个 Task 有 Files（精确路径）/ Interfaces（Consumes + Produces 的确切签名）/ 可勾选步骤（`- [ ]`）。
4. plan 写明**验证命令与通过判据**（命令 + 期望输出，见 §0.5）。
5. spec 与 plan 中出现的**数值阈值**要么引用规格文档的既有值，要么标 `[待标定]`，禁止新造魔数（AGENTS.md §5 数值纪律）。

**豁免条**：不改动 `scripts/` / `scenes/` / `crates/` / `tests/` 的卫生类与纯文档类工作项（如 `P0-C0a` 旧栈清理、`P0-C0b` 产物卫生、`P0-C0c` README 重写、验收记录落盘）**免规格化门**，可直接 `backlog → active`；但 §0.4 执行铁律与 §0.5 基线自检仍全量适用。

### 0.4 执行期铁律（`active` 期间）

- **只做本项的 plan 范围。** 计划外的新发现一律写进 §6「发现登记」，不顺手改。
- **每完成一个 Task 提交一次**（`git add <本任务文件> && git commit -m "<type>(<scope>): <任务摘要>"`，type/scope 沿用本仓现状：`feat|fix|test|docs|chore` + `ui|storage|domain|editing|project-mgmt|agents`）。
- **目标分支约定**：v0.1 期间所有提交落在当前工作分支 `deepseek-build`；切分支、合并回主线、或另开功能分支均属铁律级变更，须用户批准（§0.8）。
- 提交前必须过 §0.5 自检；**不允许**提交基线本来就红的无关改动混在同一 commit。
- 大文件（>300 行）单文件增长时，在 plan 里显式登记"待拆分"到 §6，不现场拆。
- 一切外部依赖调用按 [AGENTS.md §6.3](../AGENTS.md) 的硬编码路径与命令模板走；路径失效先按 §6.3 探测规则找，不擅自装新工具。

### 0.6 验收门（`verify` → `done`）

1. 该工作项 spec 的「验收」章节逐条勾掉（静态断言 + 单测 + build）。
2. 该里程碑的 **demo 验收口径**（[总体设计 §7](总体设计_v0.1.md)）现场跑一遍，可观察、可复述。
3. 人工 F5 目检（涉及 UI 的项）：按 spec 列的可视清单逐项确认。
4. 结果写入 `docs/acceptance/<slug>_check.md`（沿用 `docs/acceptance/map_editor_mvp_check.md` 的对照表格式）。

### 0.6.1 B3 退出码说明

B3 只看「是否在超时内自然退出 + stderr 无场景/脚本解析错误」，**不把 C# 运行时异常计为 B3 红**：`--check-only` 加载主场景实例化节点，运行时异常（如 `MarkerLayer._Ready` 的 `InvalidCastException`）不阻塞校验通过。已知运行时问题单独记录（见 §6 发现），不在基线自检拦路。

### 0.7 回写门（`verify` → `done` 前必须落盘，按需升版本号）

按 [AGENTS.md §7 改动检查清单](../AGENTS.md) 逐条过，落到文件：

- 改了字段/枚举 → 《数据模型规格》加字段 + YAML 示例 + §11 变更记录。
- 改了存储路径/文件划分 → 《存储与目录规范》。
- 改了二进制格式 → 《二进制格式规格》+ `format_version` 纪律。
- 新增/改动图层 → 《图层系统规格》图层清单（声明时间有效性、是否参与贴合/裁剪）。
- 新增地图类型 → 《地图类型规格》。
- 改了外部依赖（版本/路径） → AGENTS.md §6.3 + 《技术基调确认》变更记录。
- 更新本文件 §5 该行的 `ST` / `HIS`，以及 AGENTS.md §6.2 当前进度段。

### 0.8 阻塞协议

- 连续 2 次尝试同一验证命令均失败且原因不明 → 项转 `blocked`，把**具体失败输出**写进 §6，会话结束。
- 需要用户拍板的决策 → 写进 §6「待用户决策」，用 `ask_user_question` 一次问清，不反复追问。
- 里程碑切换、P1 决策点收敛、任何 §2 铁律级变更 → **必须用户批准**后才改本计划。

### 0.9 断点续传

会话可能在任意处中断。恢复时：

1. 走 §0.1 启动序列。
2. `git log --oneline -10` + `git status --short` 对照 §5 该行 `HIS` 判断进度落在哪个 Task。
3. 读 `.superpowers/sdd/<当前项>/progress.md` 的 ledger 续上。
4. **不要**相信会话内的口头进度，一切以 git 提交 + 本计划状态列为准。

### 0.10 范围防漂移（长期执行最大风险）

- 本计划只覆盖**规划书 v0.1 范围**（M1–M8）。分支时间线（P1-2）、第三方插件（P1-3）、多人协作、Web 导出、3D/等距视图：**不做**。
- 计划外需求出现时：登记 §6 → 走 §0.8 决策 → 经用户批准后**升本计划版本号**再插入工作项表，不允许静默插入。
- 每完成一个里程碑，做一次「范围复核」：重读 AGENTS.md §3 待决项，确认没有被顺手实现的 P1/P2 内容。

## 2. 全局铁律与约束（所有工作项默认继承）

> 摘自 AGENTS.md §2/§5 与总体设计 §7/§8，逐条是硬值不是口号；spec/plan 的 Global Constraints 直接引用本节。

1. 单机可运行：**零网络依赖**，无服务器、无账号、无云同步。
2. 目录即工程：工程自包含，引用只允许**相对工程根路径或稳定 ID**，禁止工程外绝对路径。
3. YAML 为主：元数据/配置/矢量/一切对象走 YAML；**二进制仅限大网格数组**（`encoding: chunked`），索引与语义必须留 YAML，二进制块禁止承载语义配置。
4. 多地图层级：world → region(可选) → city → street(可选) → building/interior，underground 可交叉引用；每图独立网格/距离单位/时间粒度。
5. 图层化编辑：显隐/锁定/透明度/`z_order`；图层声明 `valid_from`/`valid_to`，渲染只做交集。
6. 非破坏编辑：笔刷与选区走命令模式，可撤销/重做/快照（`UndoStack` 已有，新编辑一律实现 `IEditorCommand`）。
7. 时间轴驱动：磁盘只存**绝对时间**，展示按粒度格式化；回放 = 基准状态 + 差异事件，**禁止**每时刻存全量状态。
8. 数据契约中立：Godot/C#/YamlDotNet 概念只出现在总体设计与各规格的「实现」小节，**不得污染《数据模型规格》字段定义**。
9. 依赖方向：UI → Editing → Domain → Storage；Render 只读 Domain；Domain 纯逻辑不 `using Godot;`（`scripts/Domain/**`、`scripts/Storage/**` 保持引擎无关，可单测）。
10. 数值纪律：阈值一律可配置进 YAML，未标定写 `[待标定]`，禁止魔数。
11. 禁止过度构建：只做 M1–M8；不提前实现 P1-2/P1-3、不引入 3D/等距、不做 Web 导出。
12. 版本纪律：改设计先升版本号（`docs/<主题>_v<版本>.md`），同版本内补充走文末「变更记录」。
13. 语言纪律：沟通与文档中文；代码/文件名/YAML 键英文（小写下划线或驼峰）。

**验证命令基线**（§0.5 的 B1–B4）在每个工作项的 plan 中原样引用，不重新发明。
