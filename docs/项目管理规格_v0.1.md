# 项目管理规格 v0.1

> 定义工程动作面（打开 / 新建 / 关闭 / 切换地图 / 新增地图）的强约束与 UI 承载。
> 数据字段仍以 [数据模型规格](数据模型规格_v0.1.md) 为唯一真源；本规格只规定**动作的语义与承载位置**。
> 存储落点以 [存储与目录规范](存储与目录规范_v0.1.md) 为准；UI 容器以 [界面与交互规格](界面与交互规格_v0.1.md) 为准。

---

## 1. 范围与定位

### 1.1 范围

本规格覆盖「管理工程本身」所需的全部动作：

| 动作 | 说明 |
|---|---|
| **打开项目** | 校验工程根，登记到最近项目清单 |
| **新建项目** | 在指定目录建立最小骨架（`project.yaml` + 一张空白世界地图） |
| **关闭项目** | 结束当前会话（未保存改动兜底见 §8） |
| **切换地图** | 工程内多张地图之间切换 |
| **新增地图** | 工程内新建一张地图（弹类型选择 + 命名对话框） |

不在本规格范围：地图内容怎么画、时间轴、人物登记、事件联动、第三方插件、分支时间线——这些走各自的专项规格。

### 1.2 设计基础

- 项目根元数据：见 [数据模型规格 §1](数据模型规格_v0.1.md)
- 工程目录布局：见 [存储与目录规范 §1](存储与目录规范_v0.1.md)
- UI 容器骨架：UiLayer + BottomPalette（见 [界面与交互规格 §1](界面与交互规格_v0.1.md) 与 [AGENTS.md §6.2 UI 重设计已落成 W1–W4](../../AGENTS.md)）

## 2. 核心约定（强约束）

| 编号 | 约定 | 出处 |
|---|---|---|
| **C-R1** | 最近项目登记落在 `.worldview/recent_projects.yaml`（应用私有、不进版本库） | 动作面 第 1 题 |
| **C-R2** | 每条记录字段 = `project_root`（绝对路径） + `last_opened_at` + `display_name`（首次登记时快照缓存，不实时跟读） | 动作面 第 2 题 |
| **C-R3** | `last_opened_at` 仅在真正进入编辑器时刷新；误触 / 点开即关不刷 | 动作面 第 2 题 |
| **C-I1** | 工程根必须有 `project.yaml` 才被识别为有效工程 | 动作面 第 3 题 |
| **C-S2** | I1 校验失败时引导升级到"新建项目到此处"，不静默拒绝、不偷偷写文件 | 动作面 第 3 题 |
| **C-N2** | 新建项目最小骨架 = `project.yaml` + 一张空白世界地图（`maps/` 下）；**不复用** `examples/sample_world/` | 动作面 第 4 题 |
| **C-D1** | `display_name` 默认 = 目录名，不弹输入框 | 动作面 第 4 题 |
| **C-M内** | "切换地图" = 工程内多张地图之间切换，**不动** recents，**不动** `last_opened_at`，**仅改会话级** `current_map_id` | 动作面 第 5 题 |
| **C-M跨** | 跨工程切换 = "关闭 + 打开"组合，UI 名 `切换工程`，不发明第三种动作 | 动作面 第 5 题 |
| **C-E1+E3** | 新增地图双入口：工程树右键 + 工程抽屉菜单；BottomPalette 工具行**不**放项目级动作 | 动作面 第 6 题 |
| **C-D1-弹窗** | 新增地图弹"类型选择 + 命名"对话框；怪物刷新点等用途标签归 `usage_tags` 自定义子类型（§6 展开） | 动作面 第 6 题 |
| **C-C1** | 工程根入口 `project.yaml` 最低字段 = `kind: world_view_project` + `schema_version`（见 [数据模型规格 §工程根入口](数据模型规格_v0.1.md)） | 非动作面 N1 |
| **C-C2** | 地图实例位置：`maps/` 目录下 YAML；**目录即清单**，`project.yaml` 不维护地图索引 | 非动作面 N1 |
| **C-C3** | `examples/sample_world/` 是示例工程不是产品模板；新建项目不复用它，但它必须能被 `open_project` 加载（反向校验 C-C1 + C-C2） | 非动作面 N1 |
| **C-L1** | UiLayer 顶部新增 `ProjectChrome`（高度 32px），含工程名 + 面包屑 + 工程菜单 | 非动作面 N2 |
| **C-L1-挤压** | 顶部条 32px **显式挤压**画布区起点 y=32（§UI 容器约束） | 非动作面 N2 |

### 3.1 隐含关系（动作图固化）

1. **打开 ↔ 新建** 是 C-S2 关系：用户拖入空目录 → I1 校验失败 → 引导"新建项目到此处"，不静默拒绝
2. **切换地图不动 recents**（C-M内）：与打开/新建/关闭严格区分
3. **关闭项目未保存改动兜底**：本轮不展开细节，留待 autosave 设计时定
4. **跨工程切换 = 关闭 + 打开**（C-M跨）：不发明第三种动作；UI 名固定 `切换工程`

## 4. UI 容器约束（C-L1 / C-L1-挤压）

`UiLayer` 内新增 `ProjectChrome` 顶部条（**增量**而非破坏；§6.2 UI 重设计 W1–W4 已落成的三层结构与 BottomPalette 全部保留）：

```
UiLayer (已有, layer=1)
├── ProjectChrome           (新增, Control, 顶部锚定, 高度 32px)
│   ├── 工程名 Label         (左对齐, 点击 = 工程菜单下拉)
│   ├── 面包屑 Label         (居中, 工程名 / 地图1 / 地图2, 点击 = M内 切换地图)
│   └── 工程菜单 PopupMenu   (触发 = 工程名点击 或 独立按钮)
│       └── 项: 打开项目 / 切换工程 / 新建项目 / 新增地图 / 关闭项目
├── DockLayout              (已有, 不变)
└── BottomPalette           (已有, 不变)
```

### 4.1 画布挤压（显式约束，不可回退折叠）

- 顶部条 32px **显式挤压**画布区起点 y=32
- 落地时按 `WorldCanvas.FitRect`（见 [AGENTS.md §6.2 地图初始拟合](../../AGENTS.md)）实测：原画布区 (0,32,1152,416) → 调整为 (0,64,1152,384) 量级，以实际 `EditorController.SyncMapToCanvasArea()` 重新拟合为准
- 落地实现期**不得**回退折叠 ProjectChrome 偷回画布空间；如需调整画布区，必须修改本条款（升本规格版本号）

### 4.2 WorldDropSurface 入口职责不变

`WorldDropSurface`（W1–W4 已落成）仍是"把系统资源管理器里的目录拖进窗口触发 I1 + S2"的次级入口，不与 ProjectChrome 冲突。

### 4.3 工程树与 ProjectChrome 的关系

- **工程树**（未实现；待 M2 UI 重设计后续 W）：右键菜单放新增地图（C-E1）
- **ProjectChrome 工程菜单**（v0.1 必须）：新增地图放工程菜单（C-E3）
- 二者**共同存在**，不互相替代

## 5. 工程根入口与目录约束

### 5.1 工程根入口（C-C1 / C-C2 / C-C3）

- 工程根的 `project.yaml` 最低字段 = `kind: world_view_project` + `schema_version`；正式字段登记见 [数据模型规格 §工程根入口](数据模型规格_v0.1.md)
- 地图实例落在 `maps/` 目录下 YAML；**目录即清单**，`project.yaml` 不维护地图索引
- `examples/sample_world/` 是示例工程不是产品模板，新建项目不复用它；它必须能被 `open_project` 加载（反向校验 C-C1 + C-C2）

### 5.2 最近项目登记（C-R1 / C-R2 / C-R3）

落点见 [存储与目录规范 §最近项目登记](存储与目录规范_v0.1.md)。

## 6. usage_tags（M4 展开，本轮仅登记）

新增地图弹"类型选择 + 命名"对话框后，怪物刷新点等用途标签归 `usage_tags` 自定义子类型：

- v0.1 **仅在数据模型规格里登记字段位置**，**不展开** UI 与枚举
- M4（地图子集）阶段正式展开枚举（怪物刷新点 / 资源点 / 营地 / …）与对应 UI

字段正式登记见 [数据模型规格 §usage_tags](数据模型规格_v0.1.md)。

## 9. 与现有规范的对齐说明

- **§6.1 目录约定**：本轮所有动作落地后产生的目录（`.worldview/` / `maps/` / `project.yaml`）均符合现有约定，无目录冲突
- **§6.2 UI 重设计 W1–W4**：本轮 ProjectChrome 是**增量**（在 UiLayer 内新增），不破坏已有三层结构与 BottomPalette
- **§7 改动检查清单**：本轮不修改字段、不修改数据模型、不修改二进制格式；只在 UI 层与 `.worldview/` 应用私有目录新增约定，无需升数据模型规格版本号
